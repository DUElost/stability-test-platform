# ADR-0059 U3：试改两篇 SOP 与对应 skill（#3622）

Status: implemented
Class: process

## Decision

按 ADR-0059 §5 U3，用写作约定（`docs/development/writing-conventions.md`）试改三份文件：
`docs/operations/device-lease-emergency-release.md`、skill `device-lease-release`、
skill `diagnose-device-stall`。

- 结构按约定 §4 样板：适用条件、总体警告、「按顺序执行以下步骤」、编号步骤、警告放在被保护的步骤之前、
  状态变更后写「预期：」。
- 术语按 §2：「设备ID」限定为 `device.id`（整数主键，不是序列号）；skill 描述和标题里的
  「任务卡死」改为「PlanRun 卡死（界面上称「任务」卡死）」。
- 强度词按 §3：踩坑守卫改为带执行者的规则句（Agent / 执行者 + 必须 / 不得）。
- 查法按 §4.6：原文没有查法的检查步骤标为缺口 G1–G4，集中列在 SOP 文末，交设备租约领域 owner 补；
  实施者没有代编判据。

改写时按「代码与测试为准」核对了原文，修正了两处与代码或权威文档不符的内容：

1. 原 SOP 与 `diagnose-device-stall` 的前置查询都写 `leased_at`，表里没有这一列
   （`backend/models/device_lease.py` 与迁移 `s7t8u9v0w1x2` 都是 `acquired_at`），按原文执行会直接报错。
   改为 `acquired_at`，并补查 `job_id`、`lease_type`、`expires_at` 及关联的 job / PlanRun 状态，
   供第 6、7 步判断。
2. `diagnose-device-stall` 写的是「四层判别（L1–L4）」，triage 文档现在先问 L0 意图 / 作业层（#3065）。
   改为「先问 L0，再看 L1–L4」。

`diagnose-device-stall` 的租约查询改为引用 SOP 文档的第 2–4 步，不再内联第二份 SQL：
原来两处各抄一份，`leased_at` 错误也是两处同时存在。

## Alternatives

- 为 G1–G4 自行补判据：例如把「在途 PlanRun」定为 `job_instance.status ∈ (PENDING, RUNNING, UNKNOWN)`。
  不选：ADR-0059 U3 明文「缺失的查法由该领域 owner 补，实施者不得代编」；这些判据决定生产写操作能否执行。
- 收窄 UPDATE 条件（加 `AND id = <第 4 步的租约 id>`），避免检查与释放之间新获取的租约被误释放：
  属于操作语义变更，不在写作试点范围内。列在 PR 中供 owner 决定。
- 不动 `leased_at`：按原文写「预期」无法核对，而且改写后的 SOP 仍然无法执行。列名修正有模型和迁移作证据，
  不算代编。

## Verification

- 用 ORM 元数据的列名在内存 SQLite 中建表，执行 SOP 中的全部 SQL（`device`、`device_leases`、
  `job_instance`、`plan_run`）：改写后 4 条全部执行成功；`main` 上原文的第一条查询报
  `no such column: leased_at`。只校验表名和列名，不校验 PostgreSQL 方言与数据；未连接任何数据库。
- `check_governance_surface.py --check --base origin/main`：S1–S15、S5x 全绿。
- `./scripts/project_python.sh scripts/run_gates.py check:quick`：退出码 0；16 个成员中 15 项通过，
  `schema-at-head` 因未设置 `DATABASE_URL` 按门禁设计跳过（本容器的隔离 `.venv`，未连接任何数据库）。
- `scripts/run_pytest.py tests/test_skill_type_registry.py tests/test_skill_usage_report.py tests/test_skill_usage_probe.py`：
  未运行。本容器是 cgroup v1，runner 找不到 v2 内存边界，按设计拒绝启动；没有改用裸 pytest 绕过。
  这些根目录测试由 required CI `pr-agent-tests` 覆盖，状态以 PR 上的 CI 为准。
- 按约定 §5 自查本次改写的句子：见 PR 描述的逐项结果。
- 以下两处沿用原文的事实，但改写时做了推断，需要 owner 确认：
  - `diagnose-device-stall` 第 7 步：L2 重启 adb server 前的空闲判据，沿用 L1 原文的 `active_jobs=0`，
    并指明来源为 `GET /api/v1/hosts/{id}` 的 `active_jobs`。
  - 「5039 只用于 WSL 联调」原为陈述句，改为规则句「执行者不得在 Linux 生产 host 上设置 5039」。

## Revisit

- ADR-0059 §5 测试计划的复盘两点：
  - 改写是否暴露了真实缺口：是。查询列名错误、L0 漏同步，以及四个没有查法的检查步骤（G1–G4）。
  - 复核者核对是否更容易：待复核者在本 PR 给出结论；结论为否时，按 ADR-0059 §6 复议 D3。
- owner 补齐 G1–G4 后，删除 SOP 文末的「待补缺口」条目和正文中的缺口标记。
