# 两份裁决文档起草：#942 迁移治理语义 + #906 主机身份 ADR 草案

Status: implemented
Class: process

## Decision

B3 台账收官后仅存 #942 与 #906，两单均为「先裁决再实现」形态，本轮交付裁决
件而非实现：

1. **`docs/design/2026-09-08-seed-migration-governance.md`**（#942）：精读两个
   种子迁移的裸 SQL 行为（b8c9d0e1f2a3 原地 UPDATE `default_params`；
   k1l2m3n4o5p6 无引用停用旧版），对比 API 层
   `_ensure_script_can_be_deactivated` 的 409 语义，给三选项（A 引用感知遇
   引用即失败 / B 跳过告警 / C 维持现状文档化），**推荐 A**（与既有护栏同
   构、迁移「声明未满足即失败」哲学优于静默跳过）。实现计划明确：既有迁移
   不改（已执行，重写违反 ADR-0008），共享辅助模块只约束未来种子迁移。
2. **`docs/adr/ADR-0035-agent-host-identity.md`**（#906）：全局
   `AGENT_SECRET` + 客户端自报 `host_id` 的冒充面分析（fencing 边界与
   「有效 secret 冒充者」的区分）；四方案对比（每主机凭据 / mTLS / 注册质
   询 / 接受边界——mTLS 有 #46 TLS 前置依赖不满足），**推荐 A 为目标形态 +
   C 注册质询为引入路径**；ADR-0035 登记进 adr/README 与 DOC-MAP（S12 索引
   同步）。

## Alternatives

- **直接实现两个修复**——放弃：#942 的三语义与 #906 的四方案都是方向级选
  择，AGENTS.md 要求方向级决策走 ADR/裁决；未经拍板的实现会被推倒；
- **合一份文档**——放弃：两单分属不同治理域（迁移治理 ↔ Agent 信任根），
  裁决节奏独立（#942 可较快定，#906 牵动安装链路需更慎重）。
