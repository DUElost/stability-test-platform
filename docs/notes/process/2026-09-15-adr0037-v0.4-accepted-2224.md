# ADR-0037 v0.4：转 Accepted + 落 S1/O1/O2（#2224）

Status: implemented
Class: process

## Decision

- **转 Accepted**：依据 R02 安全联审评审一稿（`docs/reviews/REVIEW_ADR0037_SECURITY_2026-09-15_3e833f.md`，
  issue #2206 / PR #2209，结论「建议接受、无阻断项」），用户 2026-09-15 裁决
  Proposed → **Accepted（v0.4）**；验收 ①（无法对安装目录外任意路径提权写）与 ②（无宽文件状态下
  热更新仍可用）均已有实测证据。
- **采纳 S1（+ O1/O2，均为文档面）**：
  - 新增 **D6 边界承担声明**：sudoers 对 wrapper 的授权行不带参数模式 ⇒ **参数空间不受 sudoers
    约束，全部 containment 在 wrapper 进程内**（含 `bootstrap` 对 Agent 用户可达）；这是 D1–D5
    其余约束的前提，必须在 ADR 里显式化。
  - D3 补 **信任边界措辞**（O1）：信任边界是 **conf 冻结（锚点不可变）**，不是调用者身份校验；
    `SUDO_UID` 不校验的理由写在 ADR 里（此前只在实现 docstring）。
  - §4 不变量补全（O2 + S1）：把既有强控制逐条固化（staged 在 `INSTALL_DIR` 外 + 调用者属主、
    fd 基目标、`--safe-links` 与固定 excludes、`usb-authorized` realpath/同名目录 + `O_NOFOLLOW`、
    `fix-ownership` `follow_symlinks=False`、`write-digest` 字符集、`bootstrap` 的 `INSTALL_DIR`
    禁含系统目录），并把 **parser/边界测试列为不变量**（点名四个测试文件）。
- **S2/S3/O4 明确待排期并留痕**（§5 ③ 内）：S2（主机侧审计）属行为变更，需 ADR 增补 + runbook +
  机队部署；S3（宽根 `INSTALL_DIR` 纵深防御，现网 conf 全在 ⇒ 不可达）需守卫收紧 + 测试；
  O4（wrapper 版本标识）需 wrapper 变更并对齐对账方法。
- **状态面三处派生同步**（S12 索引一致性门禁）：ADR 头部 `Accepted（v0.4）` +
  `docs/adr/README.md` 主表与 M7 看板行 + `docs/DOC-MAP.md`。

## Alternatives

- **只改状态行、不落 S1**：状态转了但「边界承担」仍不可见，等于把评审中最重要的一条发现留在
  代码注释里；下一次回归可能无人知道 sudoers 不约束参数。否决。
- **把 S2/S3/O4 一并做掉**：用户裁决「先落 S1」；且 S2 是主机行为变更（需 ADR 增补 + 机队部署与
  观测），与纯文档 PR 混在一起会放大回滚面。否决（留 Revisit）。
- **把边界承担塞进 D1 的注释而非新增 D6**：D6 可被测试与后续 ADR 直接引用，且不改 D1–D5 既有语义
  （ADR 增量修订的常规做法）。采用 D6。
- **回改历史文档里的 `Proposed`**（评审稿、早前 erratum note、审计报告）：历史记录是时点事实，
  改动会破坏可复现性；只在 ADR 与派生面改，历史稿保留。否决。

## Revisit

- **S2/S3/O4 的排期出口**：S2 建议与「提权面观测」一并排（新增调用日志格式、轮转与抓取口径需 ADR 增补）；
  S3 与 O4 都只动 wrapper 一个文件，可合并为一次 wrapper 版本发布（含 `selftest` 输出/版本标识与
  `INSTALL_DIR` 约束收紧），并同步机队对账方法。
- **多 Harness 评审汇总**：若其他 harness 也产出 ADR-0037 评审稿，需做 synthesis 并核对本版采纳状态
  是否需要回填（例如其他稿对 S1 的表述更强/更弱）。
