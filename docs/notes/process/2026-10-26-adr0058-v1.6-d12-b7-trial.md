# ADR-0058 v1.6：D12 方案粒度与实施自由（B7 试行）

Status: implemented
Class: process

## Decision

Owner 于 2026-10-26 在 #3798 的讨论中选定「全量试行，D12 只限 B7」，B7 主题定为 ADR-0061 阶段 C 的 GPU 专项接入。
本次在 ADR-0058 新增 D12：方案「修复内容」只写判据、不变量、跨单元接口契约与验收清单；实施者在 scope 与验收清单内自行选择做法，
做法偏离写进 PR「偏离说明」，偏离本身不构成「需修改」；实施者可以在 PR「观察」节记录方案未覆盖的风险，复核者在 A、B 之后回答
「本方案最可能错在哪里」。三个角色的常驻门禁汇总为 `docs/development/ai/role-cards.md`；方法类内容从 `batch-planning.md`、
`batch-review.md` 原样迁入 `docs/development/ai/methods/`，按触发条件和实施档位读取。B7 关单时另记四项统计，由 Owner 裁决转常态、修改或撤回。

D1–D11 原文无改动；迁出的方法文本规则无改动，只换了位置。

## Alternatives

- 直接转为常态：只有 B6 一批数据，先试行一批，放弃。
- 只做观察通道与方法拆分、不改「不重新设计」：不需要 ADR，但方案粒度的成本不变，无法验证 #3798 的主要假设，Owner 未选。
- 方法模块放 `.claude/skills/`：规划者与复核者所在的 Web 工作面读不到该目录（ADR-0058 §4），改为普通文档、由提示词按路径点名。
- 门禁也做成按需模块：门禁管权限与不可逆操作，按需加载会在读不到模块的工作面上失效，放弃。
