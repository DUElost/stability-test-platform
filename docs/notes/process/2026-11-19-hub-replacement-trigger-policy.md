# Hub 更换出口：由固定排期改为可核触发条件（Owner 裁决 2026-11-19）

Status: implemented
Class: process

## Decision

1. Owner 裁决：**功能正常的主机不为「SuperSpeed 侧退化、且该侧不承载任何在用设备」的 Hub
   单独排期更换**；处置出口由 [`docs/operations/host-device-visibility-triage.md`](../../operations/host-device-visibility-triage.md)
   新增的 §5.7 触发条件接管。§5.2 第 6 步与 §5.4 第 6 步的「排期更换」措辞同步改为指向 §5.7。
2. §5.7 把「功能正常」写成**必须给查法的五条判据**，而不是主观形容词：在用侧设备数与 ADB 接口数
   相等、15 分钟内核窗 `-71 ∪ -110` 归零、`uhubctl` 全量列举 < 2 秒（未装该命令的主机**不得**用
   本条，`rc=127` 的 0 秒不是证据）、健康面不再点亮 USB 类 reason、VBUS 槽位与实际树一致。
3. §5.7 列出五条**恢复更换**的触发条件，其中第 1 条（`-71/-110` 回到日级三位数）直接取
   §5.3 记录的 `.102` 前兆「死亡前两周每日 400~3700 行」——这是本案唯一有历史事故支撑的先行指标，
   也是本节敢于放弃固定排期的前提；第 4 条固化 `remove` 的 write-once 性质（恢复 SS 只能重插线或
   rebind xHCI，后者会连带重新枚举另一条总线的在用设备）。
4. §5.7 以警告块写明**这次交换的代价**：接受 SS 侧长期不可用，且在用侧随之失效时不再有软件侧
   兜底；并明确本节只豁免「当前无在用设备的失效侧」，不得被引用成「Hub 坏了也可以不管」。
5. 更正 §5.6 的两处：把 `.42` 的「记为未完成」补记为实测结果（**18:25:58** 心跳
   `HEALTHY`、`reasons=[]`、`usb=17 == adbif=17`），并解释它与原推算 18:29 的 3 分钟差
   ——窗口起算点是**末条内核事件**（17:25:58）而不是拆除命令时刻（17:28:55）；
   同时删去「同一批 Hub」的说法：三台固件版本不同（`.75`/`.42` 的 `bcdDevice=0126`、
   `.60` 为 `0001`），更换是三次独立现场动作，不得批量处置。
6. 不改写 [`2026-11-19-usb-hub-half-enum-second-hosts-skill-guard.md`](./2026-11-19-usb-hub-half-enum-second-hosts-skill-guard.md)
   原文（`docs/development/writing-conventions.md` §2.5 禁止改写 `docs/notes/` 原文），
   该 Note 里「`.42` 翻转留作复核项」的表述由本文第 5 条闭合，不改历史文本。

## Alternatives

- 保持 §5.2/§5.4 的「排期更换」不动、只在口头说不换：放弃。那是把**未标注的止血**留在流程里，
  正是 AGENTS.md「不标注的止血会沉淀为技术债与代码腐化」点名的形态；后来的执行者要么徒劳开单，
  要么学会忽略文档，两种结果都坏。
- 写成「永不更换」：放弃。`.102` 的记录表明 SS 侧退化可以是主控级死亡的前兆，无条件豁免会把
  一次可观测的劣化变成一次生产中断。
- 用 ADR 承载（而非 ops 文档 + 本记录）：暂不使用。本节只改**处置节奏**，不改任何运行不变量、
  机器契约或代码语义；若后续把「SS 侧退化 ⇒ 主控失效」做成自动降级/自动告警，那部分属方向级决策，
  届时补 ADR。
- 把阈值判据写成代码常量（如 fleet 级自动判定「功能正常」）：暂不做。现有五条判据今天全部靠
  只读手段人工可核，代码化会把「判据是否成立」和「谁来承担更换决策」两件事混成一个自动开关，
  而 Owner 裁决的对象恰恰是后者。

## Verification

- §5.7 表格里的每个数都是本轮实测，不是范例数字：`.75` 16/16、`.60` 13/13、`.42` 17/17；
  15 分钟内核窗 `-110` 处置前 73/74 次、处置后 0；`uhubctl` 1.3s / 0.6~0.9s / `.42` 未安装；
  三台现 `HEALTHY`、`reasons=[]`；`.75` `usb_power_slots` 16/16 命中、另两台为 0（不适用）。
- `.42` 翻转的实测证据：`FLIP_CONFIRMED 18:26:11`（`last_heartbeat` 字段值 `18:25:58`），
  平台记录 `health=HEALTHY reasons=[] usb=17 adbif=17 hb=18:33:31`。三台翻转时刻齐全：
  `.75` 21:57、`.60` 15:47:02、`.42` 18:25:58。
- fleet 现状：`usb_link_degraded` 从 4 台（11-18 的 `.12/.42/.60/.75`）降到 2 台，且**已确认
  剩下的不是本形态**——普查 78 台中「SS 子树内有未绑定 Hub」的主机数为 **0**；`.12` 的
  `ss_top=0`、`unbound=0`，属设备/线缆侧（`error -71` 与高频 `USB disconnect`）。
- 普查自身修正过两处探针缺陷（`Driver=[none]` 未限定 Bus 002 子树、漏数 `error -71`），
  修正后才是上述结论；采集缺口 2 台：`.29`（口令与 fleet 不同，`Permission denied`）、
  `.24`（首次 keyscan 超时未入库，补抓后指纹 3 次一致、无跨主机重复指纹，且平台侧
  `status=OFFLINE / hb=null` ⇒ 未接入 fleet，非安全信号）。
- 文档结构自检：小节序列 §5.1–§5.7 后接 §6；「排期更换」在全文仅出现 3 次，且全部处于
  「不再 / 取代 / 不为」语境；§6 新增本文链接，相对链接 0 断裂。
- **门禁**与未跑项见本 PR 描述。

## Revisit

- 本文第 1 条的裁决隐含前提是「SS 侧退化 ≠ 在用侧退化的前兆」，该前提**未被证明**，只是被
  `.102` 的反例约束在「日级三位数 `-71/-110` 才升级」这一条上。若出现任一台在用侧（HS）
  先于或同时出现 §5.1 判据而 `-71/-110` 计数仍低于日级三位数，则第 1 条先行指标失效，
  必须回到固定排期，并把该指标改用在用侧自身的判据。
- 若 §5.4 的 `remove` 被用在**承载在用设备**的分支上（当前判据禁止），本文全部前提作废。
- 若将来 fleet 上出现第四台同形，说明这不是散发而是批次性问题，届时把「批次普查 + 统一处置」
  重新提给 Owner，而不是继续按单机触发条件处理。
- `.60`/`.42` 未启用 VBUS 切电（`usb_power_slots=0`），故 §5.7 第 5 条对二者不适用；
  若这两台启用切电，需重新取一次基线再判「功能正常」。
