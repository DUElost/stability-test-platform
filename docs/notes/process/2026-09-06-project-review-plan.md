# 全面只读审查总纲与文档导航

Status: implemented
Class: process

## Decision

- 新增 [全面只读审查总纲](../../reviews/PROJECT_REVIEW_PLAN.md)，固定 R01–R15 及
  执行链、日志链两项跨区收口；按业务链路和风险边界划分，不建立目录所有权。
- 每区列出范围与排除边界、代码 / 测试 / 权威文档入口；统一证据分类、严重程度、
  报告模板、安全边界与完成标准，使后续会话可以复用而不依赖聊天记录。
- 稳定分区与每轮基线、进度、结论分离；首次实际开展时才建立轮次和区域报告。
  本次仅建立导航，所有区域与收口均未开始，历史审查不自动计入新一轮进度。
- 在 [DOC-MAP](../../DOC-MAP.md) 和 [文档中心](../../README.md) 增加入口；索引层级标为
  **全面审查指引**（与 Living 审查结果文档区分），路径仍为 `reviews/PROJECT_REVIEW_PLAN.md`。
  不修改业务代码、共享 Harness 启动文件或现行执行语义，不新增 ADR。

## Alternatives

- **只保留聊天方案**：不采纳。跨会话难以发现，也无法维护覆盖边界和版本基线。
- **放入设计文档或根启动契约**：不采纳。审查导航不是架构决策，常驻加载完整清单
  会增加上下文成本，并容易被误读为新的执行规则。
- **另开顶层或子目录存放总纲**：不采纳。指引与轮次报告同属审查体系，靠无日期文件名
  与 DOC-MAP/README 层级标签区分即可，避免扩文档分层。
- **把全部结果累计写进总纲，或预建 15 份空报告**：不采纳。前者混淆历史基线，
  后者增加占位文档且容易让文件存在被误认为审查完成。

## Revisit

- 架构或模块路径变化，使分区或导航入口不再对应实际实现时。
- 实际审查发现持续重复覆盖、无人跟进的跨区空白，或需要新增独立风险区域时。
- 文档组织或审查交付方式变化时；若涉及执行语义调整，另按现行工作流经 ADR 裁决，
  不借本总纲引入新规则。
