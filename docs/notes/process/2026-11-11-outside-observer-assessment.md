## Decision

把一次「旁观者视角」的平台整体评估落盘为独立评审稿（不并入主稿
`STP_FIRST_PRINCIPLES_AUDIT_2026-09-25_codex.md`）。

- **为什么独立成文**：主稿 §10 的「后续复核续写本稿、不新增平行文档」约束针对**同一命题**（150 host /
  3750 device 容量与复利）的后续轮次（§13 即第四轮）。本稿命题不同——「一个了解目标但不参与日常决策的
  旁观者，认为哪里该调整、哪里做得好」——且不覆盖主稿结论，重叠部分只引用。若强行续写为主稿 §14，
  会把两种命题的读者与复审触发条件混在一起。
- **结论**：架构方向不需改（控制面 / Agent / PostgreSQL 事实 / Redis 传输 / 不可变发布包）；
  需要调整的是优先级与收敛方式。新增判断两处，已分别立单：#3938（测试有效性事实缺位）、
  #3939（时序/并发判据：单调基底 + 可回放交错测试）。
- **载体纪律**：本稿不立第二台账；重叠结论引用主稿 §13 与既有单；容量相关处置顺序沿用 §13.6，
  本稿只列增量。
- 同步登记 `docs/DOC-MAP.md` 的 Living 审查表（一行）。

## Alternatives

- **续写主稿 §14**：见上，命题不同会污染主稿的复审触发条件；弃。
- **只发评论留痕不落盘**：评估是给人读的完整论证，评论形态不可检索、不可复审；弃。
- **把 8 项不足全部立单**：其中多条已有载体（#3498 脚本族目标模型、#3317 守卫、#3519 台账漂移、
  #3233 存续闭环），重复立单会制造第二事实源。只对**无既有载体**的两处立单；其余在稿内给出证据与建议载体。
- **建议信息性全量测试阻塞 PR**：作者初稿曾提此建议，Owner 2026-11-11 以注意力预算为由驳回；
  稿中已撤回该建议，只记录两个附带事实（观察期到期未落结论、文档与 CI 现状漂移）。
