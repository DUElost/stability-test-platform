# R09-F09 落地：DeviceLogEvent 规格同步 ADR-0032 现行接口（#1050）

Status: implemented
Class: bug-fix

## Decision

`docs/design/2026-device-log-event-implementation-spec.md` §5 仍描述 ADR-0032
之前的形态：把 UNISOC/QCOM 都写成 stub、由已删除的
`STP_WATCHER_AEE_RECONCILE_PLATFORMS` 决定启动；协议示例含实际不存在的
`poll_new_events`/`collect` 方法。按现行代码同步：

- §5 结论 + 5.1：协议仅 `detect`/`parse_metadata`（`collector.py`
  `PlatformCollector`，含 `shell_fn` 实参签名）；`TriggerInfo` 标注为
  reconciler 从 `db_history` 解析产生（非协议方法）；
- 5.3：平台路由改为 `get_collector_for_platform` 映射表（MTK/UNISOC 真实、
  QCOM stub、UNKNOWN→MTK 兜底），明确旧 env 键已删、零读取点；
- 5.4：平台可用性**三层口径**表（模块存在 / 端到端采集可用 / 真机验收
  完成）——防止再用「模块存在」冒充「端到端可用」。

事实核对：`collector.py`（Protocol 31-36 + 路由 39-56）、
`collectors/qcom.py`（detect False / parse_metadata raise）、
`collectors/unisoc.py`（ADR-0032 B5 真实实现）、
`backend/agent/aee/AGENTS.md`（env 键随路由删除的既有记载）。

## Alternatives

- **保留旧协议示例并加「历史」标注**——放弃：规格是接口契约文档，示例必须
  是现行可用的；历史沿革归 ADR；
- **同步 `aee/CLAUDE.md` 等其它漂移点**——放弃：PLATFORM_HEALTH_REVIEW 已
  单列其它路径，本单只收 R09-F09 指出的规格文档（范围纪律）。

## Verification

- 代码事实逐项核对（Protocol/路由/QCOM stub/UNISOC 实现/env 零读取点）；
- 残留漂移词检查：`poll_new_events` / `adb_run` 已无，`RECONCILE_PLATFORMS`
  仅剩「已删除」历史说明一处；
- `check:quick`（文档结构/链接）：见 PR；
- test_impact=none（纯文档）。

## Revisit

- UNISOC「端到端采集可用 / 真机验收」状态随 R09 台账（#1055）相关项推进，
  完成后更新 5.4 表；
- QCOM 真采集（#73）落地时同步 5.4 与 `collectors/qcom.py` 描述。
