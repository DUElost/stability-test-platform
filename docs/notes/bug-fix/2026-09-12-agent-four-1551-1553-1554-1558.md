# agent 侧四单修复：#1551 / #1553 / #1554 / #1558

Status: implemented
Class: bug-fix

## Decision

同属 `audit-2026-09-12` 批次的 agent 侧四单，一个 PR 交付。

1. **#1551 终态 outbox 把 408/429 当永久拒绝**：`outbox_drainer` 的「非 409/404 的
   4xx = 中心永久拒绝」分支会把 429（限流器已把 `/api/v1/agent/jobs/` 移出豁免、
   300 req/min/IP，终态上送端点正在该前缀下）与 408 判成永久失败，10 次（≈150s）
   后转死信；而 `job_terminal_outbox` 是 terminal / log_signal / dle_register
   三张同族表里**唯一没有** `replay_*_dead_letter` 出口的——转进去连人工都取不回。
   修法：408/429 归入瞬时分支（与 5xx 同口径，不判永久、不进死信），并新增
   `Retry-After` 退避（上限 300s，进程内生效，重启即忘——最坏退化为原先的
   15s 重试节奏，不会更差）。
2. **#1553 安装锚点可被重新指向**：`fix-ownership` 对 conf 的 `INSTALL_DIR` 做
   `chown -R -h`、`apply-code` 往 `INSTALL_DIR/agent/` 做 `rsync --delete`，两者
   都以 root 执行；而 `bootstrap` 在 sudoers 的 NOPASSWD 面内（授权的是**裸二进制、
   不限子命令与参数**）。于是「`bootstrap --install-dir /etc` → `fix-ownership`」
   一条链就把整棵 `/etc` 交给 AGENT_USER，随后可改 `/etc/sudoers.d`、替换 wrapper
   本体、再经同一条 NOPASSWD 规则以 root 执行任意代码。
   **修法刻意偏离 issue 正文的建议**（见 Alternatives）：不加「要求 `SUDO_UID`
   未设置」的调用者校验，改为两条与调用者无关的护栏——① `_validate_install_dir`：
   INSTALL_DIR 与系统关键目录不得**互相包含**（既拦 `/etc` 这类祖先，也拦
   `/usr/local` 这类后代，后者会把 `/usr/local/sbin/stp-agent-priv` 本体交出去），
   并接入 `_load_conf` 使被写坏的存量 conf 也会被任何子命令拒绝；②
   `_reject_anchor_drift`：conf 一旦存在，`INSTALL_DIR`/`AGENT_USER`/`AGENT_GROUP`/
   `SERVICE_NAME` 不得再变。
3. **#1554 `fill_storage` v1.0.1 回读核验假失败**：v1.0.1 新增的校验叠加两处
   floor（`blocks` 与 `actual_pct`）＋ dd 块对齐损耗，使「正好灌到目标」几乎必然
   算成 `target-1` 个百分点。按 ADR-0020 以 **v1.0.2** 表达修法（不改 v1.0.1）：
   块数向上取整、核验改整数绝对量比较。
4. **#1558 两处静默假成功**：`connect_wifi` 的「已连接」判据是 `ssid in stdout`
   子串匹配（请求 `Test` 而设备在 `Test-5G` → 直接 `skipped=True` 报成功且**不发起
   连接**，v1.0.1 的回读复验用的是同一谓词）；`system_monitor` 的
   `zip(..., strict=True)` 要 Python 3.10+，而 DEPLOY.md 声明 3.8+、`heartbeat_thread`
   还专门注释规避它 —— 在 3.8/3.9 上 TypeError 被 `get_cpu_usage` 的 except 吞掉，
   CPU 恒 0.0，`cpu > 90` 的限流判据永不触发。修法：connect_wifi 以 **v1.0.2**
   表达（谓词改全等），`system_monitor` 直接去掉多余的 `strict=True`（上一行刚补齐等长）。

## Alternatives

- **#1553 按 issue 正文加 `SUDO_UID` 检查**：**否决，且这是本 PR 最重要的判断**。
  Ansible 更新链（`tools/ansible/playbooks/update_agent.yml:146`）以
  `ansible_user=android`（见 `inventory.example.ini`）执行 `become: true` 跑
  bootstrap，此时 `SUDO_UID` **已被设置**；而 agent 用户经 NOPASSWD 跑 bootstrap
  时同样被设置。二者从进程内不可区分，加这条检查会直接打断正常部署。
  锚点护栏不依赖调用者身份，两条路径都不受影响（smoke 已验证）。
- **#1553 把 bootstrap 从 sudoers 面摘掉**：sudoers 的 `*` 会跨参数匹配，且
  `fix-ownership`/`restart` 是热更新链（`host_updater.py` 以 agent 用户 sudo 调用）
  的必需项，逐子命令枚举的收益不足以抵消「枚举漏项即断热更新」的风险；本轮只
  在 Note 的 Revisit 登记。
- **#1551 给 `_MAX_TERMINAL_ATTEMPTS` 加独立瞬时计数**：与 5xx 分支口径不一致，
  且 `attempts` 列同时是诊断信息；先与 5xx 对齐，观察后再定。
- **#1554 直接改 v1.0.1**：违 ADR-0020（已发布版本不可原地修改）；否决。
- **#1558 connect_wifi 用裸 token 全等兜底**：试过——目标 `My` 会命中设备上的
  `My Network`，只是把子串假成功换成词级假成功；否决，改为「带标签全等 +
  带引号全等」两条精确判据。
- **#1558 猜 `cmd -w wifi status` 的标签格式**：仓库内只有 `Wifi is enabled` /
  `Wifi is not connected` 两行有真实设备样本（`docs/operations/incident-2026-07-31-*.md:190`），
  连上后的 SSID 行形态**无样本**，故不猜格式，只做与格式无关的全等判定。

## Revisit

- **#1558 connect_wifi 需要真机复核**：谓词是「带标签全等 + 带引号全等」。若某型
  设备把已连接 SSID 以**既无标签又无引号**的形态输出，会判为未连接 → 步骤再连一次
  并在 10s 窗口内复验 → 以可见的步骤失败收尾（保守方向的假阴性，不再是静默假成功）。
  上手第一台真机时应确认该形态；若确实存在，补一条对应格式的判据，而不是退回子串。
- **#1553 sudoers 面收窄**：本轮未把 wrapper 的 NOPASSWD 规则从「裸二进制」改成
  逐子命令枚举。若要收，需先确认各子命令的参数面能被 sudoers 安全表达（`*` 会跨
  参数匹配），且必须覆盖 `host_updater.py` 用到的全部子命令。
- **#1553 预置窗口**：锚点护栏对「conf 尚不存在」的首次 bootstrap 无约束——
  安装链在装完 wrapper 后立刻 bootstrap，窗口极窄；若将来出现「wrapper 已装、
  bootstrap 未跑」的长期状态，需要另想办法（如由 Ansible 侧校验）。
- **#1551 attempts 预算**：瞬时失败仍会 `bump_terminal_attempt`（与 5xx 同口径），
  因此长期的 429 风暴会把 `attempts` 推高，使之后真正的一次永久拒绝立即触发死信。
  语义上可接受（该行已长期失败），但若现场观察到误死信，应把瞬时计数与永久计数分开。
- **`enqueue_sync` 的 `on_async_failure`**：本 PR 只在通知路径接入（在另一个 PR 中）。
  agent 侧的 fire-and-forget 调用点若有「必须知道是否真入队」的语义，应逐个评估。
- **既有迁移的 `downgrade base` 不可用（非本窗口）**：实测 `f0e1d2c3b4a5` 的
  downgrade 抛 `relation "uq_project_model_active" does not exist`，与本次四条改动
  无关（我的两条迁移在其之前已顺利回滚）。仓库门禁只跑 `upgrade head`，故未暴露。
  如需「可完整回滚」，应另立单。
