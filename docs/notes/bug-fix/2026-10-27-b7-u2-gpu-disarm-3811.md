## Decision

按 [#3809 当前方案 v1.2](https://github.com/DUElost/stability-test-platform/issues/3809)
实施 U2（[#3811](https://github.com/DUElost/stability-test-platform/issues/3811)）。

飞行模式与 Wi-Fi；`gpu_finish` 1.1.0 仅收取，模板同时 pin 新版本。

可信组合保持空，登记由规划者核对真机证据后完成。

权威退回记录见 [#3809 评论](https://github.com/DUElost/stability-test-platform/issues/3809#issuecomment-6436620062)。

Scope 补充说明：真实 Engine 反例发现 manual_exit 之外的中止仍启动 collect。
因此额外修改 `backend/agent/pipeline_engine.py`，在每次 teardown 步骤开始前，
对中止后的 GPU 已登记 collect 版本跳过执行。Registry 已加入该文件。
这一补充落实 §4 U2 第 3 条，不改变字段、判据或开关机行为。
GPU 历史清理断言迁至新探针有限反例；开关机断言未改。

## Alternatives

参照 `powercycle_disarm` 保留 probe/disarm、正式值由共享政策升级、单次 I/O 后进度戳。
GPU 使用独立小脚本，从进程、文件及网络状态分别回读；不复制开关机 prefs 机制。
先停循环启动器，再 force-stop 既有四包、停 instrument、删自产脚本、恢复两项设置。
回读有三轮上界；逐项读取失败优先于残留分类。
`cmd wifi status` 同时识别设备实测 `Wifi` 与 `Wi-Fi` 拼写。

U1 墙钟 callable 为离线等待 + 600 秒。最终脚本在线后的最坏路径为
身份 80 秒、10 项动作 150 秒、三轮五项回读 150 秒、轮间等待 4 秒，合计 384 秒。
等待使用 monotonic 截止和轮询迭代上界。单次调用超时均不超过 30 秒。
