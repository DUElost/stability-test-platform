# B7 U2 GPU 解除与收取拆分

Status: implemented
Class: bug-fix

## Decision

按 [#3809 当前方案 v1.3](https://github.com/DUElost/stability-test-platform/issues/3809)
实施 U2（[#3811](https://github.com/DUElost/stability-test-platform/issues/3811)），
消费已合入 U1 的接口，开发基线已更新到 `origin/main@647971943d8bbfbebb6a13843ddecf9b724fcc20`。
新增 `gpu_disarm` 1.0.0，仅解除循环脚本进程、instrument、自产循环脚本，
恢复飞行模式关闭与 Wi-Fi 打开；`gpu_finish` 1.1.0 仅收取结果，模板同时 pin 新版本。
`test_log.txt`、Antutu 与宿主 APK 保留。工具身份消费 U1 的 `apk_sha256`。
GPU 可信组合保持空，规划者核对最终包真机证据后登记。

v1.3 明确执行体动作失败时正式结果失败；设置类恢复命令失败只保留 evidence，
正式结果由解除后的全部事实回读决定。未知、失败或空回读均为 `readback_failed`。
恢复命令采用 gpu_setup 写入状态所用 cmd 接口的逆操作：
`cmd connectivity airplane-mode disable` 与 `cmd wifi set-wifi-enabled enabled`。

[规划者裁定](https://github.com/DUElost/stability-test-platform/issues/3809#issuecomment-6436833181)
确认 1.0.0 尚未在 main 登记且未发布。本轮只读再次确认站点无该包后，
在实施分支内重建同一版本，U1 最低版本与模板版本保持不变。
此前把分支内登记当作已发布单元的版本判断错误，不再作为停工理由。

Scope 补充（均已登记 Registry）：

- `backend/agent/pipeline_engine.py`：落实 §4 U2 第 3 条。中止后只跳过 GPU 已登记的
  collect-only 版本，每次 teardown 步骤前复查，保留解除；开关机行为不变。
- `tests/test_pipeline_template_script_pins_2865.py`：新族加入既有模板 pin 守卫名单。
- `tests/test_agent_clock_stub_guard_3202.py`：移除本次已删除 GPU 清理 helper / 测试的
  两项过期豁免，保留守卫本身。

GPU 历史删除与回读测试迁入新解除族的有限反例；没有改动开关机测试预期。

## Alternatives

沿用 B6 的 probe/disarm 与共享政策升级正式值；GPU 以独立小脚本回读执行体与设置，
不复制开关机 prefs 机制。先停循环启动器，再 force-stop 四包、停 instrument、
删自产脚本，最后恢复两项设置。逐项回读失败优先于残留分类，快照至多三轮。
`cmd wifi status` 同时识别现场 `Wifi` 与 `Wi-Fi` 拼写。

脚本保留包身份字段为 null，真实 Engine 按 ScriptEntry 补齐权威值，与 U1 / B6 入口一致；
不另行读取缓存标记推断身份。独立真机执行由 Harness 核对上传归档的 SHA，证据外层绑定该 SHA。
真实 Engine 测试同时断言聚合结果中的包身份等于 manifest 登记。

U1 墙钟 callable 为离线等待 + 600 秒。在线后最坏路径为身份 80 秒、
九项动作 135 秒、三轮五项回读 150 秒、轮间等待 4 秒，合计 369 秒。
等待使用 monotonic 截止及迭代上界，单次 I/O 超时不超过 30 秒。
