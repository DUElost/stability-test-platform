**#2999 顺出的第二处失真在代码里而不在文档里**：`env_inventory.py --write` 的选项自述是「幂等」，
实测**每跑一次就在文末多一个空行**（本仓尾部空行 21→22→23→24；写回路径多补了一个 `"\n"`）。
它同时污染两件事：刷新生成块的 PR 带上无关空白 diff、以及「谁多跑一次谁负责」。按总原则修根因而非
标注过渡——去掉那一次补换行（`_replace_block` 本就保留 marker 之外的原文），并把「幂等」这句自述
变成判据：`tests/test_env_inventory.py::test_write_is_idempotent` 连写两次比对字节。已有的 21 个尾部
空行**不顺手清**（清了就是把 20 行空白 churn 混进本批），只在此留痕。

**一处本批自己制造又被自己抓到的错**：#2993 初稿写成「`job_wants_watcher` 的 Plan 默认**不受本开关影响**」——
读码后确认它是 `(globally_enabled, plan_default)` 的函数且支持 `watcher_policy.enabled is False` 逐 job 退出，
已改写。记下来是因为这正是本族要防的形态：一句听起来更清楚的概括，恰好是错的概括。

## Alternatives

- **只改字面、不补判据来源**（否决）：「默认 true」这种句子三天后又会失真。改写时把函数名/键名/行锚
  写进句子，读者能一秒钟自己证伪。
- **把 `--check` 扩成也比对行号列**（否决）：任何一行 getenv 之上的改动都会让无关 PR 点红，
  代价是把 required check 变成「每次都要重跑 `--write`」的税。改判据的方向应是**说清它比什么**，
  不是把门禁放宽或收紧到不合适的粒度。
- **给「最后更新」头部加机器校验**（本批不做，写进 Revisit）：`07-execution-protocol.md` 头部日期长期是
  2026-07-15 而正文改了 7 次，说明它是**无人约束的可派生量**（#2663 同因）。本批先把这句话写进文档
  当免责声明，加门禁另议。
- **顺手把 ADR-0048 v1.1 重议后的通过率轴残留（#2992）一起改**（否决，不同面且刚被改判）：
  #2992 的前提「run 级通过率判定轴已移除」在 `#2991`（ADR-0048 v1.1）后已部分失效，
  需要独立判断哪几处仍是活契约，不塞进本批。

## Revisit

- **「最后更新」头部应变成生成物或删掉**：若要加门禁，形状与 `env_inventory` 同（`git log -1 --format=%cs -- <file>`
  与头部比对，且只比日期不比作者），先数清有多少份文档带这个头部再决定值不值得扩面。
- **`.service` / `.conf` / `.sql` 不在 `test_removed_env_keys` 扫描面内**：本批只把事实写进文档。
  真要扩后缀，先跑一次「扩展后是否命中存量」——那可能直接点红 main，属另单。
- **文档真值对拍还剩两批**：`#2989`（`docs/adr/README.md` 索引两面失真——本批因 #3005 正在改同一文件而让路）、
  `#2992`（ADR-0048 v1.1 重议后的 9 处引用需逐条重判）、`#2995`–`#2996`、`#3000`–`#3004`。
- **jsdom 一节的病根**：当初把「一个维度不可测」写成「一类语义不可测」。若这类外推再出现，
  考虑给文档加一条判据（文档里的「测不到/不可能」类断言必须挂一个可运行的反例测试路径），
  但那是新门禁、不属本批。
