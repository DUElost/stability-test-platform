# /hosts 空态按「空集的性质」分三种：从未接入 ≠ 全部退役（#2362）

Status: implemented
Class: bug-fix

- 日期：2026-09-16
- 相关：`#2051`（空态仍保留「显示已退役」开关，本单不改那条）、ADR-0038 D5（退役列表的分键与共享缓存约定）、
  `#2358/#2359`（frontend truthfulness 批，同属「界面别把状态说错」一族但文件面不同）

## Decision

### 1. 用一条**只判存在性**的探针区分三态，而不是改 API 契约

主查询走 `include_retired=false`，其 `total` 也是**过滤后**的计数——空集无法自证是「一台都没有」
还是「都在退役态」。区分它有三条路：改后端返回 `retired_total`（动 API 契约 + types.ts + 契约用例）、
复用「显示已退役」那份查询（会把 limit=1 的结果写进用户随后要看的列表）、或**独立一条探针**。
选第三条：

```ts
queryKey: hostKeys.retiredPeek()          // ['hosts', { retiredPeek: true }]
queryFn: () => fetchHostList(0, 1, true)  // 只取 1 条 → 判存在性，不拉全量
enabled: !showRetired && !isLoading && hosts.length === 0
```

- **只在空态启用**：常态一次请求都不多发；`!isLoading` 是必需的，否则首屏会先白发一次
  （主查询还没回来时 `hosts` 也是空）；
- **独立分键**：复用 `retiredList` 会把 limit=1 的结果写进「显示已退役」那份列表
  （用户一点开关只剩 1 行）——ADR-0038 D5 的分键理由在这里同样成立；键同 `['hosts']` 前缀，
  `invalidateQueries({queryKey: ['hosts']})` 仍覆盖它。

### 2. 未知态保持既有文案（不猜）

探针未回/失败 → `hasAnyHost === null` → 沿用「所有主机都已退役…」。**不确定时不改口径**：
两个方向都会误报（说成「暂无主机」会把「全退役」的用户引离解除退役的入口），而探针在
真实环境是毫秒级返回。三态文案：

| 条件 | 标题 | 描述 |
|---|---|---|
| `showRetired`（开关已开） | 还没有主机 | 当前没有任何主机记录。 |
| 探针确认「一台都没有」 | 暂无主机 | 尚未接入任何主机。等待 Agent 接入后，主机会出现在这里。 |
| 其余（含探针未知） | 没有在用主机 | 所有主机都已退役。勾选「显示已退役」可查看并解除退役。 |

## Alternatives

- **后端返回 `retired_total`**：语义最直接，但要动 `PaginatedResponse` + 前端 types.ts + 契约用例；
  而这条信息只服务一个空态文案。**否**（真需要时另立单，届时它是「列表响应带计数」的一般需求）。
- **复用 `retiredList` 键**：见 §1，会把 limit=1 写进用户随后打开的列表。**否**。
- **不查、直接改文案**（例如一律说「暂无在用主机，可能都已退役」）：不用请求，但把两种情形
  混成一句模糊话——正是本单要消灭的「把状态说错/说不清」。**否**。
- **在 `showRetired` 为假时也把 `include_retired=true` 拉全量来判**：多拉全量列表只为渲染一句
  空态文案，成本远高于 limit=1 的探针。**否**。

## Verification

- `npx vitest run src/pages/hosts/HostsPage.test.tsx` → **23 passed**（新增「全新环境不把空集归因退役」）；
- `npx vitest run`（全量）→ **871 passed / 108 files**（唯一那条 `HTMLCanvasElement.getContext`
  环境报错为改动前既有，非本单引入）；
- **红向反证**：把探针摘掉（`hasAnyHost = null`）→ 新用例**红**（找不到「暂无主机」）；还原即绿；
- **既有用例的 mock 被修正**：「全部主机退役」原写法对两种查询都回空集——那其实是「全新环境」，
  会把空态口径掩盖掉。改为按 `include_retired` 分流（参数敏感实现必须挂在 `mockFetchHostList` 上：
  工厂里的 `mockHostsList` 是被**无参**调用的，不转发 args）；「开关穿透」原断言用「最后一次调用」
  指代主查询，现改为按调用集合断言（空态会额外发一条探针）；
- **实现泄漏**：`clearAllMocks` 只清调用、不清实现，参数敏感的实现残留会把后续用例的主列表打成
  空集（实测 7 条红）→ 在该 describe 的 `beforeEach` 逐测复位为模块级默认实现；
- `npx tsc --noEmit`、`npx eslint`（改动三文件）→ 无输出（干净）。

## Revisit

- **探针的轮询**：与主查询同为 10s。若将来主机规模上台阶、空态成为常态，考虑降频或只拉一次
  （当前空态罕见，10s 一次 limit=1 的代价可忽略）。
- **`retired_total`**：若还有别处要「含退役总数」（如页头统计），那就该由后端在列表响应里给出，
  本单的探针随之退役——触发条件：出现第二处需要该计数的界面。
- **文案措辞**：「等待 Agent 接入后，主机会出现在这里」是中性表述；若要给非 admin 也指路，
  需先确认安装入口对非 admin 的可见性策略（#2360 正在裁决入口可见性）。
