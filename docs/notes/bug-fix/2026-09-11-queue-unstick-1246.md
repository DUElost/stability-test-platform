# FIFO 队首停摆可见化：ci/queue-blocked 告警（#1246，R15-R02）

Status: implemented
Class: bug-fix

## Decision

问题：`pr-automerge-queue.sh` 对「队首 required check 非 SUCCESS」只在日志留一行
`skip head update` 后 `exit 0`——停摆无外部信号（#1205 实测卡住 12+ PR、含全绿
PR，靠人工巡检才发现）。既有 `tools/dev/queue_head_telemetry.py` 是**拉取式**判读
（要人主动跑），不解决「无人知晓」。

裁决（用户 2026-09-11）：**选项 2+3**（不做选项 1 的红队首自动重基——宽松谓词会
每小时重刷红 head 的全部 CI；收紧谓词留作后续独立评估）：

- **告警**：队列脚本在「队首非 SUCCESS」路径开/更新去重 issue（label
  `ci/queue-blocked`，与 `ci/backstop-failed` 同型）：指纹（队首 + 失败集）未变零
  写入；队首通过全部 required 或队列空时自动关闭。issue 操作用 workflow 注入的
  `ALERT_TOKEN`（GITHUB_TOKEN，job 授 `issues: write`）——不依赖
  `AUTO_MERGE_PAT` 是否含 Issues 权限；**任何 issue 操作失败都容忍**（可见性通道
  不得阻断或染红 reconcile）。
- **文档**：`repository-workflow.md` 队列节补「停摆判读 → 处置」runbook。
- 告警**只承载可见性，不参与合入决策**；`queue_head_telemetry.py` 零改动（遵守其
  「任何 workflow 不得据 reason_code 分支」约束——告警在队列脚本内用原生事实判断）。

## Alternatives

- **选项 1 红队首自动重基（一次 update-branch + 告警）**：暂缓——宽松谓词（红且
  behind）会每小时重刷红 head 的全量 CI；收紧谓词（非 SUCCESS 的 check 完成时间早
  于 head/main 推进）虽可无状态防重且不误触 #1205 型真实红，但属协议行为变更，留
  独立评估；
- **告警消费 telemetry 的 reason_code**：放弃——telemetry note 约束 4 明确禁止
  workflow 据其分支（会使其成为事实上控制面契约），须另行裁决；
- **仅做文档（选项 3）**：不足以解决「无人知晓」，与选项 2 合并交付。

## Revisit

- 选项 1（红队首一次逃生）若再现「陈旧红」实证（check 早于 main 推进且重基后可
  绿），按收紧谓词立独立项；
- 若告警噪音出现（如频繁 head 更替），可加「仅 head 更替才评论」的通知策略；
- 冲突形态已有 tolerant 人工指引、缺 check 归入同一「非 SUCCESS」判据，均已覆盖。
