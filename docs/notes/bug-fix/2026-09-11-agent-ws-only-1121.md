# Agent SocketIO 强制 websocket-only（#1121，R11-F13）

Status: implemented
Class: bug-fix

## Decision

ADR-0027 声明「LB 可不 sticky（RPC 走 room）」，但 Agent 的 `sio.connect` 未指定
transports → python-socketio 默认 **polling 优先**；而 polling 的 Engine.IO 会话要求
每个请求命中同一进程（会话亲和），与「无 sticky」冲突；`_build_url` 注释
「upgrades internally」只是假设。契约措辞超前于实现与实证：ops 的 rollout 清单本就把
「无 sticky RPC 验证」列为未勾选项（2026-07-21 决策「待验证窗口」）。

按验收「或强制 sticky / WS-only」分支（用户裁决「按推荐落地」）：

1. **实现**：Agent `sio.connect(..., transports=["websocket"])`——单条长连接 = 会话
   天然亲和 → 无 sticky 前提成立；WS 不可用**立即失败（可观测）**，不再静默降级为
   依赖 sticky 的 polling；`_build_url` 注释同步修正。
2. **契约**：ADR-0027 升 **v1.3**——清单第 4 条加前提（Agent WS-only + LB/nginx 支持
   WS upgrade；浏览器 WS-first、polling 回退需 sticky），并指向 rollout 清单未勾选项。
3. **验证记录**：nginx 模板 `/socket.io/` 的 WS upgrade 已核（`proxy_http_version 1.1`
   + Upgrade/Connection ✅）；新增单测（记录式假 Client 断言 transports）；
   **e2e 双实例无 sticky** 留给 rollout 窗口（清单项保持未勾选，注明前置已就绪）。

明确不做：浏览器强制 WS-only（牺牲代理回退可用性）；本地搭双实例端到端（生产宿主，
且验收已取 WS-only 分支）。

## Alternatives

- **只做契约回收**（改措辞为「需 sticky」）：能对齐，但放弃 ADR 的无 sticky 目标，且
  polling-first 默认在单实例下也无必要（WS 路径已就绪）；
- **双实例无 sticky 端到端验收**：需 ≥2 实例 + 非 sticky LB 环境（生产宿主不宜构造），
  留给 rollout 窗口执行；
- **浏览器也强制 WS-only**：代理阻断 WS 时仪表盘彻底不可用；保持 WS-first + 契约明示
  polling 回退需 sticky。
