## Decision

四条都是**同一形态**：窗口内代码行为变了，权威文档没跟上（或者根本扫不到）。逐条复验后按
「代码与测试为准，同步权威文档」处置；其中 #2655 的根因在**工具**，#2660 有一处在**代码**。

### #2655：扫描器盲区优先于补一行文档（根因修）

- **根因**：`tools/dev/env_inventory.py` 的读取名扫描是**逐行**的
  （`for lineno, line in enumerate(text.splitlines(), 1)`），而 `_int_env(` 的键名常写在
  **下一行**（`backend/core/job_timeout_config.py:86`：`HOST_HEARTBEAT_TIMEOUT_SECONDS = _int_env(\n
  "HOST_HEARTBEAT_TIMEOUT_SECONDS", production_default=300)`）⇒ 逐行正则在结构上看不见它。
  清单漏记与漂移门禁沉默是**同一个根因**。
- **修法**：helper 形态（`_*_env("X", …)`）改走 `scan_reads` 的**整文件通道**，行号按匹配偏移
  换算；`_HELPER_ENV_RE` 的实参捕获放开换行（`[^)\n]*` → `[^)]*`），默认值跨行也能取到。
- **代价与收益**：一修就看到同形态还有 8 个名字从来没进过文档附录——其中 **5 个连
  `.env.example` 都没登记**（`DISPATCHED_TIMEOUT_SECONDS`、`ABORT_REAPER_GRACE_SECONDS`、
  `PATROL_STALL_MULTIPLIER`、`PRECHECK_ACTIVE_STALE_SECONDS`、`PRECHECK_QUEUE_STALE_SECONDS`），
  另 3 个（`HOST_HEARTBEAT_TIMEOUT_SECONDS` / `RUNNING_HEARTBEAT_TIMEOUT_SECONDS` /
  `UNKNOWN_GRACE_SECONDS`）在示例里有、附录里没有。这正是 issue 说的「同类形态会继续漏」。
  那 5 个键按「需运维按环境调整」的口径**登记进 `backend/.env.example`**（注释态，含生产默认
  与一句说明），再从 `--write` 刷新文档附录（读取名 225 → 234）。
- 文档手写表补 `HOST_HEARTBEAT_TIMEOUT_SECONDS` 一行（issue 建议 #1），注明 #1518 后掉线窗口
  实际从 120s 变 300s。

### #2656：scan 只报告、退役是显式动作

`docs/development/script-versioning.md` 的「退役不被扫描复活」仍写「目录缺失即停用」=
**无条件**反激活；#2386（`164db542`+`71d1d10e`）之后真实行为是：只有被扫子树 == 部署目标
（`origin/main`）才反激活，否则跳过并在响应 `deactivation_skipped_versions` 显式列出 + 写审计；
显式出口 `?allow_deactivate=true`。文档已改为该语义，并指向 **ADR-0046 D2** 作为
「盘上缺失是否等于已退役」的裁决点（当前方向 = scan 只报告）。

### #2657：/health 的 schema 契约

`docs/design/02-backend.md` 的 readiness 描述只列 DB/Redis/SAQ 三条件；补 #1882/#1930 的
`503 SCHEMA_NOT_AT_HEAD` / `503 SCHEMA_PROBE_FAILED`、成功时 payload 的
`alembic_revision`/`alembic_head`，以及「非 production-like 与 `TESTING=1` 跳过探测」的边界；
中间件链补最外层 `ApiRequestMetrics`（最后注册 = 请求链最外层，故 CORS 预检/CSRF 403/限流 429/
路由 404 也计入 `stability_api_requests_total`）。

## Alternatives

- **#2655 只补一行文档、不修扫描器**：门禁对同一形态仍然沉默，下一个跨行 helper 还会漏
  （issue 明说「否则修完还会以同一形态复发」）。否。
- **#2655 用 AST 解析 helper 调用**：更彻底，但 `scan_reads` 现有实现是「按文件派生正则 +
  逐行匹配」的整体形态（含别名/裸调用/WSGI environ 误报防护），改成 AST 是一次工具重写；
  整文件通道用同一套正则、只换匹配面，改动面小且行为可测。记入 Revisit。
- **把新暴露的 5 个键声明为「内部」**：它们与已登记的 `RUNNING_HEARTBEAT_TIMEOUT_SECONDS`
  等同族、且在文档表里本就是「运维可调」的超时旋钮——声明内部等于让清单说谎。否。
- **#2660 ② 顺手删掉旧路径的标题登记**：旧 URL 仍会短暂重定向，删掉会让跳转过程显示上一个
  页面的标题；保留一份无副作用（issue 也给了「删除或保留」两可）。否（保留 + 注明）。
- **把 #2660 的 `replace_host_key` 也补进前端类型**：那是 API 契约扩张（且可能刻意只走
  API/CLI），需要 owner 裁决；文档批里夹带契约变更会掩盖它的决策属性。否。

## Revisit

- **扫描器仍是正则面**：整文件通道解决了「跨行实参」，但诸如 helper 名不在 `_*_env` 模式、
  或键名由变量拼接的形态仍会漏。若再出现同类漏记，升级路径是 AST
  （`ast.Call` 匹配 helper 名 + 第一个 `ast.Constant` 实参），代价是要重做别名/environ 误报防护。
- **`replace_host_key` 契约缺口**（#2660 附带）：等 owner 裁决「补前端字段」还是「在
  `types.ts`/文档里写明该字段只走 API/CLI」；裁决前 `types.ts` 与后端 schema 的这一处不同步
  是**已知且记录在案**的状态，不是遗漏。
- **#2659/#2661/#2662/#2663**（同日立案的其余文档漂移）本批未认领：其中 #2659 还牵扯
  `deps 文档缺 5 个新门禁`、#2661 牵扯 ADR-0039/0046 的 D2 走向，建议与各自的决策面一起做，
  不要混进本批。
