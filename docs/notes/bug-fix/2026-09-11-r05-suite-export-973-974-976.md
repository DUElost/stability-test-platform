# R05 Suite 导出/门禁收口：Global 完整性 + 物化窗口 + export_dir SOP（#973 #974 #976）

Status: implemented
Class: bug-fix

## Decision

R05（Plan/Suite/参数编排）三项 P2 收口：

1. **#976 门禁↔物化配置变更窗口（R05-F13）**
   预检 `collect_suite_gate_error` 与物化 `step_params_for_dispatch` 之间有较慢的
   脚本校验阶段；期间编辑用例会让「已校验内容」与注入的
   `expected_testpoint_count`（物化时点活表计数）分叉。新增
   `SuiteMaterializationConflict`：`step_params_for_dispatch` 注入前复核活表指纹
   必须等于冻结的 `dispatch_suite.exported_content_sha256`，不一致即抛错；
   `plan_dispatcher_sync` 捕获后把 PlanRun 结算为结构化 `FAILED`
   （`reason=suite_content_changed` + 审计），冲突**可检测**而非静默消费。

2. **#973 Global 文件未进入磁盘完整性/归档闭环（R05-F10）**
   原先只有 `runtask.xml` 有 `exported_sha256` 与归档；Global
   （`UiAutomatorTestData.xml`）磁盘丢失/被改无检测。新增
   `test_suite.exported_global_sha256`（迁移 `bb22cc33dd44`）：
   - 导出：计算 Global sha、归档到 `{exported_sha256}/UiAutomatorTestData.xml`、
     写基线列、审计含 global sha；
   - 门禁：步骤 2 要求 Global 基线非空且磁盘文件存在（缺失 → `not_exported`）；
     新增步骤 4b 校验 Global 磁盘 sha（漂移 → `global_sha_mismatch`）；
   - 冻结块与 API schema/前端类型同步 `exported_global_sha256`。
   决策：**Global 纳入门禁与归档**（与 runtask 同等 fail-closed）。

3. **#974 多套件共用 export_dir 可互相覆盖（R05-F11，已接受的设计风险）**
   保持「已接受」判断，不实现目录级互斥；按验收补运维 SOP：在
   `docs/operations/mtbf-api.md` 明确「共用 export_dir 属误配置、上线前须保证
   每套件 export_dir 唯一（显式 export_dir 或独立项目 key，勿都回落 legacy）」。

影响面：`backend/services/suite_binding.py`、`backend/services/plan_dispatcher_sync.py`、
`backend/api/routes/suites.py`、`backend/api/schemas/suite.py`、`backend/models/suite.py`、
`backend/alembic/versions/bb22cc33dd44_add_suite_global_sha.py`、
`docs/operations/mtbf-api.md`、`frontend/src/utils/api/types.ts`、
`backend/tests/services/test_suite_binding_gate.py`。

## Alternatives

- #976：在门禁通过时把计数写入 run_context（冻结）——需在 admission_pump 持久化
  并改变冻结块语义；物化前复核指纹是「版本复核」最小实现，且能同时捕获用例
  内容/启用状态的任何变化。
- #976：物化静默用冻结计数——冻结块未存计数，且导出 XML 的测试点计数与启用计数
  需从内容推导；复核指纹后取活表计数（此时等于导出时点）等价且更简单。
- #973：把 Global 仅作为 library 指纹的一部分（global_params）——可捕获库内编辑，
  但捕获不到**磁盘**丢失/篡改；磁盘漂移必须落盘基线。
- #974：实现目录唯一性运行时校验——已接受的设计风险，且合法用法可能依赖共享；
  以文档 SOP + 后续 ADR 触发条件处置。
