# R07 巡航/恢复面修复（#1008 #1010 #1012 #1013）

Status: implemented
Class: bug-fix

## Decision

R07（Agent 执行引擎与运行可靠性）四张 P2 缺陷一次收口，全部在
`backend/agent/`：

1. **#1008 patrol 生产布局导入（`patrol_recovery.py`）**
   `build_patrol_job_not_running_handler` 曾硬编码懒加载
   `from backend.agent.main import run_recovery_sync_if_needed`；
   `install_agent.sh` 只铺顶部 `agent/` 包（`ExecStart=python -m agent.main`），
   JOB_NOT_RUNNING 恢复入口在生产布局下 ImportError。改为相对导入
   `from .main import ...`——仓库布局（`backend.agent`）与安装布局（`agent`）
   均按当前 `__package__` 解析，双版可触发。

2. **#1010 checkpoint 恢复不得重置巡航预算（`pipeline_engine.py`）**
   巡航终止预算唯一参照 `init_completed_at=time.time()` 在 checkpoint 恢复时
   被重置，崩溃重启会重获完整 `timeout_seconds`。现每次 cycle 持久化
   `cruise_elapsed_seconds`；恢复时（仅 `timeout_seconds>0` 且字段为数值）把
   `init_completed_at` 回拨到 `time.time() - min(elapsed, timeout)`，使剩余预算
   不再放大；临近到期重启到顶即立即 timeout、不返抢。checkpoint 行 blob 本就是
   调用方自管 JSON，store 无 schema 改动。

3. **#1012 SIGTERM 结束整个巡航、不再退避重试（引擎 + main）**
   两处：
   - 引擎 `_run_step_with_permit`：`SchedulerShutdown` / `PermitCancelled`
     属整机/整 Job 终态，此前折叠成 `PermitDenied→False`，巡航把 denied 计为
     普通 step 失败并进入 backoff 退避重试。现两类单独拦截并 `self._canceled=True`，
     巡航主循环 L2030/睡循环据此立即 abort 收尾（普通 per-device 契约型
     `PermitDenied` 不触发整跑取消，行为不变）。`_run_patrol_cycle_steps` 每步
     前置 guard 并入 `_canceled`，失效后短路不重复 acquire。
   - `main` shutdown finally：`operation_scheduler.shutdown()` 只唤醒 permit
     等待者；新增对 `job_runner_state.active_runners` 全量 `request_abort`，令
     正在 RUNNING/巡航的引擎 `cancel()`（`_canceled`+杀进程树），其后
     `executor.shutdown(wait=True)` 才会在有界时间内排空，而非干等到 cruise
     自然超时。

4. **#1013 认领本地登记失败无补偿（`main.py`）**
   claim 后 `_register_active_job`（内存+token+`save_active_job`）在读 SQLite 前
   先占用 `_active_device_ids`；若落盘抛错，从登记到 submit 的路径直接炸进
   `agent_loop_failed`，busy 占位与 fencing 残留，且同批剩余 job 停止处理。
   现 claim 处把注册包进 try/except：失败即调用新增模块级纯函数
   `_rollback_failed_claim`（与 `_cleanup_after_job_exit` 同风格、参数注入：
   clear 当前 fencing、移除 active ids/token、释放 device 占位、drop 兜底行），
   随后 `continue` 让本批剩余 job 继续；server 下一 tick / recovery 重新对账该
   claim。

## Alternatives

- #1008：注入回调而非相对导入——需把 main 入口函数作为构造参数层层透传，面大；
  相对导入在双侧 `__package__` 下确定等价。
- #1010：持久化绝对 deadline 而非 elapsed——跨进程/重启取 `time.time` 前提相同，
  elapsed+现算与 deadline 等价，但 deadline 遇 clock 校准时反而不稳；elapsed 直接
  匹配现有 `init_completed_at` 语义，改动最小。
- #1013：把 `_register_active_job` 整体改成「先落盘后占内存」的事务式——上报与落盘
  顺序是运行语义，反转会引入锁外竞态；改为失败补偿更贴合现有“先占位防并发再持久化”
  设计。恢复路径（recovery RESUME）同类未包 try，留 Revisit。

## Revisit

- #1013 recovery RESUME 的同源 unguarded registration 未在当前 PR 覆盖；仅当
  recovery/恢复重认领面也出现 SQLite 失败时需按本 pattern 补齐。
- #1012 main 侧 `executor.shutdown(wait=True)` 无自定超时（`ThreadPoolExecutor`
  语义使然）；若未来需强制上界，须另行设计 hard timeout + 残留 worker 对账，
  非本 PR 目标。
