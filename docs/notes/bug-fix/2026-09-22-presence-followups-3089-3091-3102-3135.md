# presence 四单收尾：塌片判定 / 账本清理 / 写端点权限 / 指标事务

Status: implemented
Class: bug-fix

## Decision

第五道闸（#2958，PR #3047）上线数小时内被审计开出的四张后续单，一次收口：

| 单 | 修法 |
|---|---|
| **#3135**（P2，缺口面失效） | `classify_host_presence` 的「整片 unknown」判据从 `not verify_ok` 收窄为**只有 RPC 级失败**（`agent_offline` / `rpc_failed*` / `verify_exception*`）。`sha_mismatch` 这类**逐条结果可用**的失败一律逐条判（present/missing/mismatch）——此前一台机只要有一个文件 sha 不符，整机 28 个可达目标全变 unknown，操作者拿不到「是哪个脚本版本」，第五道闸抓 `.89` 类缺口的本职直接失效 |
| **#3089**（P2，账本只增不减） | sweep 收尾按**本轮生成集**做差集删除：全量 sweep 删「不在本轮 host 列表」与「本轮 host 但 `sweep_id != 本轮`」的行；单机 refresh 只清该 host 的孤儿行。三个次生面随之消失（`min(checked_at)` 不再被历史行钉死 ⇒ `SweepStale` 不再恒响；孤儿 gap 行不再冻结 gauge child ⇒ `Gap` 不再恒响）；`refresh` 对退役 host 改 **404**（原 200 + 全零是静默空转，告警 Runbook 指向一个假成功）；`SCRIPT_PRESENCE_HISTORY_DAYS` **接线**（调度作业与按需刷新都读它，此前是死旋钮） |
| **#3091**（P2，写端点越权） | `POST /refresh` 改 `Depends(require_admin)`（除账本 upsert 外它还触发 agent RPC，与同域写端点同权限面）；前端按 `isAdmin` 不渲染「重新核验」按钮；新增 AST 结构守卫 `tests/test_script_presence_admin_guard_3091.py`（本域全部非 GET 端点必须出现 `Depends(require_admin)`，且有覆盖面自证 + 红绿双向自证） |
| **#3102**（P2，指标事务污染） | `_refresh_script_presence_gauges` 的 `except SQLAlchemyError` 补 `db.rollback()`——它是抓取链第 5/7 环，失败读会把共享 session 置为 aborted，后续 lock-wait / 链覆盖组在同一次 scrape 里连环静默缺失 |

## Alternatives

1. **#3135 的判据位置**：也可在 `precheck.verify.verify_one_host` 里改 `all_ok` 的返回语义（让「逐条失败」不置 `ok=False`）——但那会动 run-scoped 派发门的判据（那里 `all_ok=False` 是要触发 SFTP 自愈/fatal 的），风险外溢；故把区分放在**消费侧**（本模块），派发门语义零改动。
2. **#3089 的清理形态**：软删（`retired_at` 列 + 全查询处过滤）保留了历史，但给每个读点都加一个过滤条件、且「历史」无人消费；硬差集删除让「表 = 当前矩阵」这一不变量成立（gauge/新鲜度/API 三处读点都自然正确），故取硬删。
3. **#3091 的处置**：审计给了「补 require_admin」与「显式化运维可重核角色」两条路。取前者——`refresh` 会触发主机侧 RPC 与库写，且**非管理员在 UI 上也拿不到上下文**（按钮已隐藏）；后者需要先有「运维角色」这一不存在的概念。
4. **#3102 的隔离级别**：也可给该面单独开 session / nested transaction，但同文件既有 6 组刷新全是「共享 session + 只 warning」，补一行 `rollback()` 与既有风格一致且最小。

## Revisit

- **`orphans_removed` 是新读数**：sweep 汇总里出现它（>0 表示本轮真删了历史行）。首轮上线后
  它必然 >0 一次（清掉此前累积的孤儿），之后长期为 0；若持续 >0 说明目标集在频繁抖动
  （计划改指/停用脚本），值得看一眼 sweep 日志。
- **同族未修**：`_refresh_fleet_gauges` / `_refresh_host_device_adb_gauges` /
  `_refresh_host_health_gauges` 也都没有 `rollback()`（#3102 只点了 presence 这一环）。
  它们若失败同样会污染后续组——属同一形态的存量面，建议另立单（本 PR 不顺手改：那三处
  不在四单射程内，且失败时的正确隔离方式值得单独定）。
- **`unknown` 仍不判红**：agent 不可达时的整片 unknown 只计数；若长期大面积 unknown 需另立
  覆盖类告警（与 #2957 一族同层）。
