# 09-22 审计立单与备注批修复：11 处缺陷（#3100 #3101 #3103 #3104 #3105 #3107 #3108 #3109 ＋ #2959 #2972 #2983）

Status: implemented
Class: bug-fix

## Decision

对 09-22 审计窗口（`22715aad`→`c2c8be51`）立单的自有缺陷逐条修复。**唯一来源**与
**判据方向**是本批的两条主线：能合并成一个定义的就合并（#3101），能把「未知」与
「干净」分开的就分开（#2983/#2959/#3105）。

1. **#3100（access log）**：`is_access_log_noise` 的判据从 `>= 400` 改为
   `not (200 <= sc < 300)`。原式把 1xx/2xx/3xx 一律当成功丢弃，与四处声明
   「只丢 2xx / 非 2xx 恒保留」不符。
2. **#3108（审计分层）**：`register`（公开自助注册＝账号创建）从
   `BUSINESS_ACTIONS_ALLOWLIST` 移入 `SECURITY_ACTIONS`（180d），并同步
   ADR-0049 D1 表；新增**层**断言测试——AST 守卫只能发现「未登记」，发现不了
   「已登记但归错层」。顺带修复该守卫在 main 上的既有红：本窗口其它 PR 引入的
   `bulk_swipe_trail` / `ensure_flash_prereqs(_request)` /
   `host_health_probe_agent_mute` / `step_trace_stall_detected` 五个 action
   未登记（守卫在 `backend/tests/` 内，PR 路径不跑 ⇒ 悄悄累积）。
3. **#3103（目录→zip）**：加 512MiB 未压缩上限（先量后压，超限 413 不留 temp）；
   symlink 判据与读取合并为同一个 `O_NOFOLLOW` 打开（取代「先 rglob 查、再按名
   `zf.write`」的 check-then-use）；成员名净化（反斜杠 / `..` 段拒绝）。流式与
   异步化仍留作 Revisit。
4. **#3105（skill 用量源在场）**：`_has_transcripts` 判「目录存在**且**有
   `*.jsonl`」，空目录与缺源同判；并修同一分支的既存缺陷——无源时先打人类文案再
   打 JSON，会让探针 `json.loads(stdout)` 失败并被读成 `broken`（「探针崩了」）。
5. **#2959（压测腿池读数）**：`checkout_failures_by_kind(after, before)` 对
   `stability_db_pool_checkout_failures_total` **按 kind 全量汇总**，不再枚举
   `timeout`/`error` 两条——新增 kind（如 `slots_exhausted`）自动进入失败判据。
6. **#2983（探针采集失败）**：新增 `ProbeVerdict.PROBE_ERROR` 与
   `ProbeRound.collect_failed`；`collect_failure_reason` 判「非零 rc **或**本该有
   输出却为空」（非特权 journalctl 正是 `rc=0` + 空 stdout 的形态）。判定排在
   空柜早退**之前**，否则「采不到」仍会被读成 ALIGNED。
7. **#2972（xHCI 动作门控）**：破坏性动作不再复用告警侧的宽松谓词。新增
   `is_usb_tree_verifiably_empty`（`usb_device_count == 0` ∧ `other_usb_nodes == 0`
   ∧ `discovered_devices == 0` ∧ `root_hub_count > 0`）；`GateInput` 增
   `other_usb_nodes`（关键词排除的外设单独计数）与 `host_ledger_device_rows`
   （承接 #2967 给告警加的「本应有设备」合取，新增 `REASON_HOST_LEDGER_EMPTY`）；
   裸字符串 `"no_pci_ids"` 收回 `REASON_NO_PCI_IDS`。
8. **#3104 + #3107（agent 脚本，新建版本）**：`clear_recents v1.0.4`——循环内读失败
   记入 `metrics.read_failures` 后 `continue`（消耗一次尝试），最后一次仍失败才转红
   （v1.0.3 的 `max_attempts` 对读失败不可达）；`monkey_setup v2.3.11` 与
   `clear_recents v1.0.4` 分别新增 `validated_log_dirs` / `validated_dump_path`，
   把计划参数的白名单校验挡在插入设备端 shell 之前。**已发布目录一律原地不改**
   （ADR-0020/0029），故走新版本。
9. **#3109（守卫作用面与基线）**：`EMPTY_LIFECYCLE` 从 `check_device 1.0.0 / 30s /
   retry 0` 对齐到 8 个模板的同值（`1.0.2 / 180 / retry 1`），并让 timeout 守卫
   **解析该 TS 文件**参与断言（两个生产者不得漂移）；pin 守卫新增
   「pin 与例外值必须对应真实存在的版本目录」——此前只比版本号大小，写错一个字符
   就能引用一个既不在磁盘也不在 DB 的版本。
10. **#3101（成功率口径）**：立单一来源
    `backend/models/enums.py::PASSING_PLAN_RUN_STATUSES`（= 链触发
    `TRIGGERABLE_TERMINAL_STATUSES` = 种子验收 `PASSING_STATUSES`），
    `results.py` 风险趋势与 `scripts.py` 用量 SQL 改为引用它。

## Alternatives

- **#3101 反向（保持「只认 SUCCESS」）**：即认为部分成功不该计入成功率。放弃原因：
  平台内已有两处把它当通过（链触发据此继续下一段、种子验收据此判通过），
  前端 `PlanRunDetailPage` 也把 `SUCCESS || PARTIAL_SUCCESS` 当「已完成」。反向修改
  要同时推翻这三处，属产品裁决；本轮取「与既有语义对齐 + 立单一来源」，把裁决面
  缩到常量一处。
- **#3103 直接用 `extra=` / `exclude=` 保持兼容**：与仓库既有约定不符——
  `backend/core/artifact_paths.py::_copytree_fd_at` 已是 `O_NOFOLLOW` + fd 遍历的
  正解，本条是让新面回到同一严格度。
- **#3103 现在就做流式 / 交 SAQ**：改动面涉及路由契约（返回 token 轮询）与前端，
  超出「修复已立缺陷」的范围；本轮先立上限消除「一次请求填盘」，流式留在 Revisit。
- **#3109 把 pin 守卫基线改成「已注册∧激活」head**：需要测试进程拿到 DB 状态
  （或部署期落一份 snapshot），是接口/CI 层面的设计决定；本轮先补「版本目录必须
  存在」这条离线可验的牙，并把基线语义写进注释，避免擅自引入新的 CI 机制。
- **#2972 只收紧谓词、不加字段**：那样「被关键词排除的外设」（USB 归档盘 / 网卡）
  仍不可见，rebind 会把它们从总线拔掉。`GateInput` 目前只由测试构造（心跳接线属
  后续切片），故现在加必填字段最便宜——接线切片必须显式提供证据。
- **#3104 直接改 v1.0.3**：违反 ADR-0020「已发布版本不可原地改」。

## Revisit

- **zip 流式化 / 异步化**（#3103）：`MAX_ARCHIVE_BYTES` 是常量而非 env 旋钮——
  新增 env 键要过 `env_inventory` / `test_env_example_parity` 两道台账。若运维需要
  按部署调上限，走一次台账登记；并发下载仍会各自占一份 `/tmp` 副本，真正的解是
  流式或 SAQ。
- **pin 守卫基线**（#3109）：`--pending-activation`（#2931）已是「磁盘 vs 库」差异
  的人工视图，但它没有接进任何门禁。若要自动化，建议由部署期落一份
  「已注册∧激活 head」snapshot 供测试读取，而不是让测试去连库。
- **`#2983` 窗长口径**：`journal_kernel_2h` 是 2h 窗而 `link_error_threshold=20` 按
  1h 标定（agent 侧 `LINK_WINDOW_SECONDS=3600`）。要在 fleet 上取证后再定：是缩到
  `--since -1h` 还是把阈值按窗缩放。
- **`#2972` 的熔断器持久化**：#2972 既有复核备注已记「boot/48h 计数是进程内存态」，
  接线切片落地时应一并按 `boot_id` 落盘。
- **`#3108` 的层断言**：本轮只钉住「账号/凭据事件」这一组。若要全量，可把
  ADR-0049 D1 表变成机器可读的期望层映射。
