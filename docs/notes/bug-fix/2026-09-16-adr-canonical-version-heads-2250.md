# 5 篇 ADR 补规范位版本 + 索引面同步 + 冻结目录永久豁免登记（#2250）

Status: implemented
Class: bug-fix

## Decision

#2250 的正面收口：给头部不带规范位版本的 5 篇 ADR 补上**版本记录里的最新版本**，使
S14（#2249 放宽后的集合判据）对它们真正生效；同时把冻结目录的 6 处引用登记为**永久
豁免**。

| ADR | 头部补的版本 | 取值依据 | README 状态/版本 | DOC-MAP 末 token | M7 看板 |
|---|---|---|---|---|---|
| ADR-0029 | v2.5 | `## 修订记录` 表末行 v2.5（派生归属重设计） | Accepted / v2.5 | 无该行（不约束） | 条目存在但非 `**Status** vX.Y` 形态（不约束） |
| ADR-0030 | v1.9 | `## 修订记录` 表 v1.9（P2 实施记账） | Accepted / v1.9 | v1.9 ✓ | `(**Accepted** v1.9)` ✓ |
| ADR-0036 | v1.0 | `- 版本记录：` 项目符块 v1.0 | Accepted / v1.0（**补 `：`**） | v1.0 ✓ | 不在看板 |
| ADR-0038 | v0.2 | 缩进子项块 v0.2 | Accepted / v0.2（**补 `：`**） | v0.2 ✓ | 不在看板 |
| ADR-0042 | v1.1 | 缩进子项块 v1.1 | Accepted / v1.1（**改写开头**） | v1.1 ✓ | 不在看板 |

版本值不新造：一律取该 ADR 修订记录里的最新版本，与 README 索引**既有**版本前缀一致
（5/5 一致，实测）——即本次只是把索引面早就在说的事实补进权威面（头部）。

三处 README 主表行的**版本前缀形态**要一并规整（S12 的 `^v(\d+\.\d+)：` 要求版本号后
紧跟全角冒号）：

- ADR-0036 `v1.0 定稿（…）` → `v1.0：定稿（…）`
- ADR-0038 `v0.2 定稿（…）` → `v0.2：定稿（…）`
- ADR-0042 `v1.1（2026-09-14 P1 试点完成：…）` → `v1.1：P1 试点完成（2026-09-14；…）`
  （顺带把内层冒号改分号，避免双冒号）

**存量引用核对（issue 第 3 步）**：全仓 70 处引用在新判据下 0 红，且**一处都不用改**
——抽查确认它们引的是**当时版本**而非过期版本：ADR-0029 的 3 处 v2.3 全部指向 v2.3 D
的 `on_subscribe` 收窄裁决（`socketio_server.py:335/442`、`test_dashboard_subscribe.py:1`），
ADR-0042 的 4 处 v1.0 指向「引入 pydantic-settings」这条 v1.0 裁决，ADR-0030 的 21 处
v1.4/v1.8 指向 D2 绑定机制与绑定翻转硬拒。把它们「升到头部版本」反而是错的——这正是
#2249 放宽判据的用意。

**冻结目录永久豁免（issue 收口动作 3）**：`backend/agent/scripts/` 整枝排除面现有 6 处
ADR 引用——`mtbf_setup` v1.0.0–v1.4.1 各一处 `ADR-0029 v2.2`（补偿机制注记）。内容冻结
（ADR-0020 + 硬不变量）→ 永远无法修，只能随版本退役自然淘汰。已在
`CODE_SCAN_SKIP_PREFIXES` 常量注记与治理面文档 S14 行**显式登记为永久豁免**，避免后人
读常量时误判为漏扫。

## Alternatives

- **A. 把这批「旧版本引用」统一升到新头部版本**：否决。注释引的是该注释所实现的那版
  裁决（见上），升版本会把事实改错；且 24 处会一次性引入无意义 diff。前序 Note
  [`2026-09-16-s12-s14-gate-criteria-2035-2249.md`](2026-09-16-s12-s14-gate-criteria-2035-2249.md)
  §Revisit 记的正是这条权衡。
- **B. 不补头部版本，只扩 S14 扫描面**：否决。S14 的纪律是「头部无版本者不约束」，
  不补头部 = 这 5 篇的 57 处引用继续零门禁，issue 本体（覆盖缺口）没解决。
- **C. 顺带把 ADR-0029 的 M7 条目归一为 `ADR-00XX（**Status** vX.Y）` 形态**：不做。
  会**新激活**一条此前对该 ADR 休眠的检查（S12 的 M7 比对按该形态匹配），且当前两面
  自洽、无漂移信号；属独立议题，记入 Revisit。
- **D. 新增 ADR 版本时不取记录最新版、而取「下一个版本号」**：否决。issue 正文曾按
  「必然 bump 到 ≥ v2.6」估红灯规模（51 处），但头部的规范位版本语义是**最新已发布
  版本**，不是「本次编辑产生的版本」；取记录最新版后 ADR-0029 的 27 处引用本就与头部
  一致，实际会变红的只有 24 处（且已被 #2249 判绿）。

## Revisit

- **前置依赖**：本 PR 的 `--check` 绿依赖 #2249（#2267）已合入——头部带版本后，旧判据
  「== 头部版本」会让 24 处历史引用变红。合入顺序由 FIFO 队列保证（#2267 在前）。
- **M7 看板的形态盲区**：`_ADR_M7_ENTRY` 只认 `ADR-00XX（**Status** vX.Y）`，ADR-0029
  的条目写作 `ADR-0029（项目分类域·登记簿；v2.5 …）` → 不受 S12 约束（本轮未动它，两面
  恰好一致）。若要让 M7 看板全覆盖，得先决定是否统一措辞形态——独立议题。
- **头部版本的后续维护**：这 5 篇今后 bump 版本时，S12/S14 会分别强制索引面同步与代码
  注释落在已发布集合内；但「何时算发布了新版本」仍靠 ADR owner 在修订记录里落行——
  版本记录是集合的唯一事实源，写法（单行罗列 / 缩进续行 / 缩进子项 / 表格）都可以，
  三种都会被读到（#2249 实测覆盖）。
- **零引用退役面**：`mtbf_setup` 的 6 处豁免随版本退役自然消失；退役通道见 #735 的
  零引用判据，本单不再登记额外动作。
