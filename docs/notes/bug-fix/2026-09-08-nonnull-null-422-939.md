# Project/Suite 更新 schema：不可空列显式 null 422 收口（#939）

Status: implemented
Class: bug-fix

## Decision

#939（R03-F06）：`ProjectUpdateIn.display_name: Optional[str]`（validator 对
None 原样返回）与 `TestSuiteUpdateIn.is_active: Optional[bool]`——更新提交
`{"display_name": null}` / `{"is_active": null}` 被 Pydantic 接受，routes 按
`fields_set` 赋值到 `nullable=False` 列，提交期 IntegrityError → 500。

修复（schema 层拦截，routes 零改动——两处 update 路由本就按 fields_set /
exclude_unset 正确赋值）：

- `ProjectUpdateIn` / `TestSuiteUpdateIn` 各加
  `model_validator(mode="after")`：字段 ∈ `model_fields_set`（显式提供）且值
  为 None、而对应列 NOT NULL → `ValueError` → 422。「未提供 = 不改」语义由
  fields_set 判定，不受影响；可空列（customer / jira_project_key /
  display_name(suite) / export_dir）显式 `null` 清空语义保留；
- 长度同步：`ProjectUpdateIn.display_name` 补 `max_length=256`、
  `customer` 补 `max_length=64`（DB 列 String(256)/String(64)）——创建侧
  display_name 已有 256，customer 缺约束属相邻观察（本单按 issue 证据只改
  更新面，未动 CreateIn）。

## Alternatives

- 不可空字段去掉 Optional：破坏「未提供 = 不改」——缺字段也会 422，局部
  更新语义失效；
- route 层逐字段判 None：schema 是所有入口的唯一闸门（未来新增调用方自动
  受保护），且 routes 现有 fields_set 逻辑无需复制改动；
- 同步修 CreateIn.customer 缺长度：超出本单证据面（issue 点名更新 schema），
  note Revisit 留痕。
