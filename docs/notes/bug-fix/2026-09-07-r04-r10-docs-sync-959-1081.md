# 文档与代码漂移同步：热更新键表/批量行为 + 方案 C 存储路径（#959 / #1081）

Status: implemented
Class: bug-fix

## Decision

两处权威文档与现行代码不一致，按代码为真源修正（**不动代码**）：

1. **#959（R04-F16）`docs/operations/agent-version-and-hot-update.md`**
   - `STP_AEE_LOCAL_ROOT` 从「舰队默认（两边同值）」表移除，改列入「不同步
     （每台机器独有，热更新绝不改写）」清单并注明主机本地 L1 路径差异
     （NVMe+HDD vs 纯 SSD）——与 `agent_env_sync.PROTECTED_ENV_KEYS` 一致
     （`docs/development/environment-variables.md` 本就已正确描述
     「hot-update 不下发」，本次只补齐 hot-update 文档）；
   - UI 描述由「浮动批量栏仅允许**选中一台 ONLINE** 主机」改为「多选 +
     **安全批量热更新**（受控并发 2，完成后汇总成功/跳过/失败），批量安装同样
     支持多台」——与 `HostsPage.tsx`（`useHostOperations({concurrency: 2})`、
     确认对话框与汇总 toast）一致。
2. **#1081（R10-F13）`docs/design/2026-plan-c-storage-and-access.md`**
   - §3.2 HddSpill：由「按 mtime 找最旧事件目录 → `copytree` 到
     `{cifs_root}/devices/{rel}`」改为现行 DLE 路径——取 `state=LOCAL` 事件经
     `EventUploader.enqueue_local_event(..., prune_after_upload)` 上送（落盘
     `devices/{plan_run_id}/` 或 `unassigned/{event_id}/`），上传校验后释放本地
     磁盘（#382）；mermaid 边标签同步；
   - §3.3 由「启动耦合（已知债）」改为「启动解耦（P2-3，已完成）」：`main.py`
     中 LogArchiver / LocalDiskMonitor 先于 `watcher_subsystem_enabled()` 块启动、
     各自按自身 env 门控，`STP_WATCHER_ENABLED=0` 不影响归档与 spill
     （历史债 #32 已关闭）。

## Alternatives

- **反向改代码（PROTECTED_ENV_KEYS 去掉本键 / 恢复单台批量）**——放弃：代码方向
  正确（本机路径不可 fleet 覆盖；并发 2 是受控批量），issue 亦明确「代码保护
  方向不应反改」；
- **只改一处、另一处另开单**——放弃：两个 issue 各自同一验收面，合并一单成本
  更低、评审一次到位；
- **回填历史文档（docs/archive、docs/reviews、旧 notes）**——不做：历史记录是
  当时快照，不追改。
