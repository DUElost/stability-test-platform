# 文档漂移批收口：#2037 / #2038 / #2041 / #2042 / #2043

Status: implemented
Class: bug-fix

## Decision

一次性收口 2026-09-07 → 2026-09-14 变更审计产出的 5 个文档漂移单（合计 17 处），
并给复发面补上机械守卫。**每处先按 `origin/main`（`a4128cb4`）代码/测试复核再改**，
以下三处 issue 描述与现状不符，以代码为准：

1. **#2041-1 部署源守卫的实际语义已再收窄一次**：issue 写「失败即 exit 1（库必须等于
   head）」基于 `e28f8baf`；此后 **#2062** 把该调用改成
   `check_alembic_at_head.py --allow-behind`——手工部署路径「pull → 守卫 →
   `alembic upgrade head`」中库**合法地落后**，故只拒「库超前于代码 / 修订未知」，
   落后仅 WARN；精确相等留给 systemd `ExecStartPre`（不带该参数、位于 `upgrade head`
   之后）。三处文档按**这个**口径写，不照抄 issue 的措辞。
2. **#2042 的 5 处断链实为 6 处、且两个笔记文件名有误**：issue 写
   `…-runconsole-status-snapshot-1737.md` / `…-runconsole-cancel-forwarding-1737.md`，
   实际文件名多一段 `console-`（`runconsole-console-*`）；`PROJECT_REVIEW_PLAN.md`
   的断链行已从 `:352` 漂到 `:367`（窗口内该文件被改过）。以实测 8 处扫描结果为准，
   修掉 6 处真断链。
3. **#2043 的版本号在合并前又前进了一次**：`flash_firmware` 已是 **v1.3.16**
   （issue 基于 `172c0326` 写 v1.3.15）。故 runbook **不换一个号**，改成「取最新
   active 版本」的判据 + 查询命令 + 「2026-09-15 复核值」，避免下次发布再过期。

改法分两类：

- **文档同步**（#2037/#2038/#2041/#2042/#2043 共 15 处）：ADR-0007 三处补「已删除
  （#1526）」标注、`05-data-model` 补 `exported_global_sha256` 与 `notification_delivery`、
  `03-frontend` 修 `/notifications` 角色与 `build:prod`、设备日志规格补 spill 临界分支、
  存储别名按「仅控制面 / 仅 Agent」重写、`repository-workflow` 的 #1569 前移状态、
  lint job 补充两步、`ALLOW_SQLITE_TESTS` 从两份开发文档移除、6 处失效相对链接。
- **机械守卫**（防复发，都是「同一缺陷第二次出现」的直接原因）：
  - `backend/tests/test_ci_and_test_harness_files.py`：SQLite 退路断言从「只守
    `testing.md`」扩到 `docs/development/**/*.md`（#1299 修了 testing.md 却漏掉同族
    两份，正是本条要堵的缝）；
  - `tools/dev/check_governance_surface.py`：S2 断链检查从**固定白名单**扩到
    `docs/reviews/**` 与 `docs/notes/**` 全树（实测全仓 `docs/**` 仅 8 处断链，6 处
    真、2 处是行内 code 示例，故同时加「跳过行内 code span」——`` `[标题](file.md)` ``
    是示例而非渲染链接）。

## Alternatives

- **runbook 直接把 v1.3.10 换成 v1.3.16**：最省事，但下次发版即再过期（本 issue 就是
  这么产生的）。选「判据 + 查询命令 + 复核日期」，代价是执行时多跑一条 curl。
- **runbook 换成「v1.3.15」（issue 写作时的最新）**：合并前 `main` 已是 v1.3.16，
  照抄即交付一份当天就过期的文档——故以实际 `git ls-tree` 为准。
- **`aee_signal_trigger` 只换版本号不加理由**：该 signoff 的 S2 验收要排除的失败模式
  （认领并发来源的 AEE 事件）恰是 v1.0.1 修掉的那个缺陷（#816），把「为何 ≥ v1.0.1」
  写进文档比换个数字更能防止回退到 v1.0.0。
- **S2 只扩到 `docs/reviews`（放弃 `docs/notes`）**：notes 里有行内 code 示例会被
  误报。选择「扩面 + 跳过行内 code」而不是缩小覆盖面——后者会让 4 个 runconsole
  链接这类问题继续无声复发。判定为 BLOCK 而非 advisory：扩面前实测噪音为 0。
- **不给 ADR 加版本记录块**：ADR-0007/0015 属勘误式补注（不改决策、无状态迁移），
  与 `:101` 既有口径一致；S12 索引一致性校验已绿（两文件头部行无规范位版本，不触发）。
- **顺手重构 `ADR-0007` 的「历史决策（已废弃）」段**：不做——只标注矛盾行，避免把
  历史决策整理混进本批。

  §3 的 JSON 里的 `script_version` 需要重跑一次查询命令复核；`2026-08-29-post-review-deploy-runbook`
  §7.2 同源。若该纪律再被绕过，应考虑把「runbook 版本 pin 过期」本身也做成门禁（当前
  无机械判据，成本待评估）。

  `docs/design` 等仍只覆盖白名单文件。若那两树下再出现同类断链，按同一模式扩面。
- **`ALLOW_SQLITE_TESTS` 历史留档**：`docs/archive/**`、`docs/notes/**` 与
  `backend/alembic/versions/p1q2r3s4t5u6_*.py` 注释里仍有该词——属历史记录（非现行
  指引），新断言只覆盖 `docs/development/**`，不追改历史。
