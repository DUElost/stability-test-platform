# skill_usage：缺强信号源不判 HOLLOW（#2851）

Status: implemented
Class: bug-fix

- 日期：2026-09-20
- 关联：`#2851`（本单）、`#2785`/`#2804`（探针多源化批次——引入面）、
  `stp-skill-usage.timer` 与 `check:gov` 的两个消费面

## Decision

`tools/dev/skill_usage_report.py`：

1. `is_hollow(...)` 增 `strong_source_present`（关键字参数、缺省 True 保持既有语义）——
   **强信号源不在场时一律不判洞**；
2. 表格的 Claude 列在缺源时显示 **`未扫（源不在场，不判洞）`**，而不是把未扫描的源印成
   「调用 0 次 最近 从未」。

**判据本质**：HOLLOW 是「**观测到**零强信号调用」的结论，而它的前提是**该信号源被人扫过**。
原实现里「目录缺失」与「零调用」在数据面上不可分（`claude.get(name, (0, None))` 同形），
于是「没数据」被静默当成「没发生」——把**观测缺口说成观测事实**。这与 #2851 点名的两个消费面
（timer 恒红、`check:gov` 假告警）是同一个根因；模块自己的契约「缺源自动跳过——他机/新站点
不得确定性红灯」此前只覆盖**两源皆缺**。

## Alternatives

- **把缺源与零调用在数据面上区分（用 `None` 代替 `0`）**：更彻底，但要改 `scan_claude`/
  `scan_codex` 的返回形状与所有消费点（`total`/`last` 的取值处 + 表格格式），收益与
  「一个判据参数」相同。否（当前形态最小且判据集中）。
- **缺源时直接 `return 0` 早退（照搬「双缺」的处理）**：那会连**弱信号源可用**的信息也丢掉
  ——codex 列在缺 claude 的机器上仍是有用的审计输入（本单只要求「不判洞」，不要求「不显示」）。
  否。
- **把 HOLLOW 阈值调大/加宽限**：治的是症状（什么时候不红灯），不是「缺源 ≠ 零调用」这个
  分类问题。否。
- **在 timer/gate 侧忽略退出码**：等于放弃判据，且另外两个消费面（交互式读取）仍会看到
  假的「0 次/从未」。否。

## 过程记录（两条都记账）

- **工作区纪律踩线**：本单的编辑我第一次落在了**主检出**（共享工作区）——起因是上一条命令
  的 `cd` 把 cwd 留在了主仓，后续相对路径编辑就落在那里。更糟的是，两次尝试保存补丁时
  `git diff` 都是**空**：改动已被并行会话清掉（`worktrees-vanish-commit-early` 的已知形态）。
  改动内容当时还在对话里，遂在**专属 worktree**（`.wt/stp-2851`）重放并**立即 commit**。
  教训：跨任务时先 `pwd` + `git -C <我的 worktree>`，编辑前确认落点；落盘（commit）窗口越短越好。
- **变异脚本自身出错两次**（`-k` 表达式被拆成多个 argv；选择器写成 `missing_source` 而用例名是
  `source_missing`）——两次都表现为「0 个用例被选中」，不是「用例没红」。**变异无效时先看
  选中数量**，与 #703①/#2718 那两次「锚点必须有判别力」同源。

## Revisit

- **数据面区分（`None` vs `0`）未做**：若将来出现第三种「半可观测」形态（例如转录目录在但
  格式变了、扫描抛异常），当前实现会把它当成「零调用」——那时应上移为数据面区分，而不是再加
  一个布尔参数。
- **`HOLLOW_DAYS` 与源在场的关系**：本单只处理「源不在场」；若他机的 claude 目录**存在但为空**
  （新装环境），仍会判洞——那是「真零调用」还是「数据没长出来」，需要 `runs`/时间维度的证据，
  留待有实例时再判。
