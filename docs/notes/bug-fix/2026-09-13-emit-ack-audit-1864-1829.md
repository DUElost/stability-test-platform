# emit ack 送达口径 + REST retry-dispatch 审计归因（#1864 #1829）

Status: implemented
Class: bug-fix

## Decision

#759 收口的两处残留：

1. **#1864 `_schedule_emit_agent_control` 的 Future 被丢弃**
   原实现用 fire-and-forget 的 `emit_agent_control` + `run_coroutine_threadsafe`，
   丢弃返回的 Future——协程体内异常（sio 未初始化/关闭竞态）静默沉淀，调用方
   已把 host 记入 `triggered`，emit 层仍可能「假成功」。改为桥接 ack 版
   `socketio_server.call_agent_control_sync`：等待 Agent control handler 确认，
   仅送达才返回 True；主循环不可用/超时/异常 → False（archive 据此判失败）。
   调用点均为 SAQ worker 线程，符合 `call_agent_control_sync` 的「非主循环线程」
   前提。移除不再使用的 `asyncio` import。

2. **#1829 REST retry-dispatch 漏传 audit_user_id**
   `POST /plan-runs/{id}/retry-dispatch` 端点补
   `audit_user_id=getattr(current_user, "id", None)`，与同文件 abort 端点及 AI
   路径（#759）对齐——审计行 `plan_dispatch_retry_requested.user_id` 不再恒 NULL，
   #628 的 user_id 精确筛选可查到人工触发记录。

影响面：`backend/services/ai_assistant/plan_run_ops.py`、`backend/api/routes/plan_runs.py`
+ 两个测试文件。

## Alternatives

- #1864 最小方案：给 Future 加 `add_done_callback` 记录异常——只让假成功「留痕」，
  语义仍是提交级；ack 版是「已送达」强口径，代价是每 host 最多等约 5s（归档
  host 数量级可控）。按 issue 建议取舍选彻底版。
- #1864 依赖对方 ack impl 的具体机制；若未来 ack 超时语义变化，只影响返回 True/False
  判定，不影响调用方契约。

  fire-and-forget + 显式失败留痕；当前 host 量级下串行可接受。
