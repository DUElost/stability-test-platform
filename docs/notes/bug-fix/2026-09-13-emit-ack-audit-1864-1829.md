# emit ack 送达口径（#1864；#1829 已由 #1866 落地）

Status: implemented
Class: bug-fix
Issue: https://github.com/DUElost/stability-test-platform/issues/1864

## Decision

`_schedule_emit_agent_control` 原实现用 fire-and-forget 的 `emit_agent_control` +
`run_coroutine_threadsafe`，丢弃返回的 Future——协程体内异常（sio 未初始化/关闭竞态）
静默沉淀，调用方已把 host 记入 `triggered`，emit 层仍可能「假成功」。改为桥接 ack 版
`socketio_server.call_agent_control_sync`：等待 Agent control handler 确认，仅送达才
返回 True；主循环不可用/超时/异常 → False（archive 据此判失败）。调用点均为 SAQ
worker 线程，符合 `call_agent_control_sync` 的「非主循环线程」前提。移除不再使用的
`asyncio` import。

**#1829 overlap**：本 PR 曾一并改 REST `retry-dispatch` 的 `audit_user_id`；该改动已
由 #1866（oid `f2d40773`）合入 main。冲突解决时取 main 实现
（`audit_user_id=current_user.id if current_user else None`，与 abort 端点同口径），
并保留 main 侧测试 `test_retry_dispatch_records_audit_user_id` 与 Agent Note
`2026-09-13-retry-dispatch-audit-user-1829.md`，删除本分支重复测试。

影响面：`backend/services/ai_assistant/plan_run_ops.py` +
`backend/tests/services/test_ai_plan_run_ops.py`（#1864）。#1829 路由/测试以 main 为准。

## Alternatives

- #1864 最小方案：给 Future 加 `add_done_callback` 记录异常——只让假成功「留痕」，
  语义仍是提交级；ack 版是「已送达」强口径，代价是每 host 最多等约 5s（归档 host
  数量级可控）。按 issue 建议取舍选彻底版。
- #1864 依赖对方 ack impl 的具体机制；若未来 ack 超时语义变化，只影响返回 True/False
  判定，不影响调用方契约。
