# 夜间 CI 安全网三处修复：#1547 / #1548 / #1549

Status: implemented
Class: bug-fix

## Decision

三处独立缺陷，同属「夜间/队列安全网」且都在 2026-09-11 的窗口内引入，合并一个
PR 交付（同批：`audit-2026-09-12`）。

1. **#1547 `backend-test` 同库拒载**：`ci.yml` 的 `backend-test` job 把
   `DATABASE_URL` 与 `TEST_DATABASE_URL` 设成同一个容器库，触发
   `backend/tests/conftest.py` 导入期的 `db_url_guard` 「与运行时配置同库」拒绝，
   pytest exit 4；该步失败后同 job 的 agent / 仓库级测试因 `if: success()`
   全部 skipped——**main 的后端测试面整片变暗**。
   修法：job 级**不再提供** `DATABASE_URL`；确实需要它的两处
   （`alembic upgrade head`、agent 测试）改为**步骤级**注入，值同为
   `TEST_DATABASE_URL`。
   - 不选「改成两个库名」：`backend/tests/conftest.py` 明确依赖
     「CI 先 `alembic upgrade head`，测试跑在迁移后的 schema 上」，
     拆库会让测试退化成只看 `create_all` 的 schema，丢一层保真度。
   - 不选 `STP_ALLOW_UNSAFE_TEST_DATABASE_URL=1`：`_allow_unsafe()` 会一并
     关掉「库名必须含 test」的隔离检查，等于废掉护栏。
2. **#1548 backstop 静默失效**：`main-ci-backstop.yml` 用了 `gh api` 不存在的
   `--arg`（`gh api --jq` 只接受一个字符串）。`gh` 报
   `accepts 1 arg(s), received 4`，该步骤在 `set -e` 下中止整个 job：等待、
   分支清理、linked issue 补关三步全 skipped，**且不生成 `ci/backstop-failed`
   兜底单**——09-11 的红灯因此没有任何告警。修法：管道给真正的 `jq`，与同文件
   其它处写法一致。
3. **#1549 队首告警占位符未替换**：`pr-automerge-queue.sh` 把整行（含 `%s`）
   当 `printf` 参数、只把 `'%s\n'` 当格式串，正文输出字面 `%s`；指纹行也变成
   字面 `<!-- queue-blocked-fingerprint: %s -->`，使
   `grep -qF "queue-blocked-fingerprint: ${fingerprint}"` 永不命中，
   「同指纹零写入」的反刷屏去重失效，告警 issue 被每次 reconcile 重写。
   修法：占位符改由 shell 在参数里展开。

## Alternatives

- **只修 #1547 的 CI env、不动另外两单**：三条是同一失效链——`#1548` 让红灯
  静默、`#1547` 是那个红灯、`#1549` 让队列告警本身失真。分开交付会让「修好
  红灯却仍无人知晓」的状态多存在一个窗口。
- **给 CI 加 `STP_ALLOW_UNSAFE_TEST_DATABASE_URL`**：见 Decision 1，否决。
- **在 guard 里豁免 loopback/CI**：AGENTS.md 明确本机可能就是生产控制面与
  数据库宿主，「本地库 = 安全」不成立；护栏不该为 CI 放宽语义。
- **#1549 改用 heredoc**：正文含反引号（需转义 `\``），heredoc 下既要变量展开
  又要转义反引号，比 `printf` 逐行更易写错；否决。

## Verification

- **#1547**（双向）：
  - 新接线：`pytest backend/tests --collect-only -q` → `2288 tests collected`（conftest 导入通过）。
  - 旧接线：同命令复现 CI 原报错
    `db_url_guard.UnsafeTestDatabaseUrl: TEST_DATABASE_URL is identical to DATABASE_URL`。
  - 直调护栏：新接线返回 URL、旧接线 raise。
  - `yaml.safe_load` 解析 `ci.yml`，确认 job env 只剩 `TESTING/JWT_SECRET_KEY/TEST_DATABASE_URL`，
    且两步的步骤级 env 为 `DATABASE_URL: ${{ env.TEST_DATABASE_URL }}`。
- **#1548**（双向）：
  - `python -m pytest tests/test_main_ci_backstop_guards.py -q` → 5 passed。
  - 新增 `test_gh_api_jq_never_receives_jq_options`（扫**全部** workflow，剔除
    注释行后断言 `--jq` 后不跟 jq 选项）。
  - 新增 `test_redispatch_poll_filter_functionally_excludes_preexisting_runs`
    ——把过滤器真跑一遍（`jq` 可用时；否则 skip）：`pre="111"` → `222`，
    `pre="111 222"` → `0`。
  - 反向验证：把该处还原成 `--jq --arg`，两条新测试同时失败。
- **#1549**（双向）：
  - `bash -n scripts/ci/pr-automerge-queue.sh` 通过。
  - `python -m pytest tests/test_automerge_queue_alerts.py -q` → 7 passed。
  - 新增 `test_alert_body_renders_placeholders_and_self_dedups`：假 `gh` 另存
    argv JSON（正文含换行，空格拼接的旧日志无法还原单参数），断言脚本**实际
    写出**的 body 不含 `%s`、指纹注释与真实指纹逐字一致，并做回环——把该
    body 当作存量 issue 正文喂回去必须零写入。
  - 反向验证：还原坏 `printf`，新测试失败。
- `python scripts/run_gates.py check:quick`（见 PR 描述的实际输出）。

## Revisit

- `pr-agent-tests` 与 `pr-migrate-empty-db` 仍把两个变量写成同一个串。它们
  今天不受影响（都不加载 `backend/tests/conftest.py`：前者只跑
  `backend/agent/tests/` 与两个纯离线 lock 测试，后者只跑 alembic +
  `check_schema_sync`）。若将来有测试把它们接到该 conftest 上，会以同形态再炸
  ——届时按 #1547 的步骤级注入模式处理。
- `#1548` 的根治是给 workflow 加 actionlint/shellcheck 门禁：本轮只补了
  「`--jq` 后不得跟 jq 选项」这一条静态断言（该类错误的唯一已知形态）。
  若再出现其它 shell 语法类 workflow 缺陷，应升格为真 linter 而非继续加正则。
