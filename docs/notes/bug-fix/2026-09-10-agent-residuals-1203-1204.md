### #1203 — release 占位清理按 device 归属收敛

`JobRunnerState.release`（#1006 引入）用
`active_job_tokens.get(job_id) in (None, worker_token)` 判 current 后
`active_device_ids.discard(device_id)`。None 分支把两种态混为一谈：
「本 job 残留占位待清」（#1006 合法路径：恢复动作清了 renewer 映射、
deregister 取不到 device 未清占位）与「权威清理已清占位、继任 job 已重占
同设备」（lease-lost/正常退出后 claim 环已把设备派给新 job）。后者迟到
release 会清掉继任占位 → 同设备第三次并发派发窗口。

修复：main 侧新增与 `_active_device_ids` 同锁同步的 `_active_device_owner`
（device_id → job_id），注册/摘除点（claim 预占、`_register_active_job`、
`_cleanup_after_lease_lost`/`_cleanup_after_job_exit`/`_rollback_failed_claim`）
全部维护；`release` 仅当该设备当前归属本 job（或无归属）才 discard+pop——
归属已转其他 job 时不动。`JobRunnerState.active_device_owner` 可选
（默认 None = 旧启发式，fixture/直调测试语义不变）；三个 main 清理 helper
的 owner 参数同设为可选。

### #1204 — DLE register outbox 死信 + 队首饿死

`dle_register_outbox`（#1042）持续失败的 create 意图只累加 attempts 永不下台；
`get_pending_dle_registers` 按 `created_at ASC LIMIT 20` 取数，20 条永久
4xx（403 host 不符/422 升级漂移/FK 违约）意图会永久占满窗口、饿死后续可恢复
意图——与 log_signal/step_trace outbox 的 dead-letter 机制不一致。

修复（对齐既有模式）：
1. 表增 `dead_letter INTEGER NOT NULL DEFAULT 0`，`_ensure_dle_register_outbox_schema`
   幂等 ALTER 兼容已部署 agent（同 log_signal 套路）；
2. `get_pending_dle_registers` 过滤 `dead_letter = 0`；
3. `drain_register_outbox` 达 `_MAX_REGISTER_ATTEMPTS=10`（对齐
   watcher/emitter）转死信并告警；
4. `replay_dle_register_dead_letter` + main control 命令（与 log_signal 对称）
   供中心升级/漂移窗口过后手动回放；
5. `enqueue` 的 ON CONFLICT 重置 `attempts/dead_letter`（新 create 意图语义）。

## Alternatives

- **#1203 在 release 用「job 仍在 active_job_ids」作 None 分支守卫**：不可行——
  #1006 合法路径里 deregister（release 首步）已先摘 ids/token，None 分支评估时
  job 已不在 active_job_ids（既有测试即此形态）；无法区分「已清+继任重占」。
- **#1204 死信行加到期自动重置**：更自愈但需额外定时器；沿用 log_signal 的
  「死信保留 + 手动 replay + 周期巡检由运维触发」最小一致面，重试窗口=10×30s
  drain 周期（约 5 分钟中心故障内不误伤）。
