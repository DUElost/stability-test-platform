# R13 助手 P1 权限/原子性/凭据收口（#1213 #1214 #1215 #1216 #1217）

Status: implemented
Class: bug-fix

## Decision

R13（平台 AI 助手审查）五张 P1 一次收口：

1. **#1213 停用账号仍可执行既有已批准动作**
   `user_may_invoke_tool` 补 `is_active != "Y" → 拒绝`（与 REST 登录/会话同
   口径）。三个调用点（提案、执行前复核、轮次内工具裁剪）与用户会话校验共用
   同一函数，因此停用即全线拒绝；执行前 `execute_action` 会重新加载发起人。

2. **#1214 通知失败把 Webhook 凭据送进 LLM 上下文**
   - 新增中性 `backend/core/redaction.py::redact_secrets`：脱敏 URL userinfo 与
     敏感 query（access_token/token/secret/sign/signature/…）及 Authorization 头。
   - `notification_service` 用 `_raise_for_delivery_error` 取代
     `resp.raise_for_status()`：失败只留 `HTTP <status> <reason>`，不带 URL；
     reason 也过 redact。
   - `orchestrator` 在 `_finalize_action`（result_summary + tool 回执）、
     service 工具异常摘要、`_history_as_llm_messages` 的 tool/回执内容统一
     redact——纵深防御，避免任何路径把凭据写进模型上下文。

3. **#1215 审批/执行缺原子状态转换，可重复执行**
   新增 `backend/services/ai_assistant/actions.py::try_transition_action`：单条
   条件 UPDATE（`WHERE status=expected`）+ rowcount 判定。
   - 审批：`proposed → approved/rejected` 原子抢占，并发批准仅一人成功（另一人
     409）；审计只在胜者路径写。
   - 执行：`approved → running` 原子抢占，双执行仅一次副作用。

4. **#1216 enqueue 安排入队当成功，可永久丢轮次**
   - `saq_worker.enqueue_sync`：`_do_enqueue` 透传 SAQ `Queue.enqueue` 返回值；
     `required=True` 分支返回 `job_ref is not None`——同 key 去重（None）不再
     伪报成功。
   - `orchestrator._enqueue_continuation` 改用 `required=True` 并区分三态：真实
     投递→正常；去重→有界重试（3×0.5s）后仍失败则占位收敛为 failed；入队异常
     →立即收敛 failed（可重试），绝不留悬挂 pending。

5. **#1217 普通用户 T2 提案无管理员审批入口**
   - 后端 `GET /api/v1/ai-assistant/actions/pending`（admin）：跨会话列出
     `proposed` 动作，仅返回摘要（tool_name/preview_text/requested_by/created_at，
     不含 params、不拉会话消息）。
   - 前端新增 `AssistantApprovalsPage`（`/assistant/approvals`，AdminRoute 内）+
     助手页 admin 入口；approve/reject 复用现有端点。

影响面：`backend/core/redaction.py`（新）、`backend/services/ai_assistant/`
（authz/actions/orchestrator）、`backend/services/notification_service.py`、
`backend/tasks/saq_worker.py`、`backend/api/{routes,schemas}/ai_assistant.py`、
`frontend/src/pages/assistant/`、`frontend/src/{router,utils/api}`。

## Alternatives

- #1214：只截断字符串长度（现状）无法阻止凭据入上下文；只在通知层兜底又漏掉
  其他外部异常。选择「源头结构化 + 助手边界统一 redact」双层。
- #1215：应用层锁（进程内）不跨 worker，与服务型工具多 worker 部署不符；DB
  条件更新是唯一跨进程成立的抢占原语。
- #1216：把 `enqueue_sync` 默认改成 `required=True` 会改变 recycler/reaper 等
  补偿路径的「失败不阻塞」语义；只在续轮这一处要求真实投递，保留默认 best-effort。
- #1217：开放管理员读他人会话来嵌卡片会破坏会话隐私；新增独立摘要队列页。

## Revisit

- #1213：T0 查询路径现已随 `user_may_invoke_tool` 复核；若未来引入更细 RBAC，
  保持「执行面复核账号有效性」不变量。
- #1216：去重补偿为有界重试；若 SAQ 长期同 key 占用，仍会收敛 failed 让用户
  重试而非自动续跑——真正的「续轮意图持久化」需模型/表结构支持，留观察。
- #1217：审批页当前按需拉取，未做推送/角标；出现「管理员数量大、审批频繁」需求
  时再加通知。
