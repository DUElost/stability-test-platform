# R15 CI/devx/testing 守卫收口（#1293 #1294 #1295 #1296 #1297 #1298）

Status: implemented
Class: bug-fix

## Decision

R15（测试、CI 与工程治理）六项一次收口。均为「门禁/守卫以为在拦、实际漏检或
越界」类缺陷：

1. **#1293 自动审批脚本分支过滤无效**
   `approve-pending-workflow-runs.sh` 查询改用 REST 实际支持的 `branch=`
   （原 `head_branch=` 被忽略，返回全仓运行）。审批前逐条核对返回对象的
   `head_branch == 目标分支` 且 `head_repository.full_name == 本仓`（排除 fork），
   并复用 `is_excluded_ref`——入口过滤之外补审批对象过滤。

2. **#1294 夜间清理可能删除复用分支的未合入提交**
   `main-ci-backstop` 删除远端分支前，先用 `compare/main...<branch>` 证明当前
   tip 已包含在 main 中（`status ∈ {behind, identical}`），再重读 tip SHA，若在
   检查与删除间被并发推送则跳过。无法证明即不删。

3. **#1295 直接运行 Agent 测试仍可读生产配置**
   `backend/agent/tests/conftest.py` 在导入任何 `backend.agent.*` 之前
   `setdefault` 一个明确的本地隔离 `DATABASE_URL`，阻断模块级
   `resolve_database_url()` 回落到仓库根 `.env.backend`。新增
   `test_env_isolation.py` 钉住「生效 URL ≠ 生产 .env.backend」。

4. **#1296 表名单数门禁检查了不存在的目录**
   `check_invariant_diff.py` 的 `plural-table-name` 规则路径由
   `backend/migrations/` 修正为 `backend/alembic/versions/`，自测样例同步改用
   真实目录——此前真实迁移匹配数为 0，门禁形同虚设。

5. **#1297 依赖锁门禁漏检被包含清单的版本变化**
   `requirements_digest.compute` 递归展开 `-r/--requirement` 包含清单后再摘要，
   include 路径也入摘要（缺失/循环安全）。只改 `requirements.txt` 版本而不更新
   dev lock 现在会失败。运行时 lock（无 include）摘要不变，已重新 stamp dev lock。

6. **#1298 夜间重派 CI 后可能认领旧失败运行**
   dispatch 前快照已存在 run id；轮询只接受不在快照内的 `workflow_dispatch` 运行，
   并按 `branch=main` 解析（容忍 main 前进），不再取「同 SHA 第一条」。

影响面：`scripts/ci/approve-pending-workflow-runs.sh`、`.github/workflows/main-ci-backstop.yml`、
`backend/agent/tests/conftest.py`（+新测试）、`tools/dev/check_invariant_diff.py`、
`tools/dev/requirements_digest.py`、`backend/requirements-dev.lock`（digest restamp）、
`tests/`（新增 approve/backstop 守卫测试，扩展 dev lock 测试）。

## Alternatives

- #1293：仅信任查询参数——API 参数曾被证无效；审批对象核对是必要第二道。
- #1294：`DELETE` refs API 不支持条件 SHA，无法完全消除 TOCTOU；采用「compare
  后再重读 tip」把窗口压到最小，残留窗口在 Agent Note Revisit 记录。
- #1295：只在 CI/run_gates 注入——保护不到文档推荐的直接 `python -m pytest`；
  在 scoped conftest 建立边界才是所有入口共享的。
- #1297：只校验 dev lock 满足运行时「版本约束」需解析 PEP 440，复杂且易漏；
  递归摘要更简单、更严（任何被包含内容变化都触发重生）。

## Verification

- `tests/test_approve_pending_workflow_runs.py`（假 gh）：查询用 `branch=`；
  仅同仓同分支 run 被审批，跨分支/fork 跳过；排除分支短路。
- `tests/test_main_ci_backstop_guards.py`：重派轮询排除 pre-existing run；
  删除分支前有 `compare/main...` 祖先判定 + tip 重读守卫且在 DELETE 之前。
- `tests/test_requirements_dev_lock.py`：递归包含版本变化改变 dev 摘要；
  缺失/循环包含安全；`--check` 两份 lock 均通过（dev lock 已 restamp）。
- `backend/agent/tests/`（`env -u DATABASE_URL`）→ **1542 passed**；
  `test_env_isolation.py` 护栏。
- `tools/dev/check_invariant_diff.py --self-test` 通过（真实 alembic 路径红绿）。
- 工作流各 `run` 块 `bash -n` 通过；`ruff check` 变更文件通过。

## Revisit

- #1294：`DELETE git/refs` 无条件写，检查与删除间仍存在极小推送窗口（已重读 tip
  缩小）；若需彻底原子，可改为 `PATCH git/refs` 的 force+sha 语义或服务端保护。
- #1298：以 `branch=main` 解析新 run，容忍 main 前进；若同分支同时存在多个人工
  重派，仍以「最新未在快照内」为准，正常情况下唯一。
