# 治理面 S14：代码注释里的 ADR 版本引用门禁

Status: implemented
Class: bug-fix

## Decision

在 `tools/dev/check_governance_surface.py` 增 **S14**：扫描 `backend/` 与 `frontend/src`
的源码，凡注释里写「ADR-XXXX … vX.Y」且该 ADR 头部带**规范位**版本者，版本必须与
头部一致，否则 BLOCK。判据与取值面刻意收窄：

- **权威版本只认 ADR 头部规范位版本**（与 S12 同判据）。头部不带版本者不约束——
  ADR-0029/0030/0036/0038/0042 因此不受影响，规则面对分支基线零红灯；CI 首次
  运行即命中 main 上 4 处真漂移（ADR-0032 v0.8 凭空引用，见 #2192）。
- **只绑 ADR 号后第一个 `vX.Y`**：「v1.0 → v1.1 沿革」这类叙述里的第二个 token
  不误绑到该 ADR，避免历史叙述被判违规。
- **排除 `backend/agent/scripts/`**：已发布脚本版本目录内容冻结（ADR-0020 +
  硬不变量，改它即触发 immutability 门禁）。扫进去一旦红灯，就是「必须改、又
  不许改」的死结。
- **收集（IO）与判定（纯函数）分离**：`collect_adr_code_refs` 只做扫描，
  `check_adr_code_refs` 是纯函数，判定面进 `--self-test` 红绿双向自证——CI 的
  治理面 step 同跑 `--self-test` 与 `--check`，检查器自身回归即红灯。

起因是 #2154 的实测教训：ADR-0043 升 v1.1 后同步注释时漏改一处（同文件另两处
已是 v1.1），全靠人肉 grep 才发现。S12 覆盖索引面、覆盖不到注释面，于是
「bump 版本必须同步注释」只剩自觉——这次把它变成门禁。

## Alternatives

- **A. 不加规则，只在 PR/Agent Note 里写「记得同步」**：否决。#2154 已证明不够——
  我在 #2173 里做过精确串批量替换，仍因一处后跟 `；` 而非 `）` 漏网。
- **B. 连 `docs/` 一起扫**：否决。`docs/notes/` 下的 bug-fix 记录是**史实快照**，
  里面写「ADR-0043（Accepted v1.0）D3 的…」描述的是当时的正确状态；纳入会逼人
  改写历史，且淹没有效信号。
- **C. 用版本记录块末项（record_tip）当权威版本**：否决。record_tip 是启发式解析
  （S12 注释自陈：单行罗列形态下行尾污染无法机械区分），拿它做阻塞判据误报风险
  高，且与 S12「只认头部规范位」的既有口径不一致。
- **D. 做成独立脚本 + 独立 gate**：否决。gov-surface 已持有 ADR 版本一致性（S12）
  与 CI 锚点，复用同一步骤零新增 CI 成本；独立 gate 还要再登记
  `GATE_TO_CI_ANCHOR` 并新增 CI step。
- **E. 顺手给 ADR-0029/0030 头部补版本以扩大覆盖**：否决，超出本次范围
  （且会连带触发 S12 的主表/DOC-MAP/M7 同步义务）。记入 Revisit。

## Verification

- **CI 首次运行即 4 处红灯**（合入最新 main 后本地同样可复现）：ADR-0032 头部
  v0.7，代码注释却写「ADR-0032 v0.8 裁决 2026-09-15」（引入方 `d025affd`，#1071
  那批）  ——注释引用了一个 ADR 尚不存在的版本。按「不伪造归属」原则去掉版本 token
  （保留 ADR 号与裁决日期；该措辞由并行 Execution 的 `de3a2926` 先落地，本分支
  合并采用），复跑全绿；ADR-0032 是否落地 v0.8 转 #2192 裁决，落地后须把 4 处
  回填成 `v0.8`。

- `--self-test`：15 条规则红绿样例全过；S14 新增 5 条——一致绿、版本落后红、
  头部无版本不约束绿、只绑首个 token、无版本 token 不判定。
- `--check` 全绿（S1–S14、S5x）；新增全仓扫描后整脚本耗时 0.132s。
- 收集面：66 处引用（摸底 72 减去冻结目录 6），冻结目录残留 0。
- 端到端红验证：在 `/tmp` 造最小假仓库（未动工作区）跑完整「收集 + 判定」链路——
  落后引用报 S14、一致引用放行、冻结目录文件未被收集。
- **未跑**：完整测试套件（改动为 dev 工具脚本 + docs note，无业务行为变化；由 CI
  required checks 复核）。

## Revisit

- **首个真实命中（#2192）**：注释版本**高于**头部（凭空引用）与**低于**头部
  （落后）归责方不同——落后改注释即可，领先必须落地 ADR。规则两个方向都拦，正是
  为了逼出二者之一；ADR-0032 v0.8 落地后需把 4 处注释回填成 `v0.8`。
- **覆盖缺口**：ADR-0029/0030/0036/0038/0042 头部不带规范位版本 → 代码注释里
  64 处版本引用无门禁覆盖（其中 6 处在冻结脚本目录，永远无法修，只能随新脚本
  版本淘汰）。真要覆盖，得先给这些 ADR 头部补版本（S12 会顺带要求主表/DOC-MAP/
  M7 同步）——独立议题，不混在本条里做。
- **误报面**：注释若刻意引用旧版本（「v1.0 时曾…」）会被拦。当前无此写法；真
  出现时应改写措辞，而不是给规则加豁免。
- **形态覆盖**：正则要求 ADR 号与 `vX.Y` 之间不含数字（中间夹 issue 号 `#2154`
  则漏检）。漏检只是少拦一次，误报会逼人加豁免——取严格面。
- **范围**：前端只扫 `frontend/src`，`dist`/`build`/`node_modules` 已排除；测试文件
  （`backend/tests/`）一并纳入，那里的注释同属维护面。
