# #2057 ADR-0040 落地遗留：重复身份、precheck 记账、收敛与 VERSION 的口径

Status: implemented
Class: bug-fix

## Decision

**1. 删除未接线、且与 D1 身份分叉的第二份实现**

`backend/services/deployment_digest.py` + `backend/agent/deployment_digest.py`（#1911 切片）
自称 ADR-0040 D1 身份，但：

- 序列化与已接线的实现不同（`\x00` 连接 vs `artifact_digest` 的 JSON 形式）；
- 输入集不同（`_iter_included()` 会整树剪掉 `resources/`，而部署输入集只排 `resources/mtbf/`）；
- **全仓无生产消费方**——唯一引用是它自己的等价性测试（`git grep` 全仓确认）。

一旦 P2 接线它，算出的值永远匹配不上部署路径写入的 digest → no-op gate 要么恒 miss
（全量重下发）、要么假 no-op。ADR-0040 的 D1 身份实现应当只有一份：`backend/services/artifact_digest.py`
+ 其 Agent 镜像 `backend/agent/artifact_digest.py`（已有 `test_mirror_parity_both_kinds` 守护，
`backend/tests/services/test_artifact_digest.py`）。

决定：**删除三处**（控制面实现、Agent 镜像、其测试），直到 P2 真正需要分层身份时再按同一算法
单点扩展；`docs/notes/feature/2026-09-14-deployment-digest-mirror-1911.md` 作为历史记录保留
（本 Note 记其被取代）。

**2. precheck 治愈通道补 `code_version`**

`backend/services/precheck/sync.py` 调 `execute_hot_update` 与
`finalize_hot_update_outcome` 时都不传 `code_version`（默认空串）→
`record_agent_code_deployed` 对空 revision 提前返回（`agent_version_info.py:67-69`）、
远端 `VERSION` 也不重写（`host_updater.py:239-246` 的 `if [ -n "$CODE_VERSION" ]`）。
后果：这台**真正被修复**的主机永远停在上一次部署的 revision，UI 的 deployed_at 语义不达
（该 Note 的 D5 宣称三条入口共享同一套记账）。
改为两处都传 `code_version=get_agent_code_version()`（从 `host_updater` 导入）。

**3. 收敛（no-op）与 `VERSION` 的口径：暴露事实，不改语义**

`VERSION` 不进内容身份（ADR-0040 D1），所以「digest 相等」**不等于**「主机 revision 与期望一致」：
任何不动 `backend/agent/**` 的提交都会让 `expected_code_revision` 前移 → 主机侧长期显示
drift，而热更新通道判 no-op（只有 `?force=true` 能"清"）。
决定：**不改收敛语义**（「把 VERSION 纳入收敛判据」会让每次后端提交都触发全量重下发，
代价远大于收益；「让 VERSION 只记 agent payload 的 revision」是改 ADR-0040 的 D1 口径，
须先裁决），改为把事实回传：no-op 响应新增 `code_revision_stale`，并在命中时打一条
`hot_update_noop_code_revision_stale` WARNING（含 reported/expected），使运维能解释
「为什么徽标是 drift 而主按钮说已收敛」。

## Alternatives

- **保留 `deployment_digest` 并把它改成薄适配**：控制面侧可行，但 Agent 镜像无法 import 控制面
  实现 → 只能再复制一份，等于把「两份身份」的隐患换个位置；删除更干净。
- **把 VERSION 纳入收敛判据**：见上，代价是每次后端提交触发全量下发。
- **让 `get_agent_code_version()` 返回「最后触碰 agent 目录的提交」**：语义上最贴近直觉，
  但改动 ADR-0040 D1/D2 的既定口径（VERSION 记什么），须走 ADR 追补裁决——列入 Revisit。

## Revisit

- **VERSION 语义（需 ADR-0040 追补裁决）**：当前 `VERSION` = 仓库 HEAD，而收敛除它之外全部
  已对齐 → 主机侧 drift 徽标会随任意后端提交出现。三个候选：(a) 维持现状 + 本 PR 的可观测性；
  (b) `VERSION` 记「最后触碰 `backend/agent/**` 的提交」；(c) VERSION 纳入收敛判据并接受
  重下发代价。选 (b)/(c) 均改变 D1/D2 口径，须先裁决再改。
- **P2 分层身份若回流**：应按 `artifact_digest` 的算法与输入集**扩展参数**（kind 分层），
  而不是新起一个模块——本 PR 删除的正是后者的前车之鉴。
