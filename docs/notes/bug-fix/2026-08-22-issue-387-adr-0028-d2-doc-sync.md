# ADR-0028 D2 FAILED 门禁机制文档对齐（issue #387）

Status: implemented
Class: bug-fix

ADR-0028 D2 与关联文档仍把「FAILED PlanRun 不执行 merge/extract」描述为
靠 scan xls 不足自然阻断，且常量引用过期；实现自 2026-08-13（#258/#259）
起是显式门禁。本 note 随对齐 PR 附带。

## Decision

- ADR-0028 D2 的门禁 bullet 改写为实际三层机制：路由层 409（`trigger_merge`
  / `trigger_extract`，先于 merge precheck）、SAQ 层 `run_merge_sync` 显式
  跳过（`merge_skip_failed_plan_run`）、extract 在 SAQ 链靠 merge 无产物
  短路（`-1`），显式拒绝仅在路由层。
- 常量引用 `_AUTO_STATUSES`（`dedup_scan.py:471`）改为 `_DEDUP_AUTO_STATUSES`
  + 函数锚点 `should_trigger_dedup`，**不再写行号**——行号会再次过期。
- `06-realtime` §9 五触发表第 2/3 行补「手动 merge/extract API 对 FAILED
  返回 409」。
- `dedup_scan.py` `should_trigger_dedup` docstring 同步（原「自然跳过」与
  同文件 `run_merge_sync` 的显式门禁自相矛盾）。
- ADR L205 的 `_AUTO_STATUSES` 是 commit `bce5177` 的历史实施记录（当时
  常量确实叫这个名），不改写历史记录。

## Alternatives

- 把 409 契约只写进 ADR、不动 `06-realtime`——放弃：五触发表是前端/调用方
  查 API 行为的入口，缺 409 会让人以为手动触发只会"静默跳过"。
- 保留行号引用只更新数字——放弃：471→587 下次重构又过期，函数锚点更稳。

## Verification

- 事实核对（main @ c391ea0）：`backend/api/routes/dedup.py:473-476`（merge
  409）、`:523-526`（extract 409）、`backend/services/dedup_scan.py:587`
  （`_DEDUP_AUTO_STATUSES`）、`run_merge_sync` FAILED 分支。
- `ruff check backend/services/dedup_scan.py` + `python -m py_compile`。
- 既有 409 路由测试：`backend/tests/api/test_dedup_scan_endpoints.py`
  （#259 引入，未改动，行为无变化——本 PR 仅文档与 docstring）。

## Revisit

- 若 extract 在 SAQ 链获得独立显式门禁，或 409 语义（状态码/detail）变更，
  需同步本 PR 涉及的三处。
