## Decision

1. **#1820 `unisoc_reconciler`**：用远端 `ls` 回显退出码区分「root 不存在
   （rc≠0，权威空列表）」与「传输层失败（`shell_fn` 返回 None，整拍未知）」。
   此前持久缺失的 root 恒 rc≠0 → 整拍视为未知 → `_last_listed` 恒 None →
   `_prune_processed` 永不执行，#767 的线性膨胀收敛对这类设备不成立。
   **合入冲突裁决（相对 #1879）**：#1879 已先合入同语义实现，采用
   `echo __STP_RC__:$?` + `_list_remote_uniview_root` 抽取；本 PR 初版 marker
   为 `__STP_LS_RC__=`（内联解析）。行为等价，保留 main/#1879 形态以免双
   marker；本 PR 另保留「两 root 均缺失」与「rc 标记缺失保守挂起」补强测例。
2. **#1862 `reconciler._handle_new_entry`**：本前缀意图簿未命中时回查另一
   前缀（baseline↔runtime）簿中同 line 的 **done 墓碑**，复用其
   keys/seq_no 写入本前缀簿后幂等返回——堵住「baseline 落 processed→emit
   done→崩溃于 merge 前 → runtime 重拉以新 seq_no 重复 emit」窗口（反方向
   runtime→baseline 同理）。未 done 的跨前缀占位不复用（keys 尚未分配，
   复用无法稳定幂等键）。
   **该回查在合入后于生产路径上不可达**（#2034）：processor 总在
   `on_new_entry` 之前把占位落进**同一个**前缀簿，`record is None` 因此永不成立；
   且 `tick_once` 先 sweep 后拉取会抹掉 baseline 墓碑。两条成因的修复见 [`2026-09-15-aee-intent-finalize-and-tombstone-2034-2044`](2026-09-15-aee-intent-finalize-and-tombstone-2034-2044.md)，本条机制本身仍是正确设计。

## Alternatives

- #1820 先 `ls -1d {root}` 探测再列表——否：多一次 adb 往返；rc 回显一次
  拿到结果与判据。
- #1820 把 rc≠0 当作传输失败沿用旧行为——否：即本缺陷本体（root 持久
  缺失 = 永不收敛）。
- #1820 冲突时改回本 PR 的 `__STP_LS_RC__=` marker——否：与已合入 #1879
  双轨，无行为收益。
- #1862 复用跨前缀**任意**记录（含未分配 keys 的占位）——否：占位无
  keys，两侧各自分配仍会双 seq_no；done 墓碑才有稳定幂等键。未 done 的
  跨前缀窗口留 Revisit。
- #1862 改单簿共享命名空间——否：job 级 baseline 隔离是 #1719 的有意
  设计（#1028 同型语义），动命名空间影响面大。
