# 中心存储挂载源保留 IPv6 方括号 + hard mount 语义落杆（#2321）

Status: implemented
Class: bug-fix

## Decision

**① 派生 NFS 服务端主机时保留 IPv6 方括号。**
`agent_installer` 从站点公开入口派生挂载源主机，此前用 `urlsplit(api_url).hostname`——
stdlib 会**剥掉** IPv6 字面量的方括号（`netloc` 保留、`hostname` 不保留），而 NFS 源语法
要求 `[addr]:/path`：拼出 `2001:db8::1:/srv/stp-aee` 是冒号歧义 → 挂载必然失败，且现象与
「网络真的不通」不可区分（S5 报 `install.s5.storage` FAIL、Agent 退到本机根）。

新增 `nfs_server_from_api_url()`：`hostname` 里含 `:` 且未带括号时补回 `[...]`。
消费点（`install_agent.yml` 的即时 `mount` 与 fstab 行）共用同一个变量，一处修即两处生效。

**② hard mount 语义落杆（issue 的「请裁决并落一条」）。**
`install_agent.yml` 的挂载没有 `soft/timeo/retrans`，即默认 **hard**：控制面分享断线时，
触碰 `STP_AEE_NFS_ROOT` 的 Agent 线程进入**不可中断睡眠**（该路径是 AEE reconciler /
事件上传 / dedup 的落点），`nofail,_netdev` 只解决开机顺序、不解决运行期断线。
**裁决：维持 hard**，理由与复议触发写进
[`docs/design/2026-storage-roles-and-aliases.md`](../../design/2026-storage-roles-and-aliases.md)
§4.4（durable 落点，不再只存在于代码里）：
站点内网同机房、可用性由 NFS 侧保证；改 soft 会把断线变成 `EIO`，而 Agent 侧对 `EIO`
的处理路径**未经验证**——改成 soft 之前必须先有那条链的验证。复议触发：出现「NFS 侧
非计划断线导致 Agent 线程挂死」的现场实例。

## Alternatives

- **A. 用 `netloc` 剥端口后直接用**：等价可行（`normalize_install_api_url` 已拒 userinfo），
  但「重拼 `[...]`」把意图写在函数名与 docstring 里，读代码即可见「为什么不能直接用
  hostname」——取本方案。
- **B. 在 playbook 侧补方括号**：否决。语法知识应留在**派生源**（控制面），放进消费点会让
  下一条消费路径（fstab、未来的挂载探针）各自再补一次。
- **C. 顺手改 `soft,timeo=…,retrans=…`**：否决（本单只记录裁决）。soft 的代价是把断线
  从「挂死」换成「`EIO` 传播」，而 Agent 侧对 `EIO` 的处理**没有验证过**——先改会引入
  一类新的未验证故障面。已把「复议触发」写进设计文档，留待有现场证据时再议。

- **红绿双向**：还原 `agent_installer.py` 后新用例
  `test_prepare_install_agent_keeps_ipv6_brackets_for_the_share_source` 红（`cmd` 里出现
  `agent_nfs_server=2001:db8::1`——方括号被剥掉）；改后绿。

  `https://stp.example.invalid → 'stp.example.invalid'`；`https://[2001:db8::1] → '[2001:db8::1]'`
  （IPv4 / 主机名 / 带端口 / 不带端口四种形态都不回归）。

  `gov-surface --check` 全绿（文档链接面）。
- **未跑**：真机 IPv6 站点安装（无 IPv6 站点环境）——本单为派生字符串修复，交 CI 与现场。

## Revisit

- **IPv6 站点的真实安装验证**：本机没有 IPv6 站点可试；若首次 IPv6 站点安装仍失败，按
  「`mount` 报错原文 + 派生出的 `agent_nfs_server` 值」两行定位（派生的形态已由用例钉住）。
- **hard mount 的复议触发**（已写入设计文档 §4.4）：出现「NFS 侧非计划断线导致 Agent 线程
  挂死」的现场实例时，重新权衡 `soft,timeo=…,retrans=…`；届时必须先给出 Agent 侧 `EIO`
  处理的验证结果，否则只是把一类故障换成另一类。
- **挂载源的其它派生点**：本次只改了 `agent_installer`。若将来出现第二处「从 URL 派生主机
  拼 NFS 源」的代码，应复用 `nfs_server_from_api_url`（函数名即契约）。
