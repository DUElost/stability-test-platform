# audit-20260913-3 misc 批：死代码删除 / /health 探测 / 快照清理 / TTL 口径（#1928 #1930 #1931 #1923）

Status: implemented
Class: bug-fix

来源：2026-09-13 第三轮变更审计 8 个 OPEN 单的剩余四项（backend 三项 +
agent 文档口径一项；另四项见同日 PR #1952）。

## Decision

1. **#1928 删除 `_record_host_abort_request`**：该函数写
   `run_context['abort_requested_hosts']` 并声称「由 reaper 按 host 消费」，
   但全仓无调用方无消费者（reaper 只读 run 级 `abort_requested` 存在性）。
   按最小面移除孤儿数据结构，原地留注释指路（按 host 独立 grace 须先
   ADR 裁决消费语义）；同时在 run 级写入处补「重置 `at`/`deadline_at`
   是现行为」的复核注记（每次 host 级 abort 最多延长 host 数 × GRACE）。
2. **#1930 `/health` schema 探测重构**：探测只在需要判定的环境执行
   （`skip_schema_check` 时跳过 `alembic_version` 查询）——未迁移的
   dev/测试库不再因此 503；探测异常（表缺失/多 head/alembic.ini 缺失）
   返回显式 `SCHEMA_PROBE_FAILED`（带异常日志），不再落宽泛 except 误报
   `DB_UNAVAILABLE "database disconnected"`；payload 的 revisions 仅在
   真实探测成功时报告（skip 路径 `None == None` 不再误判 at-head）。
   连通性仍由同连接先行的 `SELECT 1` 判定，`DB_UNAVAILABLE` 语义收窄回
   「数据库真的连不上」。
3. **#1931 RunConsole spawn 失败清快照**：RUNNING 快照发布在 `Popen` 之前
   而 spawn 失败路径无 reader 线程（`_finalize` 永不执行）——显式
   `delete_status_snapshot`，其他实例的 `status()` 不再在 TTL 窗口内读到
   RUNNING 假状态（清理失败仅告警，不掩盖主错误）。
4. **#1923 streak 口径修正（注释级）**：`_LEASE_VERIFY_OUTAGE_ABORT_STREAK`
   的「≈15 分钟」名义窗口注明**实际受租约 TTL 封顶**（后端默认 600s，
   extend 不复活过期租约 → 有效容忍 ≈ min(15min, ~10min)）；调大 TTL 或
   宽限复活指向 #1923 的 ADR 裁决路径。纯注释，不改行为。

## Alternatives

- #1928 接线 reaper 按 host 消费——否：#1880 的实测缺陷（run 级写扩散）
  已由 run 级 merge 修掉，host 级独立 grace 是新增语义，须 ADR 先行；
  留死函数与误导文档比删除更糟。
- #1930 对「表缺失」特判返回 200——否：生产类环境探测失败必须 fail-closed
  （systemd 硬门禁同口径）；非生产 skip 已足够。
- #1931 改为先 Popen 后发布快照——否：快照先行是 P2 的可见性设计
  （注册即跨实例可见），失败路径清理比倒置发布顺序侵入更小。
- #1923 调参对齐（streak=2）——否：治标且恶化真中断容忍；口径如实 +
  ADR 裁决路径才是终态。
