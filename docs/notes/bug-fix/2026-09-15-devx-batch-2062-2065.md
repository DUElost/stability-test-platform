# devx 批（#2062 / #2065）：memory-lint 可用性、门禁与测试质量

Status: implemented
Class: bug-fix

## Decision

### #2065 memory-lint 在实际在用的目录上失效

三处改动（`tools/dev/memory_lint.py`）：

1. **`path:line` 误报**：断链判定前剥掉位置后缀（`:NNN` / `:NNN-MMM` / `#LNN`）。
   AGENTS.md 推荐的引用形式正是 `file_path:line_number`——实测当时该 store 的 288 个
   error 里 **181 个**属此类误报，真信号被淹没（工具因此闲置）。
2. **brace glob**：`{,aee/}` 这类无法判定的写法纳入占位符跳过集（`{`/`}`）。
3. **默认目标错位**：新增 `memory_dir_candidates()` / `resolve_memory_dir()`——按 harness
   逐个探测（CodeBuddy `~/.codebuddy/projects/<path-slug>/memory`、ZCode
   `~/.zcode/cli/memories/projects/<project-id>/memory`），**一个都不存在时显式报错并退出 2**
   （列出候选），不再静默指向另一个 store；命中时打印 `harness=`。
   目录约定表落进 `memory_lint.py` 的模块 docstring（代码 = 单点权威），
   `harness-adapters.md` 只加**指针**——该文件原本正好 100 行（S6 预算上限），任何新增行
   都会破门禁，故把指针并入既有段落同一行。

同步维护动作：把在用 ZCode store 的 `MEMORY.md` 两条超 150 字符的索引行压回预算内
（细节已在各自记忆文件里）。

### #2065 残留（同日补修：位置后缀列表 + 多命中不静默）

#2103 合入后复扫实际在用的 store，仍有 22 条 `path:line` 误报未被消除，且默认目标在
**多个 store 同时在用**时静默取第一个。两处都在 #2065 的原始要求内（「建议含 `#LNN`」
「多个命中或不命中时显式报错/列出候选」）：

4. **位置后缀的支持面太窄**：`_LOCATION_SUFFIX_RE` 只剥结尾的**单个** `:N` / `:N-M` /
   `#L…`，而变更审计笔记的实际写法是**位置列表**：`path:303,331`、`path:75/134/159`、
   `path:14,117,122-126`、`path:20/:31/:53`（`/:` 混写）。实测 22 条残留**全部**属此类，
   且被引路径逐个核对**都存在** → 100% 误报，占该 store 当时 53 个 error 的 42%。
   **改**：剥离 `,` / `/` / `/:` 分隔的位置列表（保留 `#L12-L14` 旧形态）；
   真缺失的 `path:12,16` 剥离后仍照报。
5. **多命中静默**：`resolve_memory_dir()` 原先返回**第一个存在的候选**（codebuddy 优先），
   而本机 CodeBuddy 与 ZCode 两份 store **同时在写**——默认运行只看得到 CodeBuddy，
   真正的重灾区（ZCode，100+ 文件）不会出现在同一次输出里。
   **改**：新增 `existing_memory_dirs()`；`resolve_memory_dir(repo_root, harness=None)`
   只在**唯一**命中时返回；0 个或 ≥2 个都返回 None。CLI 新增 `--harness`：多命中时报错、
   列出在用目录并要求指定（退出 2），`--harness` 过滤后为空时同样报错列出在用目录。

涉及文件：`tools/dev/memory_lint.py`、`tests/test_memory_lint.py`、
`docs/development/ai/harness-adapters.md`（同行内指针，守 S6 行预算）。
本残留单独立项为 **#2118**（#2065 在前述 3 处落地后即被 CLOSED，这两个面仍在内）。

### #2062 门禁与测试质量（5 处）

1. **测试会连生产库**：`tests/test_check_alembic_at_head.py` 只从 env 剔 `DATABASE_URL`，
   而 checker 会回落读 `<repo>/.env.backend`（本机存在=生产控制面）→ 用例在本地会真的连库。
   **改**：checker 新增 `--env-file`（显式指定即取代默认回落），用例指向空文件。
2. **部署守卫顺序误报**：`check-deploy-source.sh` 用精确相等判据，而 runbook 是
   「`git pull` → 守卫 → `alembic upgrade head`」——刚 pull 到带迁移的代码时库**合法落后**，
   守卫必红。**改**：checker 新增 `--allow-behind`（只拒「库超前 / 修订未知」，落后仅 WARN），
   手工路径带上它；systemd 的 `ExecStartPre` 不带（那里硬检查在 `upgrade head` 之后）。
   新增纯函数 `classify_schema_state()` + 4 个离线用例。
3. **孤立模型门禁空跑即绿**：解析不到任何模型时原先打印「无零消费方模型」——与「检查通过」
   不可区分。**改**：退出码 2 并说明原因。同时把「引用」判定从**整文件正则**改成
   **AST 使用点**（`Name`/`Attribute`/import 别名 + 整串即标识符的字符串常量，覆盖
   `relationship("Foo")` 惯用法；文档字符串节点显式排除）——原实现让「被提及」等于「被使用」，
   正是 #734 那类幽灵模型可存活的口子。self-test 补两态（散文提及不算引用 / 字符串引用算）。
4. **env 示例门禁口径与实现不符**：实现只查「键名在仓里出现过」，标题却写「真实读取点」。
   **改**：标题与判据说明对齐（明示是拼写/悬挂键粗筛）。**未收紧**到真实读取点——
   实测 25 个示例键里 9 个未命中读取点模式，直接收紧会立刻变红而非暴露新问题（见 Revisit）。
5. **前端用例写在 describe 之外**：`HostsPage.test.tsx` 的批量安装用例在 describe 闭合之后，
   `beforeEach` 的 mock 复位对它不生效（可能落在共享 mock 的历史调用上假绿）。
   **改**：把 describe 的闭合移到文件末尾，使该用例回到 describe 内。

## Alternatives

- **#2065 只修误报不动默认目标**：工具仍会去体检 CodeBuddy store 而给出与在用 store 无关的
  结论（本次事故的起点）——两处都改。
- **#2065 无候选时回落到 CodeBuddy**：正是「静默指向另一个 store」的成因，改为报错退出。
- **#2062-2 直接删掉手工路径的守卫**：会丢掉「库超前于代码」这一真实风险（分支代码/schema
  超前）；`--allow-behind` 保留该拒面。
- **#2062-3 只加「空则退出 2」不动引用判定**：门禁仍可被「在注释里提一句」绕过。
- **#2062-4 直接收紧语料**：见上，会立刻变红且 9 条里可能混有真实读取点（如经 Settings 类
  读取），需先逐条核对。
- **#2065 残留只修位置列表、不管多命中**：默认运行仍会静默给出某一个 store 的结论，而
  「多命中」在本机是**常态**（CodeBuddy + ZCode 两份都在写），等于把 #2065 的起点问题
  留在原地。
- **多命中改为「取最近写入的那个」**：等于用 mtime 猜「哪个在用」，猜错的时代价与静默取
  第一个相同（结论张冠李戴），且 store 正被写入时结果不稳定。
- **位置后缀改成「冒号后一律截断」**：会误伤含冒号的合法引用（如 `path:2026-09-15`
  这类日期串），误伤面大于收益，故只覆盖可枚举的位置形态。

## Revisit

- **#2062-4 的 9 个候选键**（`AUTH_COOKIE_SECURE`、`AUTH_COOKIE_SAMESITE`、`CORS_ORIGINS`、
  `CORS_ALLOW_METHODS`、`CORS_ALLOW_HEADERS`、`AUTO_REGISTER_HOST`、
  `HOST_HEARTBEAT_TIMEOUT_SECONDS`、`SESSION_WATCHDOG_INTERVAL_SECONDS`、
  `UNKNOWN_GRACE_SECONDS`）：需逐条核对是「经 Settings 类间接读取」（我的正则没覆盖）
  还是真幽灵键，再决定把门禁收紧到读取点。属独立跟进项。
- **#2062-2 的 `classify_schema_state`**：`known_revisions()` 用 alembic ScriptDirectory 扫，
  单头仓库下祖先闭包即全部 revision；若将来出现多 head，需改成「按 head 分别取闭包」。
- **S6 与 `harness-adapters.md`**：该文档已顶到 100 行预算，后续任何新增内容都需先扩容预算
  或下沉到按需文档——本次用同行内指针绕开，属临时姿势。
- **`origin/main:path`（git ref:path）形态**：它不是仓库相对路径，现被当断链报（该 store
  有 1 条）。是否纳入跳过集，取决于这类写法在记忆里的用途能否判定，未在本 PR 处理。
- **余下 31 条断链的判读**：多为缩写引用（`services/auth_session.py` 实为
  `backend/services/...`、`aee/...`、`backend/migrations`）或已删/改名的旧路径。工具只能判
  存在性，「缩写算不算腐化」需人工裁决；若要机械化，须先定义「允许省略的前缀集合」，
  否则会重新引入误报。
- **多命中的默认策略**：现状是「多命中即退出 2，须 `--harness`」。若将来出现「一个仓库
  多 harness 长期并行、希望一次体检全部」的诉求，应加显式开关（如 `--all-stores`），
  而不是回退到静默取第一个。
