# merge 交付产物面三件：兜底清理引用守卫 / 表头契约可观测 / 平台发布路径覆盖（#2281 / #2256 / #2253）

- 类型：bug-fix（含验证缺口收口）
- 范围：`backend/services/dedup_scan.py`、`backend/services/dedup_extract.py`、
  `docs/design/2026-scan-upload-merge-contract.md`、两处 services 测试

## Decision

### 1. 本机中转兜底清理加第二条判据：持久引用（#2281）

`sweep_stale_local_merge_outputs` 的清理前提从「中心已配置」扩为**三条同时成立**：
中心已配置 ∧ 无 `plan_run_artifact` 行指着该目录 ∧ 形态与 mtime 超期。

- 引用集在**调用点**算好（`local_merge_artifact_refs`），以 `protected` 传入 sweep——
  保持「清理函数只按形态与 mtime 筛、交付语义留在调用点」的既有分工；
- 引用查询**失败即跳过本轮清理**（留残留优于毁交付物：删错不可逆，残留可由下一轮收敛）；
- 保留与被删目录都留名：`merge_local_sweep_kept_referenced`（带引用它的 run 号）与
  `merge_local_stale_swept dirs=...`。无引用的中转残留**不可**反推 run 号（artifact 行
  正是缺失的那种），故只记目录名，不伪造标识。

### 2. 两处按名依赖的静默降级改为可观测（#2256）

`Path` 列取不到时不再无声跳过，各记一条 WARNING 并带上**实际读到的表头**
（`merge_report_path_column_missing` / `dedup_xls_path_column_missing`）。降级行为本身
不变：该 xls 跳过、其余继续——变的是「表头漂移」与「本轮确实无数据」从此可分。

契约面登记在 `docs/design/2026-scan-upload-merge-contract.md`：按名依赖的两处消费点、
容忍面（大小写/首尾空白/列位置）、盲区（改名、删列、`str.strip()` 不剥的不可见字符），
以及两处**不阻断**面（整段重写失败只记日志；列缺失只跳该 xls）。

### 3. 平台侧发布路径补覆盖（#2253）

`merge/{platform}/` 分支此前零执行：既有 6 处 `_publish_merge_to_center` 调用全部不传
`platform`，多平台聚合用例又把 `run_merge_sync` 整个 mock 掉。本次补三段一致性用例：
发布落 `merge/{platform}/` → `PlanRunArtifact.storage_uri` 同形 → 下游
`_merge_uri_is_platform_partitioned` 判真（含 jira bundle 落点）。真实 UNISOC 产物的
终确认仍归 ADR-0032 §Revisit（见下）。

## Alternatives

- **#2281 改成「按 run 判定」**（该 run 是否已登记中心路径的 merge 产物）：语义等价但需要
  run↔目录映射——即同一次查询；且会把交付语义搬进清理函数，单测（无 DB）也不可用。否。
- **#2281 查询失败时照旧清理**：维持旧行为、无额外分支，但把「DB 抖动」与「产物丢失」
  绑成同一后果。否——清理是兜底而非交付前提，跳过不损主链。
- **#2256 缺列改抛错**：与既有「降级不阻断发布」的取舍冲突，且会让单个坏 xls 打断整轮
  发布。否，只补可观测。
- **把 #2256 的静默面写进 ADR-0032 §Revisit**：ADR 该条的两个触发条件（首次真实 UNISOC
  run、工具升级）**仍然成立**，不会因本次单测收口而失效；改 ADR 反而要推版本号并占索引。
  改记设计契约文档（merge 语义的权威入口），ADR 留作真机终确认的锚点。

## Revisit

- **真实 UNISOC 产物的终确认未做**：本次三段用例用 stub 表头（非工具真实的 15 列归一
  形态），`_rewrite_merge_report_paths_to_center` 在真实 UNISOC 产物上的 Path 列重写
  仍属 ADR-0032 §Revisit 的触发范围——首次真实 UNISOC run 走完归档链时按
  `run_context.merge_platforms` 核对。
- **引用查询的成本**：`plan_run_artifact.storage_uri` 无索引，前缀匹配是顺序扫描；当前
  仅在「中心已配置」时每次 merge 调用一次，相对 merge 子进程可忽略。artifact 表量级
  上台阶后复核（可加表达式索引或改为只对候选目录做 `IN` 查询）。
- **孤儿目录**：目录被人工删除而 artifact 行仍在时，本守卫会保留同名残留；plan_run
  删除（artifact 行级联删除）后自然可回收，不需要额外清理通路。
