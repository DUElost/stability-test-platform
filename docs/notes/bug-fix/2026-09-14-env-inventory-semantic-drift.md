# 门禁修缺：环境变量清单漂移判定改为语义比较（#737 续）

Status: implemented
Class: bug-fix

## Decision

`env_inventory.py --check` 原本**逐字节**比较生成块——把「无关 PR 加了一行代码导致
读取点行号平移」也判成清单漂移。2026-09-14 **#1952**（abort/merge 修复，与配置无关）
的 `pr-agent-tests` 因此变红：其分支里 `notification_service.py` 的 5 个 SMTP 变量
行号整体 +1（`:44-48` → `:45-49`），名称/默认值/登记状态全部未变。

修法：门禁只对**语义**负责——比较签名 `名称 → (默认值, 是否登记, 类别)`；
`读取点` 列降级为 `--write` 时的**导航快照**（文档头部已注明可能与当前行号有偏差）。

配套：

- 失败信息改为可处置清单（新增名 / 消失名 / 默认值变化 / 登记状态变化 / 类别变化），
  并明示「纯行号平移不触发」；
- 单测补 `test_signature_ignores_line_numbers_and_detects_semantics`（同语义不同行号
  签名相等；默认值变化产生可读 diff）。

## Alternatives

- **保持逐字节比较，让每个 PR 自行 `--write`**：否决——把与配置无关的 PR 拖进
  清单刷新，是典型的门禁误报成本（本次 #1952 实证：一个 abort 修复被环境变量表格
  挡住）；且 `--write` 会把无关 PR 的 diff 掺入 300+ 行文档改动，审阅成本更高；
- **从文档里删掉行号列**：否决——定位读取点是该列的主要价值，保留但声明为快照更划算；
- **只在夜间/定时任务里刷新行号**：暂不做——`--write` 已能随时刷新，
  加定时任务属于新机制，先看快照漂移的实际影响。

## Verification

- **四项变异（退出码级）**：
  | 变异 | 期望 | 实测 |
  |---|---|---|
  | 在 env 读取前插入注释行（模拟 #1952 的行号平移） | 绿 | `exit=0` ✅（修复前为红） |
  | 默认值 `SMTP_PORT 587 → 2525` | 红 | `exit=1`，输出「SMTP_PORT：默认值变化 '587' → '2525'」✅ |
  | 新增未登记读取名 `ZZ_NEW_DRIFT` | 红 | `exit=1`，指路「登记或内部声明」✅ |
  | 还原 | 绿 | `exit=0`（210 名一致）✅ |
- `pytest tests/test_env_inventory.py tests/test_env_example_parity.py` → **8 passed**；
- `pytest tests/` 与 `run_gates.py check:quick`：见 PR；`ruff` 通过。

## Revisit

- **行号快照的实际漂移速度**：若长期无人 `--write`，附录行号可能偏差较大——
  观察一至两周，必要时在夜间 check:full 里加一次自动刷新（仅文档、单独 PR 规则）；
- **其他"逐字节 vs 语义"门禁**：本次教训适用于同类生成块（若后续再引入生成型文档，
  默认按语义比较设计）。
