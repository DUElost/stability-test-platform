# B11-U5：aee_extract 非零退出改采产出实证判据（兼容 MTK rc=255）

Status: implemented
Class: bug-fix

检索词：B11-U5、aee_extract、rc=255、产出实证、`__exp_main.txt`、
`resolve_valid_aee_extract_exp_main`、#4199 v1.2、#4174。

## Decision

按 [#4199](https://github.com/DUElost/stability-test-platform/issues/4199) **v1.2**
§1 M5 / §3 B11-U5 / §4.2 与 [#4174](https://github.com/DUElost/stability-test-platform/issues/4174)
Owner 裁决，修复全仓 2 处 `aee_extract` 调用点对「满产出仍 `rc=255`」的硬判失败：

1. 在 `backend/agent/contracts/evidence_layout.py` 新增纯 stdlib
   `resolve_valid_aee_extract_exp_main`（ADR-0054），统一四重核验：唯一合法
   `*.DEC`（优先 `<dbg.name>.DEC`）→ `assert_no_symlinks` → 普通非空
   `__exp_main.txt` → UTF-8 可读且 `strip()` 非空。
2. 控制面 `jira_handoff_export._run_aee_extract_isolated` 与 Agent
   `EvidenceUploader._unpack_dbg_in_place` 同构：`rc == 0` 仍过核验；`rc != 0`
   先记结构化 `WARNING`（dbg / rc / 截断 stderr·stdout），再按产出实证判定；
   失败时 U3 抛 `JiraHandoffError(502, handoff_dec_extract_failed, …)`（保留 rc），
   U4 抛 `EvidenceLayoutError` 并 purge 本次新产生的半成品 `.DEC` 后走既有降级。
3. 不改全局补解并发上限 = 1、原件零污染 / 不提前 prune、不覆盖防线；不改
   `frontend/`、`tool_manifest.json`，零 Alembic 迁移。

## Alternatives

- **仅把 `rc=255` 加入白名单**：否决。无法覆盖其他非零但仍满产出的厂商行为，且
  缺少产出核验会放行半成品。
- **两侧各自复制校验逻辑**：否决。同形态两处调用点易漂移；按 ADR-0054 抽契约
  纯函数更稳。
- **修改 / 包装 `aee_extract` 二进制本体**：否决（#4199 §6）。
