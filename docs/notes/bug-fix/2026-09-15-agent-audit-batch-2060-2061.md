# Agent 侧审计批（#2060 / #2061）：上限驱逐误伤在场条目、退避预算、sink 收口

Status: implemented
Class: bug-fix

## Decision

**#2060 unisoc `_processed` 上限驱逐会把仍在设备上的条目踢出去**
`#767` 给 `UnisocUniviewReconciler` 加了 `_max_processed_entries` 上限，超限时按滞回计数
排序取前 `overflow` 个驱逐，**未排除仍在场的名字**（本拍设备列表 `listed` / 本地树
`local_names`）。而 emit 循环唯一的去重就是 `_processed` 成员判定，
`_sync_device_events_to_local` 对已同步目录不再重拉、也不会把名字加回来 → 被误驱逐的条目
下一拍以**新 seq_no** 重发，随后重回集合再次超限被驱逐：稳态下每拍重复 emit 约
`overflow` 条 log_signal / DLE（控制面按 `(job_id, seq_no)` 去重，新 seq_no 拦不住）。
**改**：victims 只从「不在 `listed` 且不在 `local_names`」的名字里取；不足 `overflow` 时
本轮少驱逐（上限是防膨胀的最后防线，不要求精确命中），并以 `..._cap_partial` 记日志。

**#2061(a) 租约校验退避的最后一段花在「放弃之后」**
`_LEASE_VERIFY_RETRY_DELAYS = (1,2,4,8,15,30)` 与 `for attempt, delay in enumerate(...)`
使探测发生在 t≈0/1/3/7/15/30，末次失败后**再睡 30s 才返回**——t≈60s 处没有探测。于是
30s 之后才结束的控制面中断仍判死，改动只多了约 30s 的失败延迟（#1921 按「总耗时 ≈60s」
结算，但那不是运维目标）。
**改**：退避语义改为「两次尝试之间的间隔」——循环头 `if attempt > 1: time.sleep(delays[attempt-2])`，
共 `len(delays)+1 = 7` 次探测，末次落在 t≈60s；异常分支不再自己 sleep。

**#2061(b) 被放弃 reader 的 sink 不收口**
`_StepLogSink` 只在**拥有它的 reader 的 `finally`** 里 `close()`；而 `_pump_process` 的
「reader 卡住被放弃」路径（POSIX 轮询 reader 正常退出，Windows 阻塞 reader 无法打断）
只关管道 → 该 sink 的缓冲尾部日志（步骤排障的**唯一**副本）与 fd 一直留到进程退出。
**改**：新增纯函数 `_close_sinks_for_abandoned(threads, log_sinks)`，在放弃路径上对仍存活
的 reader 补 `close()`（`close()` 幂等、不抛）。

## Alternatives

- **#2060 直接把上限纳入策略（超限即告警不强驱逐）**：设备事件目录数确实可能长期超限，
  完全不驱逐会回到 #767 的线性膨胀——保留上限、只收窄候选集。
- **#2061(a) 仅追加一个 `60` 到 delays 元组**：探测序列变为 0/1/3/7/15/30/60/**90**，
  多出一次无意义等待；改语义后元组本身就是探测间隔，含义单一。
- **#2061(b) 让放弃路径直接 `os.fsync`/重开文件**：sink 已封装缓冲与失败语义，
  调用它的 `close()` 才是同一条路径。

## Revisit

- **#2060 的在场集合来源**：`listed` 为 `None`（本拍设备列表任一 root 失败）时整段裁剪跳过，
  此时上限也不生效——若现场出现「长时间列不出设备 + 状态持续膨胀」，需要另一条防线
  （属 #767 的后续）。
- **#2061(a) 的总预算仍写死在元组里**：若现场反馈 60s 仍不够（例如 nginx 502 恢复更慢），
  调 `_LEASE_VERIFY_RETRY_DELAYS` 末位即可，无需改循环结构。
