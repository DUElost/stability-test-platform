# 治理门禁逃逸向量修复（S9 深层标题 / S10 非日期文件名 / self-test 入 CI）

Status: implemented
Class: bug-fix

## Decision

修复 #854 立案的三项门禁缺口（均为当日实测复现的低危逃逸向量）：

1. **S9 深层标题逃逸**：原实现只匹配 `### ` 前缀，`####`+ 标题两种前缀都不命中、完全绕过章节白名单。改为正则 `^(#{2,})\s` 统一捕获标题层级——二级进白名单校验、**三级及以下一律 BLOCK**（含四五六级），与 S9「领域细节不能新增为深层章节」的意图对齐；
2. **S10 非日期文件名逃逸**：原实现对不匹配 `^\d{4}-\d{2}-\d{2}-.+\.md$` 的文件直接跳过——class 目录内改名即可绕过 Status/Class 头校验。改为**非日期命名的 .md 一律报错**（新 Note 强制日期命名）；存量核查=六个 class 目录零非日期文件（README.md 已由调用方排除），无兼容负担；
3. **self-test 入 CI**：`ci.yml` 治理面检查步骤在 `--check` 前先跑 `--self-test`——检查器自身回归（判定逻辑被改坏）此前 CI 不可见，与相邻 `check-internal-ip-leak.py` 的正反样例自证步骤对齐。

自测样例同步扩充：S9 深层/五级逃逸红样例、S10 非日期文件名红样例（12 条规则数不变，新增均为既有规则的红绿补强）。

## Alternatives

- **S10 只对非日期文件警告不阻塞**——放弃：与 #854 修复建议相反，且「改名绕过校验」正是要堵的洞；
- **S9 单独列 #### 前缀判断**——放弃：逐级枚举会继续漏 #####；正则按深度统一捕获一次堵全；
- **self-test 放独立 CI job**——放弃：与 --check 同 step 顺序执行最简，失败语义相同（lint job 红）。

## Verification

- `--self-test`：12 条规则红绿双向通过（含新增 4 个样例）；`--check`：S1–S11+S5x 全绿；`ruff` 通过；
- 逃逸向量实测复验（修复后）：`####`/`#####` 标题被拦（返回非空）、非日期文件名被拦、合法样例全绿；
- 存量兼容：六个 class 目录非日期 .md 零存量（升级前核查）；PR CI 六项 required checks 以实际运行为准（self-test 新入 lint job）。

## Revisit

- 若未来出现确需非日期命名的特殊 note（如索引类），须先修订 S10 规则而非绕过；
- S2 对 `.cursor/rules/*.mdc` 与 `.claude/skills/*/SKILL.md` 内链接的覆盖仍为潜在缺口（#854 附带观察，当前零 markdown 链接语法、无实害，暂不动）。
