# 治理面 S12/S14 判据收口：索引粗体状态归一 + 注释版本判据放宽到已发布集合（#2035 / #2249）

Status: implemented
Class: bug-fix

## Decision

两条判据同批收口，都在 `tools/dev/check_governance_surface.py`：

**#2035（S12）索引行状态 cell 也须在场且可解析。** 状态 cell 经 `_norm_status_cell`
剥首尾空白与 `*` 后比对 `_ADR_STATUSES`，粗体/斜体与裸词同判；仍解析不出的**在场**
行报 BLOCK，不再退化成「不在场不约束」而静默退出状态比对。开单时点记 5 行（ADR-0036
..0040），2026-09-16 实核为 **8 行**——其后新增的 ADR-0041/0042/0043/0044 沿用了粗体
风格，issue 正文的计数已过期，以实核为准。

**#2249（S14）判据由「== 头部规范位版本」放宽为「∈ 已发布版本集合」。** 集合 =
版本记录块 token（三种书写形态全读，见下）∪ `## 修订记录` 章节 token ∪ 头部规范位
版本；头部不带规范位版本者仍不约束（S12 同纪律）。旧判据在头部 bump 后把**刻意引用
历史版本**的合法注释判红（ADR-0032 头部 v0.9、代码引 v0.8 的 B3 spike 裁决即现实例），
并使「给头部补规范位版本」的努力制造大面积红灯 → 覆盖缺口永久化。新判据拦的是
「该 ADR 从未发布过的版本」。

**形态不止一种，只读一种等于没修。** 实核 45 篇 ADR 后确认版本历史有**三种书写形态**
（外加表格）：

| 形态 | 篇数 | 例 | 块扫描的坑 |
|---|---|---|---|
| 单行罗列 / 线性续行 | 多数 | ADR-0034 `- 版本记录：v0.1 … / v1.0 …` | 无 |
| 缩进续行 | 1（ADR-0035） | `  **v1.0（草案）**；` | 无（旧实现已能读） |
| 缩进子项 | 2（ADR-0038、0042） | `  - v0.2（2026-09-13）：…` | **旧块扫描把缩进子项当成「下一个 `- ` 项」= 块结束 → 整块零 token**，两篇 ADR 的已发布版本对 S14 完全不可见 |
| `## 修订记录` 表格 | 7 | ADR-0029/0030/0031/0032/0033/0026/0027 | 列布局三种；#2249 举的现实例 ADR-0032 正是此形态 |

块扫描据此改为：**终止只看同级或更外层的 `- ` 项**（缩进子项是块内容），并按**行首**
token 收集——行尾引用 token（「本版号 v1.8 已被占用，重编 v1.9」）仍不计入，否则伪造
引用会被当成已发布版本放行。

**S12 的 record_tip 同步改取「版本号最大者」而非「最后一个 token」。** 起因是实测被
证伪：缩进子项形态是「最新在前」（ADR-0038 首项 v0.2、末项 v0.1），于是按位置取末项
会得到 v0.1 —— 而 ADR-0035 的缩进续行又是「最新在后」。**书写顺序在形态之间不一致**，
按位置取末项会随形态摇摆（实测对 ADR-0035 取末项得 v1.0、头部 v1.2 → 假红）。取版本号
最大与该规则本意（头部行 = 最新版本）一致，且对现有线性形态零行为变化。

## Alternatives

- **A. 维持「== 头部」+ 要求历史引用改写措辞**（前序 Note
  [`2026-09-15-adr-code-ref-version-gate.md`](2026-09-15-adr-code-ref-version-gate.md)
  §Revisit 的立场）：否决。ADR-0032 v0.8 的注释**是对的**（该裁决确属 v0.8），为迁就
  工具去改写事实不成立；且 #2250 补版本时会有引用成批变红——**实测 24 处**
  （ADR-0029 的 3 处 v2.3 + ADR-0030 的 21 处 v1.4/v1.8），issue 正文估的「51 处」是按
  「头部必然 bump 到 ≥ v2.6」估的，而头部版本应取记录最新版 v2.5/v1.9，其中 27 处本就
  与头部一致。前序 Note 的该条 Revisit 由此闭合为「改判据」而非「改写措辞」。
- **B. #2035 只报 warning 不阻塞**（issue 原文用词）：否决，取 BLOCK。与 #1524 对头部
  状态行的处置同纪律（同一盲区、同一后果）；且归一后当前 0 存量红灯，「只准变短」的
  棘轮无存量可背。
- **C. 集合只取项目符块**（改动最小）：否决。漏表格 → ADR-0032 现实例不修（见 Decision）。
- **D. 集合取「该 ADR 文档全文出现过的 vX.Y」**：否决。过宽——正文叙述里的引用 token
  （如 ADR-0034 的「本版号 v1.8 已被并行 PR 占用，重编 v1.9」，v1.8 从未发布）也会
  变成「已发布」；范围也不可界定。
- **E. 沿用 record_tip 顺带激活表格形态的 S12「头部 ↔ 版本记录末项」比对**：不做。
  那会给 7 篇表格 ADR **新激活**一条休眠检查，可能当场红灯存量漂移——属独立议题，
  记入 Revisit，不混进本批。
- **F. 缩进形态按位置约定「最新在前」反转**：**做过又被证伪，已撤回**。先按
  「缩进子项 = 最新在前」实现，随即实测 ADR-0035 —— 它的缩进续行是「最新在后」，
  反转后 tip 变 v1.0 与头部 v1.2 冲突，门禁当场红。书写顺序在形态间不一致，位置语义
  不成立；改取版本号最大者。

## Revisit

- **检测力损失（本批最重要的代价，需知悉）**：判据放宽后，「头部 bump 后注释停在旧
  版本」这类**漏改**只有在旧版本**不在**已发布集合时才会拦——即 #2154 原始场景（v1.0
  已发布、头部 v1.1、注释停 v1.0）在新判据下**不再报**。「历史引用」与「漏改」在单行
  注释上无法机械区分，本批依 #2249 裁决取「不误报」优先。要恢复该检测，出口是给历史
  引用一个显式书写形态（如 `ADR-0032 v0.8（B3 spike 时点）`）后另立规则，届时须重新
  权衡误报面。
- **record_tip 取最大值的反向风险**：块内若混入「引用别的 ADR/别处的更高版本号」的
  散文 token，取最大会把头部判红（位置语义下这个 token 若在行尾同样会污染，属同一类
  书写纪律问题，风险面等价）。目前 45 篇实测无此形态。
- **表格区间未展开**：`v0.1–v0.4.1` 这类区间只取到两端字面 token，引用 v0.2/v0.3/v0.4.1
  仍会误报（当前无此类引用）。出口：区间展开，或在表格里逐行列出。
- **同族新发现（未修，建议另开单）**：S12 的「头部行 ↔ 版本记录块**最新版本**」对
  **表格形态** ADR 仍是**休眠**的——`parse_adr_record_tip` 只读项目符块，7 篇表格 ADR
  的该条比对从未生效（与 #2035 同一「静默跳过」族）。激活它等于给这 7 篇新增一条检查，
  可能当场暴露存量漂移，应作为独立议题带存量清账一起做。
- **#2250 只解除了前置**：给 ADR-0029/0030/0036/0038/0042 补规范位版本 + 同步
  README/DOC-MAP/M7 + 57 处引用逐条判断「当时版本 / 当前版本」的本体工作单独进行；
  本批的形态修复正是它的前置之一（ADR-0042 的 4 处 v1.0 引用需要缩进子项形态被读到
  才判绿）。冻结目录 6 处登记为永久豁免同样在 #2250 内。
- **#2035 的可选项未做**：issue 提出的「S12 增加一条要求 README 状态单元格格式统一」
  属可选；归一只让两种写法同判，未强制统一风格。
