## Decision

1. **#1695 gpu_check v1.0.10**（新版本目录 + seed `a3b2c1d0e9f8`，串在
   z7a6b5c4d3e2 之后保持单 head）：`_last_protobuf_test_result` 的字段值
   判定从**全等**改**前缀**。真机形态 `test_result\x12\x05true\x0f`
   （2026-09-01 实证，length=5、第 5 字节是下一字段 tag 字节 `\x0f`）经
   `bytes.strip()` 仍是 `b"true\x0f"`，v1.0.8/v1.0.9 全等比较恒返回 None →
   verdict `no-tests` → 正常完成被判空跑失败（PASS→FAIL 回归）。长度前缀
   仍在，#746 的「最后一条为准 + 不被后文 true 子串干扰」语义不变；seed
   按 v1.0.9 同款治理模板停用 1.0.9（带 plan_step 引用检查）。
2. **#1715 mtbf_setup v1.4.1**（新版本目录，无 seed——v1.4.0 即
   auto-register 路径）：run_dir 新鲜度判据从「宿主 `time.time()` × 设备
   mtime（2s 容差）」改为「**触发启动前**的设备侧目录快照对比」——不在
   快照中（新建）或快照内 mtime 相对增大（同名重建）即命中。mtime 与快照
   同取自设备时钟，自比无跨钟；设备未对时（偏差 >2s）不再把启动成功误判
   为 60s 超时。`_snapshot_run_dirs` 对 stat 失败的目录记 0.0（视为旧目录）。

## Alternatives

- #1695 用 `rstrip(b"\x0f")` 等白名单剥尾——否：把「现场字节」硬编码进解析
  器，下一台设备换个尾字节又复发；前缀判定对任意尾随字节稳健。
- #1695 回退 v1.0.7 的 64B 窗口扫描——否：#746 的误判成功场景（false 后
  64B 内出现 true 子串）会回来。
- #1715 用「宿主与设备时钟差测量校准」——否：引入新的跨钟测量不可靠面；
  快照对比彻底消除跨钟。
- #1715 接受任意 mtime 快照内目录——否：#810 的假阳性场景（残留目录）回来。
