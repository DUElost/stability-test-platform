# 真值面批：漂移检测器比错源 + dev PG 存量卷文档射程 + ADR-0048 supersede 注记（#2985 / #2963 / #2992）

Status: implemented
Class: bug-fix

## Decision

### ① #2985：检测器的「源随落点定」

事实：`etc/…/alerts-stability-platform.yml` 在两类宿主上是**两份不同的东西**——站点装
`site-alerts.yml` 子集（installer 渲染），存量控制面宿主放平台全量**人工副本**（原样拷贝、
不渲染）。工具此前把清单里的站点源 + installer 渲染口径套在存量落点上 ⇒ 本机该资产恒 DRIFT
（判别力退化成常亮灯），且补救提示指向 `etc/stp/…`——本机 Prometheus 根本不加载它。

改法：`LEGACY_FALLBACKS` 的值从裸字符串升级为 `LegacyFallback(destination, source, remedy, render)`：

- `source`：该落点实际运行的那份仓库源（此处=平台全量）；
- `render=False`：**人工副本口径**——期望内容=仓库源原文（占位符原样保留，逐字节比对）；
- `remedy`：该落点专用的补救路径（重放副本 + `POST /-/reload`；ADR-0011 正式挂载未落地）。

输出新增 `source_used` / `remedy` 字段；`source` 保持「清单声明源」语义不变（清单对拍类断言不受影响）。
接线面同步修：`check-deploy-source.sh` 的 WARN 过滤器原先把「源文件：」续行一并丢掉——操作者只看得到红、
看不到该改哪份源；改为一并透出，WARN 文案不再单一指向「重跑站点安装」。

### ② #2963：存量 dev 卷路径进日常入口

`local-development.md` 补「存量 dev 卷的 PG 大版本」小节：现象原话
（`database files are incompatible with server`）+ 立即解法（`.env` 的 `POSTGRES_IMAGE=postgres:<原major>-alpine`）
+ 正式迁移配方（dump → 留证副本 → 空卷 17 → restore → `init_dev_db`/`alembic upgrade head`）+ 校验点。

**未做机械判据（issue 建议 3），理由**：`init_dev_db.py` 不是有效落点——postgres 起不来时 server 容器
根本不会启动（`depends_on: service_healthy`），该脚本不会被执行；当前 dev 栈也没有统一启动入口可挂。
终态出口写在小节末句（启动期比卷内 `PG_VERSION` 与镜像 major），避免沉淀一个「有工具没人跑」的判据。
守卫：`test_postgres_compose_image_2945.py` 增一例，钉日常文档覆盖存量路径的三要件
（可检索原话 / `POSTGRES_IMAGE` / `pg_dump`+`pg_restore`）。

### ③ #2992：ADR-0048 supersede 注记（6 文件 9 处 + 3 处同族残留）

- ADR-0020：`:217` 就地改写 + **文件级勘误块**（覆盖其历史 DDL / JSON 示例 / 「复制
  `failure_threshold`」迁移条款——这些片段是 2026-05 的历史记录，不逐条改）；
- ADR-0021 D6 原因第 1 条：改为「派发未对齐属调度层故障，不与设备级失败混算」；
- ADR-0022：watcher-summary 行的 `exceeded` 标志、`stability_plan_run_pass_rate` histogram 行
  （整条标记退役）、测试覆盖项 6（`test_failure_threshold_includes_backoff.py` 已不存在——悬空引用一并收）；
- ADR-0023：Drawer 顶部字段清单去 `failure_threshold`；
- ADR-0026：§6 现状段（删已漂行号 + 注记）+ 方案 B 驳回理由的例证；
- 设计文档：Phase 5 第 2 项（`failure_threshold == null` 的「默认 5%」显示）、冲刺 B 的 B4（失败阈值 Tooltip）。

措辞按 **ADR-0048 v1.1 终态**：三态产出恢复（`failed_only > 0` → PARTIAL_SUCCESS，**不判红、不断链**），
通过率=纯前端派生展示；`failure_threshold` 判定轴、后端 `pass_rate` 字段与 histogram 维持废止不回灌。
新增注记不写行号（引用 ADR 编号 / 小节名 / 符号名），避免再次漂移。

## Alternatives

- **#2985 按 issue 建议 2 给平台全量单列一条 manifest 项**：弃——`monitoring_artifacts()` 同时是
  **installer 的写入清单**（`stages.py` S2b 渲染循环），加一条会把控制面指标规则下发到每个站点，
  直接回退 #2643 方向 1（站点结构性无样本、只制造「监控就绪」假象）。
- **#2985 让存量副本「渲染/原样两种期望都接受」**：弃——判据失去单一定义，且会掩盖「副本不是原样拷贝」
  这一事实。选原样拷贝口径（与 README 的「人工重放」一致），渲染过的副本报 DRIFT 并给出「按原样拷贝」补救。
- **#2963 新增 dev 栈启动期判据脚本**：弃——没有执行者（见 Decision ②）。
- **#2992 全库清剿 `failure_threshold`/`pass_rate` 字样**：弃——`docs/notes/*`、`docs/reviews/*`、
  灰度记录是有日期的历史留痕，按纪律不回溯改写；本次只动**规范面**（ADR + 权威设计文档）。

## Revisit

- **ADR-0011 正式挂载落地时**：本处 `render=False` 的原样拷贝口径与 `remedy` 文案要一并复核——
  若平台规则改为 installer/挂载路径下发，存量兜底条目应删除或改为渲染口径。
- 存量 dev 卷的机械判据仍是缺口（见 Decision ②）：若将来出现统一的 dev 栈启动入口（Makefile/脚本），
  应把「卷内 `PG_VERSION` vs 镜像 major」前置检查挂在那里。
- #2992 只收规范面；若后续再出现「ADR 引用已移除字段」的复发，考虑给 `docs/adr/*.md` 加一条
  机读棘轮（出现已退役字段名即要求同段落含 supersede 注记）——本批未做，避免文本匹配型守卫的脆性。
