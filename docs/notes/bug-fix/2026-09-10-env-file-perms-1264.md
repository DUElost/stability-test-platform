# 环境文件以 0600 创建（#1264）

Status: implemented
Class: bug-fix

## Decision

#1264（R14-F18）：`tools/prepare_env.py` 用 `target.write_text()` 写出含密钥的
环境文件，权限由调用者 umask 决定——常见 022 下产出 0644（同机其他用户可读）。

修复：

- 创建改用 `os.open(target, O_WRONLY|O_CREAT|O_EXCL, 0o600)` +
  `os.fdopen` 写内容——**mode 显式 0600，不依赖 umask**；
- `O_EXCL` 顺带收紧「exists 检查 → 写入」之间的 TOCTOU 竞态：并发下第二个
  进程拿 `FileExistsError`，按既有「已存在」语义打印并返回 0（语义不变）；
- 已存在的文件**不改动**（既有测试锁定「keeps existing target content」）；
  存量 0644 文件不在本单自动收紧——静默改用户文件权限的副作用大于收益，
  需要时由运维按 runbook chmod（见 Revisit）。

与 ADR-0033 的关系：无直接约束（仓库工具脚本）。

## Alternatives

- `write_text` 后补 `chmod(0o600)`：存在「先 0644 落地、再收紧」的窗口，
  且并发下仍是竞态；O_CREAT mode 在创建那一刻就对；
- 对已存在文件强制 chmod 0600：静默修改用户现有文件（可能是被刻意共享的
  文件），且本单验收只针对「生成文件」——不做。

## Verification

- `pytest tests/test_prepare_env.py`：6 passed，新增 1 例——以 umask 022 运行
  后断言目标文件 `stat.S_IMODE == 0o600`（修复前会得到 0644，用例即复现）；
- 既有 5 例（创建/保留已存在内容/模板契约/secret 替换）不回归；
- `ruff check backend/ tools/ scripts/ tests/` 全绿。

## Revisit

- 存量 0644 环境文件的巡检/收紧：如运维需要，可加一次性检查脚本（列出
  `find` 命中的 0644 env 文件），不自动改；
- `target.exists()` 早退与新 O_EXCL 分支并存：前者是快速路径（含内容检查
  语义），后者兜竞态——两处打印文案已对齐（"already exists"）。
