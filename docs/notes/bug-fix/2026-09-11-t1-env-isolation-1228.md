# R13-R02 落地：RunConsole 子进程环境白名单化（#1228）

Status: implemented
Class: bug-fix

## Decision

`RunConsole.start()` 以 `proc_env = dict(os.environ)` 为基底叠加调用方 env：
被测/工具子进程继承控制面全部环境——`DATABASE_URL` / `AGENT_SECRET` /
`JWT_SECRET_KEY` 等服务凭据可达，「T1 环境覆盖」不等于完整隔离（argv /
路径白名单 / 四键覆盖有效，但未来测试命令仍可能读取继承的凭据）。

修复（`backend/services/run_console.py`）：

1. `_build_child_env(extra)`：白名单（PATH/HOME/USER/LOGNAME/SHELL/TMPDIR/
   TZ/LANG/LANGUAGE/LC_ALL/LC_CTYPE/TERM）+ 调用方显式 `env` + 
   PYTHONUNBUFFERED/PYTHONIOENCODING——**控制面环境不再透传**；
2. `start()` 改用该函数，docstring 更新隔离契约；
3. 隔离边界书面化（验收 1）：`docs/design/06-realtime-and-background.md`
   §5.1 表格列明 argv / cwd / env 白名单 / 进程组 / **同 UID 文件权限
   已知边界**；更强隔离（独立用户/容器）的触发条件指向 #1228 评估。

调用方（dedup JIRA 工具、agent 安装）本就显式传 env，白名单化不改其
行为；需要额外继承键的新调用方应在 `env=` 显式注入（新契约）。

## Alternatives

- **完整清空 env（不给白名单）**——放弃：PATH/HOME 等缺失会破坏子进程
  正常启动（解释器/工具解析），白名单是最小可用集；
- **保留 `STP_*` 前缀继承**——放弃：STP_* 面大且含路径/角色信息，显式
  注入更可审计；当前两调用方不需要继承；
- **本轮直接实现独立用户/容器隔离**——放弃：方向级变更（部署形态/权限
  模型），#1228 只要求评估+边界说明；已在文档标注触发条件。

## Verification

- **反例实证**：回退 run_console.py 保留测试 → 新用例失败（DATABASE_URL/
  AGENT_SECRET 透传）；修复版全绿；
- 新增用例（`test_run_console.py` +1）：子进程探测 `DATABASE_URL`/
  `AGENT_SECRET` 为 None、`PATH` 保留、显式注入 `STP_PROBE` 生效、
  `PYTHONUNBUFFERED=1`；
- `test_run_console.py` 全套 **17 passed**（含既有流式/超时/取消回归）；
- `check:quick` 与 PR 门禁：见 PR 描述。

## Revisit

- 同 UID 文件权限边界未变——「任意命令不可达生产资源」需独立用户或
  容器化执行（触发条件：出现新调用方传入非受控 argv 时优先立项）；
- 新调用方若依赖继承环境（如代理变量 HTTP_PROXY）需在 `env=` 显式传入；
  本单后所有继承即白名单，缺键会显式表现为子进程行为差异（可观测）。
