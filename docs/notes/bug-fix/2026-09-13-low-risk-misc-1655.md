# 低危杂项批 4 处（#1655）

Status: implemented
Class: bug-fix

来源：`audit-2026-09-12` 最近 24 小时变更审计的低危/复核成立项合批。

## Decision

1. **testcontainer 巡检目标判定收紧**（`tools/dev/check_test_containers.py`）：
   目标判定改为以 testcontainers 注入的 label（`org.testcontainers`）为准，
   镜像名只保留 `testcontainers/*` 兜底——不再按裸 `postgres:16` 匹配，
   手工起、仍在使用的同名 PG 不会被 `--prune` 误删；`_run_docker` 返回 rc，
   `docker ps/inspect` 非零退出 → 巡检失败退出码 2（不再把「docker 不可用」
   报成「未发现残留」绿退）；`--prune` 需显式 `--yes` 才执行删除（缺省只列
   待删清单），`rm` 失败逐个报告并复核剩余。
2. **内网泄漏门禁恢复扫描覆盖**（`tools/dev/check-internal-ip-leak.py`）：
   `backend/core/device_serial.py` 由整文件白名单改为 `SAFE_TOKENS` 逐 token
   放行（`0123456789ABCDEF`，公开占位常量）——该文件此后仍受扫描覆盖，
   将来加入真实地址/序列号会被拦。
3. **非 22 端口主机密钥信任判定修正**（`backend/core/ssh_security.py`）：
   `trust_host_key` 此前把裸 `ip`（22 端口）条目与 `[ip]:port` 条目混进同一
   集合比较——keyscan 对非默认端口只产出 `[ip]:port` 形态，集合恒不相等，
   即使密钥材料一致也被误判「host key changed」拒绝（诊断方向也错）。
   修为：只取与本次扫描同一 host token 的条目参与比较，且比较**密钥材料**
   （key type + key）而非整行文本。
4. **套件 import 上传豁免超时**（`frontend/src/utils/api/suites.ts`）：
   `import:` 补 `{ timeout: NO_TIMEOUT }`，与同文件 export/exportGlobal 及
   `dedup.ts` 先例一致（#1199 验收：文件上传/下载不得设 30s）。

## Alternatives

- 容器清理保留「裸 `postgres:16` 也匹配」——否：判定依据与误删面同构，
  且 #1655 已实证开发机存在手工 PG；label 是 testcontainers 官方注入的
  精确判据（本机实测 `org.testcontainers=true`）。
- `--prune` 维持直接删除、仅加提示——否：删除不可逆，`--yes` 显式确认成本低。
- ssh 侧「只比较同 token」但继续比较整行文本——否：行序/空白/注释差异会
  再次造成假换钥；密钥材料比较才是语义判据。
- 容器 `rm` 失败时不复核——否：复核是「清理是否真生效」的唯一报告口径。
