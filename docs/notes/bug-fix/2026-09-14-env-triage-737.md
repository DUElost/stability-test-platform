# 环境变量裁决收口：登记 91 项、内部声明 19 项（#737 文档切片续）

Status: implemented
Class: bug-fix

## Decision

承接 #1948（读取清单生成 + 漂移门禁），把 109 个「未登记」读取名**逐个裁决**，
并把裁决本身变成门禁规则：

1. **门禁升级为二选一**：`代码读取名 ∈ 示例登记 ∪ 内部声明`——二者之外即红；
   此外「既登记又声明」（冲突）与「声明但代码已无读取点」（陈旧）同样红。
   这样新增环境变量时**必须**显式二选一，不可能再默默变成黑盒。
2. **裁决口径**（写入工具注释，作为后续评审依据）：
   - **登记进示例**：需运维按环境/规模/机型调整的运行参数——调度节奏、批量与
     并发上限、保留期、告警阈值、外部集成（SMTP/JIRA）、认证与 Cookie、RunConsole
     多实例（ADR-0027）、部署路径、Agent watcher/磁盘/租约参数；
   - **内部声明**：控制面注入的派生键（hot-update 载荷）、运行时注入（脚本参数/
     设备序列号/sudo 变量）、测试与开发专用、纯内部实现细节。
3. **登记方式**：以**注释态**条目（`# KEY=默认值    # 用途`）追加到
   `backend/.env.example`（控制面 55 项）与 `backend/agent/.env.example`（Agent 36 项）
   ——注释态不改变任何现有部署的行为；示例文件是运维模板，这是「把默认值摆在
   手边、需要时取消注释」的最小侵入形态。

### 分类结果

| 桶 | 数量 | 说明 |
|---|---|---|
| 登记进示例 | **91** | 控制面 55（调度/批量/保留/阈值/集成/安全/Console/路径/展示/热更新）+ Agent 36（Watcher/租约/磁盘归档/注册网络/路径） |
| 内部声明（含理由） | **19** | hot-update 载荷 3（`AGENT_SECRET_B64`/`ENV_OVERRIDES_B64`/`ENV_PATH_KEYS_B64`）、运行时注入 5（`STP_STEP_PARAMS`/`STP_DEVICE_SERIAL`/`SUDO_UID`/`SUDO_GID`/`STP_AGENT_VERSION`）、测试专用 4（`FAKE_TAR_SLEEP`/`HOST_IP`/`STP_SMOKE_ORIGIN`/`STP_NOTIFY_SAQ_RETRIES`）、实现细节 7（`INSTALL_DIR`/`PRECHECK_NOTIFY_DEBOUNCE_SECONDS`/`STP_ALLOW_UNSAFE_TEST_DATABASE_URL`/`STP_ARTIFACT_DIGEST_CACHE`/`STP_DEDUP_LOG_ENCODING`/`STP_DEDUP_PLACE`/`STP_WATCHER_AEE_RECONCILE_HOSTS`） |

文档附录的「内部声明」小节自动生成（变量 + 理由），读到清单即可知道每个 `—` 的
原因，不需要回查代码。

## Alternatives

- **把 109 个全部塞进示例**：否决——注释态也会让运维模板膨胀一倍，稀释信噪比
  （`FAKE_TAR_SLEEP`、`ENV_OVERRIDES_B64` 这类键对运维毫无意义）；
- **全部声明为内部**：否决——等于没裁决：调度节奏/保留期/集成凭据这些**确实要调**
  的参数仍不在手边；
- **只登记「常用」的十几个**：否决——剩下的仍无记录，#737 的「黑盒」问题只解决一半；
- **为每个变量写人工用途文档**（登记项已在示例旁写一行用途）：超出切片；
  已用「示例注释 + 附录默认值/位置」覆盖可发现性。

## Revisit

- **注释态登记的降级/升级**：若某登记键长期无人使用且无运维语义，可降级为内部声明
  （改 `_INTERNAL_ONLY` 一行 + `--write`）；反之新出现的实现细节键若被现场使用，
  应升格登记进示例；
- **动态读取形态**（f-string/字典键名）仍不在清单内（工具头部已声明范围）；
- **`backend/agent/scripts/**` 的注入型变量**（`STP_JOB_ID` 等 11 个）按 ADR-0020
  的脚本目录契约另挂，不在本清单范围。
