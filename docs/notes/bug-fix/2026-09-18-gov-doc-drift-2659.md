## 四处判据的独立复核（均与 issue 一致）

1. **`S1–S13` 与 §3 打架**：`:29` 写 `S1–S13`，而同文件 `:54` 有 S14 行；
   权威口径是自检末行 `check_governance_surface.py:1398` 打印的「S1–S14、S5x」。
2. **lint 步数**：实测该 job 有 **16** 个具名 step（issue 在旧 tip 上数到 12）；
   文档写「五步」且漏列窗口内新增的「alembic revision 不可变检查」「上帝文件行数封顶检查」
   等——**计数与清单双失准**。
3. **行号**：`FULL_EXCLUDE` 实测在 `scripts/run_gates.py:322`（文档引 `:214`）。
4. **缺 5 门禁**：实测这 5 个名字在 deps 文档中**各 0 命中**，而在
   `run_gates.py:69,76,165,209,235` 有定义、且已入 `PROFILES` 成员表
   （`orphan-models`/`god-files` 在 `check:quick` + `check:pr`；其余三个在 `check:pr`）。

## 修法取向：**去掉会漂移的形态**，而非只是改正数字

三处改动都刻意选择**不引入新的可漂移表述**：

- **不写步骤总数**：改为「本段只列举治理/门禁类步骤，**不声称穷尽**」+「以 `ci.yml` 为准」。
  写死总数必然随每次新增步骤过期——这正是 `#2041` → `#2659` 复发的机制。
- **引符号名而非行号**：`FULL_EXCLUDE` 是语义标识，行号不是（实测已 214 → 322）。
- **§2 的版本区间仍写死 `S1–S14`**：这一处**保留**数字，因为它是规则集**上界**的声明，
  且同文件 §3 有逐条明细、自检末行有权威口径——去掉区间会让 §2 失去可读性。
  但**已在同段落标注更正来源**，使下次漂移可被 `grep #2659` 定位。

## 一处我在实施中**自己引入又修掉**的错误（留痕）

初稿我写「上帝文件行数封顶检查（**`check_god_files.py`**）」——实际文件是
**`check_god_files_ceiling.py`**。写完用「文档引用的文件名是否真实存在」逐条核对时发现并修正。

> 这正是本单要治的病（文档引用了不存在的/已变的东西）。教训：**新增引用后必须回查目标是否真实存在**，
> 而不是相信记忆中的命名。

## Alternatives

- **只把「五步」改成「十六步」** → 否决：下次新增步骤即刻再过期，等于把复发周期延长一次。
  改为不写总数才是根治形态。
- **给 `FULL_EXCLUDE` 写新行号 `:322`** → 否决：同上；issue 亦建议「只写符号名不写行号」。
- **deps 文档只补名字不给说明** → 否决：该节其余条目都有「规则 + 为什么」，只列名字会
  与本节风格不一致，且读者仍需自行读码才知道判据。
- **顺带把 §2 的区间也改成指针** → 否决：见上，§2 的区间是上界声明，有可读性价值；
  且自检末行已提供权威口径。

## Revisit

- **§2 的 `S1–S14` 仍是写死的数字**：下次新增规则（S15）时会再次漂移。若 `#2041`/`#2659`
  再复发一轮，应考虑给该区间加一条**门禁**（比对 §2 区间上界与 `check_governance_surface.py`
  的实际规则数），而不是继续靠人工同步。触发条件：同一形态**第三次**复发。
- **deps 文档的「穷尽性」未声明**：本单按 issue 的定性（「该文档未声明自己是穷尽清单，
  故按条目缺失登记」）只补条目、**未**给该节加「本节是否穷尽」的声明。若希望它成为权威清单，
  应显式声明并加门禁（比对 `PROFILES` 成员与本节条目）。
