# R13 助手 P2 收口：拒绝回执/审计/连接预检/续轮预算（#1221 #1224 #1225 #1227）

Status: implemented
Class: bug-fix

## Decision

R13（AI 助手）四项 P2 一次收口：

1. **#1221 拒绝事实未传给模型**
   新增 `orchestrator.record_rejection_receipt(action_id, decided_by)`：拒绝时向
   会话写入一条 `role="tool"` 的明确回执（「操作卡 #N 已被 X 拒绝，不会执行」）。
   路由 reject 分支在 `_enqueue_continuation` 前调用它，续轮
   `_history_as_llm_messages` 因此能看到拒绝事实，模型不再只看到「等待审批」。

2. **#1224 动作生命周期审计不完整**
   新增 `orchestrator._audit_action(db, action, event)` 统一出口，事件名
   `ai_assistant_action_{proposed|auto_approved|executing|finished}`：
   - `_create_action`：proposed（人工路径）/ auto_approved（自动 T1 路径）；
   - `execute_action`：取得执行权后写 executing；
   - `_finalize_action`：终态写 finished（含状态）。
   自动 T1 全链路自此可审计，与路由侧人工审批审计对齐、不重复。

3. **#1225 连接测试不验证工具调用能力**
   `/config/test-connection` 现在携带受控 `preflight_ping` 工具声明并要求模型
   调用；未返回 tool_calls → `ok=false` + `tool_calling_unsupported` 说明。
   只支持普通聊天的上游不再被误判为可用。

4. **#1227 自动续轮缺少累计预算**
   新增配置 `ai_assistant_config.max_auto_continuations`（默认 20，可配置）与
   会话 `ai_chat_session.auto_continuation_count`。用户发消息时计数清零；
   `_enqueue_continuation` 每次原子自增并检查上限，超限不再入队，占位收敛为
   用户可见失败（「已达自动执行链累计上限…」）。迁移 `aa11bb22cc33`。

影响面：`backend/services/ai_assistant/orchestrator.py`、`backend/api/routes/ai_assistant.py`、
`backend/api/schemas/ai_assistant.py`、`backend/models/ai_assistant.py`、
`backend/alembic/versions/aa11bb22cc33_add_ai_auto_continuation_budget.py`、
`frontend/src/{utils/api/types.ts, pages/settings/AiAssistantSettingsPage.tsx}`（配置项同步）。

## Alternatives

- #1221：让 `_history_as_llm_messages` 读 action 状态动态注入——需为每个历史
  动作查表且消息顺序仍缺「何时决定」的时序；写一条回执更简单、时序正确。
- #1224：在各调用点分别 record_audit——重复且易漏；集中 `_audit_action` 一处。
- #1225：仅断言 API 接受 `tools` 参数——不支持 function calling 的上游也可能
  200 返回普通文本，必须校验实际 `tool_calls` 产出。
- #1227：仅在单轮 `max_turns` 上收紧——单轮限制不等于整条自动链限制；必须有
  跨轮次的持久计数。计数放会话（用户消息清零）而非新建链实体，改动最小。
