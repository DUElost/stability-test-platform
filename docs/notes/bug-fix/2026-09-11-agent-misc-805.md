# Agent 杂项批收口（#805：心跳护栏 / abort 坏 id / 日志换行 / Unisoc 超时产物）

Status: implemented
Class: bug-fix

## Decision

四域审查 #805 的 Agent 杂项批，逐项落地（第 4 项 CPU 累计采样已由 #1259 修复，
本 PR 不再重复）：

1. **心跳线程 `_loop` 异常护栏（#805-1，`heartbeat_thread.py`）**
   新增 `_safe_tick()` 包裹 `_tick()`，`_loop` 两次调用点改走它——单次 tick
   异常不再杀死守护线程（否则 `effective_slots`/在线状态永久冻结、主循环按
   冻结值继续 claim 且无人重启）。对齐 `lease_renewer` 的批 tick 护栏。

2. **abort 控制坏 id 不中断整批（#805-2，`main.py`）**
   抽出模块级 `_parse_abort_job_ids(payload)`：逐项 `int()`，非法值记 warning
   后跳过，保留合法 id。原 `[int(jid) for jid in ...]` 遇坏 id 抛 ValueError
   会中断整个控制 handler，同批其它 job 的 abort 丢失且无 ack。

3. **步骤日志双换行（#805-3，`pipeline_engine.py`）**
   抽出模块级 `_append_log_line(path, line)`：`_drain_polling` 已给每行补
   `\n`，原 `_handle_line` 再 `line + "\n"` 导致每行后多一空行。现按需补尾，
   恰好一个换行。

4. **UnisocScanRunner 超时半成品上送（#805-5，`unisoc_scan_runner.py`）**
   工具按设计持续轮询、runner 到点主动终止（`TimeoutExpired` 属预期），但产物
   可能是半成品。现置 `_last_scan_timed_out` 标记：
   - `run_scan_result` 在超时场景要求产物通过 `_artifact_looks_complete`
     （非空且 0.2s 复读大小稳定），半成品返回 None 不上送；
   - `run_scan_and_upload` 超时后跳过原始 `Result_*.xls` 的二次上送（最可能
     是半成品），只保留经处理且校验通过的 org 文件。

影响面：`backend/agent/{heartbeat_thread,main,pipeline_engine,unisoc_scan_runner}.py`
+ 测试（新增 `test_agent_misc_805.py`，扩展 `test_unisoc_scan_runner.py`）。

## Alternatives

- #805-1：在主循环重启心跳线程——复杂且需检测线程存亡；tick 级护栏是 lease_renewer
  已验证的最小形态。
- #805-5：超时一律按失败处理——会破坏「轮询工具本就靠超时收口」的正常语义，
  合法结果将被丢弃。改为「校验产物完整性 + 超时降级」，既不误杀也不上报半成品。
- #805-5：解析 xls 结构判完整——需引入解析依赖且工具契约未证实（issue 标疑似）；
  大小稳定性启发式足够且无新依赖。
