# 死信端点：主机不存在 → 404，不再压成 503（#2383）

Status: implemented
Class: bug-fix

## Decision

`GET /hosts/{host_id}/log-signal-dead-letters` 与 `POST .../{row_id}/replay` 此前
**不查主机存在性**，直接把 `host_id` 丢给 `call_agent_rpc`；库里没有这台机器和 Agent
掉线被压成同一个回答：

```
GET  /api/v1/hosts/1                     → 404 host not found
GET  /api/v1/hosts/1/log-signal-dead-letters → 503 agent 1 not connected   ← 自相矛盾
```

503 的语义是「暂时不可用、可重试」，「这台主机不存在」是永久错误：UI/脚本按 503 退避
重试就是白等，排障方向还会被带去查 Agent 掉线而不是查 ID。

修法只加一次判别：`_require_host(db, host_id)`（与 `get_host` 同一文案
`host not found`，同一 404），放在**发起 RPC 之前**。不改动 RPC 的 502/503 语义。

写端点的 404 **不落审计、不发 RPC**：`#907` 建的审计面是「重放动作的可归责记录」，
而打错 ID 的请求从未尝试过任何 Agent 动作——记它会把审计变成噪声源，也等于宣称
「有人试图重放」。这条取舍写进了用例断言。

## Alternatives

- 只在 `AgentNotConnectedError` 的文案里区分「不存在 / 没连接」：否决——判别依据在库侧
  （host 表可查），放在 RPC 之后等于让 Agent 侧猜，且重试语义（408/503 vs 404）仍然错。
- 返回 410/422 之类更「精确」的码：否决，与同资源族（`GET /hosts/{id}`、`GET /plans/{id}`）
  的既有口径不一致，前端/脚本按 code 判定的约定会被撕开第二套。
- 顺带处理 `REVIEW_ADR0038` 提的「replay 端点未防守退役主机」：否决（不同问题面——那是
  权限/状态守卫，本单只修错误归因），登记在 Revisit，等 R03 那条收口时一并做。

## Revisit

- 同族缺陷还有别的端点：`#2386` 之外，凡「拿 path 里的 id 直接打 Agent RPC」的端点都可能
  把不存在压成 503。判据（进 RPC 前查存在性）适合提成一条契约测试，而不是逐个手改。
- 退役主机（`retired_at`）在本端点上仍按普通主机处理——`REVIEW_ADR0038` 已登记，
  与 #2386 那条「scan 反激活」一起属「已退役/不存在资源被当活资源」这一族。
