# 展锐 uniview 超限事件目录：整目录 pull 有界化 + 显式降级态（#2252）

Status: implemented
Class: bug-fix

- 日期：2026-09-16
- 相关：`#73`（事件源与载荷策略 Revisit）、`#740`（host 提取预算共享）、`#2079`（拉取失败不推进签名）、
  `#2272`（签名不可得 + 失败上限，本单的直接前置）

## Decision

### 1. 选 (b) 尺寸阈值 + 显式降级态，不选 (a) 增量拉取

issue 给的方向是 (a) 增量拉取 / (b) 阈值 + 显式降级态 / (c) 两者组合，并注明「最小方案待裁决」。
选 **(b)**：

- (a) 要改**工具侧**载荷协议（按 `{seq}-{ts}.tar.gz` 与事件行序号对应逐个拉），是跨端改动；
  (b) 是 Agent 侧单点，且**直接命中**本单要消除的两个形态（每拍白烧 + 永久无信号）；
- 本单的证据只支持「超限目录」这一个形态（真机 `NE.103000003` = 1.9GB / 999 文件），
  在没有「载荷本身必须随信号到达」的需求前，(a) 的收益是推测的。留作 Revisit。

### 2. 「信号照常发射」是**有意的行为变更**

改动前，超限目录的结局是：整目录 pull 反复超时 → `#2272` 的失败上限把「每拍白烧」截断成
**N 拍后永久沉默**（只留 `signals_dropped` 计数）。这正是 issue 要消除的形态。

现在：`du -sk` 探测到超过 `MAX_PULL_DIR_KIB`（256 MiB）→ **不整拉**，只取 `unievent_info`
（KB 级），本地目录按现有「内容对应当前签名」语义整体替换，随后走原发射路径——信号进风险
摘要与 DLE，载荷缺失用 `extra.payload_state = "oversized_skipped"` + `extra.payload_remote_kib`
显式标记。

理由：展锐事件的运营价值主要在**元数据**（event_type/subtype/aee_ts → 风险评级 S/A/B），
载荷是取证细节；把「永久无信号」换成「有信号且明确标注载荷缺失」是净收益。风险（下游把
元数据-only 当完整载荷）由标记控制——`extra` 是 JSONB 附加键，不改任何 API 契约。

### 3. 阈值、探测失败、与 #2272 的关系

- **阈值 256 MiB**：按 180s pull 超时与**保守**的 2 MiB/s adb 吞吐下界估算 ≈360 MiB，留一倍
  余量取半。正常事件目录（KB 级）不可能触及。
- **常量而非 env 键**：它只决定「哪些目录降级为仅元数据」，不改变信号语义与交付口径；
  与 `MAX_DIR_ATTEMPTS`（#2272）、`_MERGE_LOCAL_RETENTION_HOURS`（#2281）同口径——真有调参
  需求时再走 Settings 通道（升格须同步 env 清单门禁）。
- **探测失败（`du` 不可得）= 不知道**：回落整目录拉取。两个方向都不能猜——当成「不超限」
  会白烧，当成「超限」会静默丢载荷。
- **降级成功即 `_clear_dir_failure`**（不是失败）；**降级路径自身失败**才按原失败语义计数，
  因而仍受 #2272 的放弃上限约束。

### 4. 「每拍重烧」在降级路径上不存在

降级成功后本拍照常记 `_pending_signatures`，签名随发射写入 `_processed` → 下一拍同签名直接
短路（用例 `test_oversized_dir_degrades_to_metadata_only_and_still_emits` 的第三拍断言）。

## Alternatives

- **只做「阈值 + 跳过 + 计数」不发射信号**：改动更小，但保留「永久无信号」——issue 明确要
  消除的形态之一，也没解决「该目录长期无信号的现实解释」。否。
- **用 `ls -l` 里目录项的 size 当判据**：目录项的 size 是块大小（4096），与内容量无关，
  判不了超限。否（必须另取 `du`）。
- **让超限目录直接复用 `_dir_attempts` 走「放弃」**：那是**失败**语义，会把「载荷缺失但信号
  已发」的目录也变成沉默，与 §2 相反。否。
- **(a) 增量拉取**：见 §1，留下不做的理由与触发条件（Revisit）。

## Revisit

- **(a) 增量拉取**：触发条件是「超限目录成为常态」或「载荷本身成为必需（取证/复现）」。
  做法对齐 toolkit 的 `{seq}-{ts}.tar.gz` 与事件行序号对应逐个拉；那会同时改工具侧协议。
- **阈值是否定小**：WARNING 日志 `unisoc_reconciler_payload_skipped` 带每个目录的远端 KiB，
  首次真机跑起来后按分布复核；若命中正常事件目录，说明阈值需要上调或改成按文件数判据。
- **`payload_state` 目前没有消费方**：只在信号 `extra` 里。若要「载荷缺失率」进看板/告警，
  另立单（本单只保证状态可分辨、可查询）。
- **本地载荷替换**：若某目录先按整目录拉过（本地有完整载荷），之后超限，则本地那份会被
  替换为仅元数据——与既有「本地内容必须对应当前签名」语义一致（整目录拉取本来也是整体
  替换），不新增窗口；若将来发现上传窗口因此受影响，再议。
