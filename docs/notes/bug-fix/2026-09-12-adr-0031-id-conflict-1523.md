# ADR-0031 附录改子编号 + README 补登（#1523）

Status: implemented
Class: bug-fix

## Decision

`docs/adr/` 下两份文档共用 ADR-0031 编号（主文档「平台 AI 助手」与
「附录 A：阶段三核心业务写操作」），任何「见 ADR-0031」引用天然歧义；
README 表格漏登附录（磁盘含附录但表格无）。

**owner 裁定（2026-09-12）：附录采用子编号方案**（issue 修复方向 1 的保守
变体）——不动主文档（历史引用零影响），附录让位为子编号：

1. `git mv` 附录 → `ADR-0031-A-appendix-phase3-core-write-tools.md`——
   四位编号枚举（`ADR-\d{4}`）不再把附录当独立 ADR，计数不双计；
2. 活文档引用同步：主 ADR 两处相对链接、`PROJECT_REVIEW_PLAN.md`、
   `design/2026-08-27-platform-ai-assistant.md`、T0 Agent Note 的链接；
   历史档案（`PLATFORM_AUDIT_2026-09-11` 的事件叙述、doc-architecture
   integrity note）保留原样（带时间戳的证据，非导航链接）；
3. README 补登附录行（表格 38 → 39 条，与磁盘 39 文件一致），并在「编号
   与命名」节增补**附录规则**：「附录沿用父编号 + 大写字母后缀
   （`ADR-xxxx-A-<slug>.md`），不占独立编号、不参与编号递增」——防再犯
   （issue 的流程改进点）。

## Alternatives

- **主/附录同时改 0031a/0031b（issue 字面建议）**——放弃：主文档改号会
  破坏全部既有「ADR-0031」引用（历史 PR/注释/note），而附录让位即可消除
  歧义（主文档单调唯一）；
- **附录升格独立编号**——放弃：附录自述「父 ADR」、内容是配套决策细节，
  升格需补完整决策结构，语义不符；
- **附录移出 docs/adr/**——放弃：弱化「ADR 附录」属性，且目录惯例允许
  附录共存。

  `comm` 双向差集均为空）；补登附录后表格 39 条 == 磁盘 39 文件；
- 旧名残留：全仓仅历史档案两处（事件叙述，保留）；活文档/链接零残留；
- 主 ADR 正文两句引文（阶段三说明 + 相关文档清单）指向新子编号；
