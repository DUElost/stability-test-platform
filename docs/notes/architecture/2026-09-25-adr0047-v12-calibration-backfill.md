   `20/20`、`reserve=8`、`2s` **维持**（判据：两层均无 `kind="timeout"` 尖峰）；
2. **D1 表格**注记「已由 §4 校准确认维持」；
3. **§5** 逐条标注生效状态：参数/对外语义/文档 = 已落地（#3240）；门禁 = 已落地 + 已实装（2026-09-25 17:17
   挂 `ExecStartPre`），**启动实测待下次重启**（dry-run `app_total=80 available=97 reserve=8 headroom=17`）；
   告警 = **已生效**（09-25 17:18 副本同步 + reload，实测 40 rules / 9 groups）；
4. **defer 项改指**：`ADR-0026 §6 的终态聚合语义（P1 另立 ADR 处理）` → 指向 ADR-0052（2026-09-24 起草，Proposed，随 #3244）；

**未改**：不变量与门禁形态、D1 数值、D2 取值、D5 判据；**D3 未裁**（保留开放；其「复评触发」一行属可选，
本次未加）、D4 复评条件不变。

## Alternatives

- **按真机数据调数（例如 pool_size 20→12）**：不采纳——两层观测都没有要求调数的信号
  （真机池峰 async 4 / sync 11 vs 预算 40），为「更小」而调数会把 `reserve`/headroom 的计算前提搅动，
  且违背「只改数字要有依据」；真机的尾部延迟问题在 `/complete`（父行锁），不在池。
- **把 p99 2.47s 记进 ADR 作为「需调池」的证据**：不采纳——归因已明确（#3243 Revisit 3 + #3244 数据：
  被接纳的 `/complete` 尾部由父 `plan_run` 行锁串行段支配），记录在 §4.1 的 ⚠️ 遗留里指向 ADR-0052，
  避免把「池参数」当成其解。
- **顺手把 §4.3（非应用连接分布）也补上**：不采纳——该项**仍缺**，本次以「待办」显式保留（#3261 的验收要求
  正是「不静默丢失」），补数属另一批工作。
- **统一更新全仓 `ADR-0047 v1.1` 引用（env 文档 / 手册 / 历史 note）**：不采纳——S14 的口径就是
  「版本引用 ∈ 已发布版本集合」即合法：v1.1 引用在其语境里仍成立（不变量/判据未变），
  历史 note 按纪律保留原样；本次只动 S12 约束的索引面。
