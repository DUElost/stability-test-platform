# ADR-0037 v0.2 勘误：flash 链事实修正与退役前置（#2133）

Status: implemented
Class: architecture

## Decision

对 [ADR-0037](../../adr/ADR-0037-agent-host-privilege-boundary.md) 做 **v0.2 修订**
（`docs/adr/README.md` 主表行同步），内容是事实勘误 + 前置补记，不改 D1–D4 方向：

- **§1.2 勘误**：删去「`flash_preflight v1.0.x` 修复分支现状已不可用」的结论——
  该结论来自漏记存量文件 `/etc/sudoers.d/android`
  （`android ALL=(ALL) NOPASSWD: ALL`，install/update 链均不清理，2026-09-15
  实测 48/48 台在网）。修复与门控分支实际在用（36 次 preflight `usermod` 修复
  rc=0；487 次 flash 中 280 次 sysfs `authorized` 门控经 sudo 回落成功）。
  「本次收窄不构成回归」仅在**收窄动作**层面成立（收窄只重写
  `/etc/sudoers.d/stability-test-agent`），不再隐含「宽面已经消失」。
- **§2 新增 D5**：flash 链运行时提权收敛 = provisioning 归位（apt/dialout/udev
  在 root 期保证）+ wrapper 两个窄子命令（`ensure-udev-rule` 固定路径与内容、
  `usb-authorized` port 字符集校验 + 值 ∈ {0,1}），脚本以新版本落地；本项验收
  （无宽文件主机 flash 链通过）前不得删宽文件。
- **§4 偏差记录**：目标态不变量（NOPASSWD 面 ⊆ {固定 systemctl, wrapper}）在
  清除动作完成前不成立，如实记录。
- **§5 判据修订**：Revisit #1 退役判据改为「fleet `priv_mode=wrapper`
  **且** flash 链在无宽文件主机验收通过」；#3 由条件项（「若需恢复修复能力」）
  升为**下线前置**。
- **状态保持 Proposed**：决策者是 R02 安全联审；本轮是事实勘误与前置补记，
  不替联审做状态推进。

影响面：仅文档。执行落在 [#2133](https://github.com/DUElost/stability-test-platform/issues/2133)
（wrapper 子命令、`flash_preflight v1.0.2`、`flash_firmware v1.3.16`、
install/update 归位）与 [#2134](https://github.com/DUElost/stability-test-platform/issues/2134)
（34 台迁移 → 宽文件清除 → legacy 分支/哨兵删除）。

## Alternatives

- **另起新 ADR 而非修订**：否决——D1–D4 与方向未被推翻，需修正的是 §1.2 事实
  陈述与 §5 时序；另立会造成同一议题双 ADR 的歧义，且历史决策链断裂。
- **只改 §1.2、不补 D5/判据**：否决——退役判据不改，执行方会按旧判据在
  fleet 全 wrapper 后删宽文件，直接打断 flash 链（I4 反例实验已证：
  无宽文件主机上旧版 preflight 直接 `success:false`）。
- **勘误留到实现 PR 再写**：否决——ADR 是 #2133 的裁决载体，先勘误才让实现
  有据（AGENTS.md：方向级决策使用 ADR）。
- **顺手把状态推到 Accepted**：否决——决策者是 R02 联审；本轮不含联审意见。

## Verification

## Revisit

- #2133 验收通过（无宽文件主机 flash 链 + 真机 canary）→ 触发 #2134 的
  B/C/D 步骤；

  （#2133 核查项）→ 在 D5 子命令面补充评估后再定宽文件清除范围。
