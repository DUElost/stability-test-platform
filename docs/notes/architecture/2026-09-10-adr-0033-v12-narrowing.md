# ADR-0033 v1.2 收窄与工具接入文档对齐（#1237）

Status: implemented
Class: architecture

## Decision

**ADR-0033 升 v1.2——收窄落地优先级、登记已发生的 legacy 例外、显式化"未落地"状态**（不新立 ADR、不废弃）。落点 `docs/adr/ADR-0033-tool-kit-ecosystem-integration.md` §5：

- **§5.2 D0 与 D3 权威即刻生效**：源码不入仓 + DB script catalog 唯一运行时权威（manifest 仅发布格式、升级 = 新建 script 版本行）自本版起即约束评审与实现，**不等 tar.gz / manifest / 缓存就绪**——这两条零成本，且正是防"新族继续全量入仓"与"双版本体系重造"的关键；
- **§5.3 D2 收窄为「新工具族准入要求、按族采用」**：Tool Contract 四要素不再是"所有外部工具必须立即改造"的存量要求；既有族继续 legacy（argv + stdout JSON），迁移时机由各族 Phase 3 决定。D2 的**语义不变**（退出码命名空间、`failure_kind` 标注、双轨衔接），变的是适用范围；
- **§5.4 包存储改为条件落地 + legacy 例外登记**：tar.gz + sha256 + `tools_cache/` 作为终态出口保留，三条触发条件（第二个需版本化分发的 Tier 1/2 工具族 / 多机复制不一致或源码目录被就地修改的真实事故 / Phase 3 启动）任一出现才排期；过渡形态 = 中心存储版本化源码目录 + 路径 env 配置，**标注为过渡而非终态**。展锐三工具族（`Start-Log-Scan` / `Monkey-Log-Scan-GT-SPRD` / `Scan-Result-GT`）与 `STP_UNISOC_*` / `STP_AGENT_UNISOC_*` 路径键按 legacy 追溯承认，边界三条：不得扩散到新族、路径键必须登记进 env 清单、不得再新增工具私有 env 键；
- **§5.5 未落地状态显式化**：头部增"落地状态：未落地"行；§4 的 Phase 2/3 时间点作废为参考序；明确"决策效力与实现进度分离"——既不因超期降级决策效力，也不得把纸面 Accepted 当已落地基线；
- **§2 / §4 增指针**，使收窄结论从决策章节与阶段章节均可达。

**同批文档对齐**（同一 Requirement 的口径同步，非顺手重构）：

- `docs/development/script-versioning.md`：增 ADR-0033 指针（新族必须契约 + 包存储、既有族新版本可继续 legacy）；
- `docs/reviews/TOOLKIT_INTEGRATION_FEASIBILITY_2026-08-26.md` §6：补注「4-P1 必开新 ADR」已由 ADR-0032 承接（2026-08-31 supersede #220 并落地 UNISOC 链路），原判据保留为历史记录、不再作待办触发器；
- `docs/development/environment-variables.md`：登记 5 行 UNISOC 工具路径键（控制面源键 `STP_AGENT_UNISOC_*` → Agent 无前缀键，属 `AGENT_PATH_ENV_KEYS` 路径校验集；`STP_UNISOC_LOG_SCAN_POLL_SECONDS` 为 host 级手工键、不进 fleet 列表）——此前 4 个键代码已在用而清单未登记；
- `docs/design/2026-09-external-tools-integration-and-package-architecture.md` §5：增排期口径注（Gantt 为参考序；D0/D3 即刻生效、D2 按族准入、包存储条件落地）。

**影响面**：4 个文档 + 1 个 ADR + 索引三面（`docs/adr/README.md` 主表与 M7 看板、`docs/DOC-MAP.md`）。**零代码、零脚本版本、零环境变量行为变更**。

**明确不做**：不改 ADR-0020「每版本全量副本 + 绝对不可变」契约（膨胀病根的终态出口，属独立方向级问题——#735 长效机制先出 1 页可行性）；不改 D1/D4；不把展锐三族立即包化。

## Alternatives

- **新立一个 ADR 取代 ADR-0033**（同方向重写）：弃——无新证据推翻方向判断；`docs/adr/README.md` 维护约定是"修订用 v1.x、取代只用于方向变更"；重写一遍会切断决策史且属负复利；
- **保持 v1.1 原样**：弃——Accepted + 零落地 + 排期过期 + 例外未登记 = 索引面失真，读者会把纸面 Accepted 当作已落地基线（本仓库 ADR 索引的"状态"列不表达实现进度）；
- **废弃（Deprecated）**：弃——膨胀问题仍在恶化，ADR-0020 的复制契约需要终态出口，#735 长效机制会悬空；
- **按 D3 原计划立刻落地包存储**：弃——三条触发条件均未成立，先把过渡形态**标注**清楚比强推大工程更符合最小方案（AGENTS.md：不标注的止血会沉淀为债，标注过的过渡是允许的）；
- **把展锐三族立即包化**：弃——工具是仓库外既有源码，尚无多机复制不一致事故，"登记边界 + 禁止扩散"已覆盖风险；
- **本轮一并裁决 ADR-0020 复制契约**：弃（本轮）——那是另一个方向级问题，需先有成本/收益/迁移路径的可行性；本版只把它写进复议触发器（§5.6-3），不代答。

## Revisit

- ADR-0033 §5.4 三条包存储触发条件任一成立 → 撤销过渡形态标注并排期落地；
- 出现**第二个**使用"中心存储源码目录 + env 路径"形态的工具族（过渡形态扩散）→ 先行复议是否提前落地包存储；
- #735「差量分发 / 共享基础库」长效机制形成方向级提案 → 由新 ADR（或 ADR-0020 v2）裁决复制契约，本 ADR §5.6-3 已留下接口。
