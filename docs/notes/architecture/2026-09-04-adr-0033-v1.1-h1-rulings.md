# ADR-0033 v1.1：三项合入前必答裁定的写入与 #840 冲突解决

Status: implemented
Class: architecture

## Decision

ADR-0033 升 v1.1，写入平台健康审查（`docs/reviews/PLATFORM_HEALTH_REVIEW_2026-09-03.md` §6）判定为「合入前必答」的三项裁定（用户逐项确认）：

1. **H1-1 与 ADR-0032 权威分家（非 supersede）**：ADR-0032 拥有行为权威（platform 路由 / mtk-unisoc 分区 / 按分区双 merge 循环 / 归档语义），ADR-0033 拥有结构权威（打包分发 / 调用契约 / 胶水归属）。Phase 2 展锐样板定位 = 在 ADR-0032 已建的 per-platform merge 循环内为 unisoc 分区加装第一个 `DedupMergeEngine` 实现；Phase 3 存量归一验收 = 行为等价（watermark / 发布中心路径 / 产物注册不变）。落点：ADR §1.1。
2. **H1-2 契约翻译在 Agent 边缘（设计文档 §2.5 双轨运行声明）**：退出码命名空间分层——工具作者只拥有 `{0,1,2}`，`≥124` 为平台执行器保留（124 wall / 125 stall，`pipeline_engine.py` 现状），`3–123` 与信号死亡 = 工具缺陷按环境类；终态映射用 `failure_kind` 标注字段（step_trace），**不新增状态机终态**；`--check-env` 以退出码为权威（0 就绪 / 2 未就绪），Tier 3 挂 Agent 步骤启动前 precheck 槽位、Tier 1 由 SAQ 自调；双轨分级准入——新工具族必须契约化，既有族新版本目录可继续 legacy 至 Phase 3（D0 执行细则）。控制面状态机零改动。
3. **H1-3 DB script catalog 唯一运行时权威**：`tool_manifest.yaml` 降格为发布格式，注册时编译进 script 行（沿用 #171 `capabilities.json`→JSONB 编译入库先例）；升级工具包 = 新建 script 版本行（`content_sha256 := tarball sha256`，保 ADR-0023 溯源）；422 不可变 / 退役 409 守卫零新机制复用；CI 门禁 Git/NFS 分工——PR 门禁只做 manifest schema lint + 已登记条目 append-only，tarball 存在性与 sha256 校验在注册时 / Agent 拉取时 / 控制面周期巡检（GitHub runner 无 NFS 访问）。落点：ADR D3 + 设计文档 §3.3。

同步项：索引四处（`docs/adr/README.md`、`docs/DOC-MAP.md`、hub `docs/README.md`、根 `CLAUDE.md` 决策表）、storage-roles `tools/` 段两处、AGENTS.md scan/merge 段 #291 过时描述修正（健康审查 §7-1 同源漂移）。

**与 PR #840 的冲突**：#840 合入版本的 D3 写「工具版本由 Manifest 统一权威解析」，与上述 H1-3 确认裁定相反；本 PR 改写为 DB catalog 唯一权威（保留 `script:<name>` 不变量表述），**不回退 #840 的其余修复**（其已修掉健康审查大部分 H2 失真：Z2581→unisoc、secrets 分层注释、124/125 归因、check-env 判据、§1.1 承接关系雏形、D4 接口收窄、support_files_manifest 语义扩展声明）。

## Alternatives

- **manifest 独立成第二套版本权威**（#840 实际走向）——弃：422 不可变 / 409 退役守卫 / sha 溯源全部要重造一遍；DB catalog 权威 + manifest 发布格式零新机制。
- **控制面集中翻译契约**——弃：Job/PlanRun 状态机与 ADR-0026 四层调度全部感知契约，震荡面大；Agent 边缘翻译可按 script 行灰度。
- **git submodule / 私有 PyPI 作包载体**——弃：外部二进制与 APK 不适合进 Git、非 Python 工具装不进 wheel；NFS tar.gz + sha256 语言中立且复用中心存储。
