# ADR-0033 §5.4 包存储触发重评（2026-09-22·多站点）

Status: implemented
Class: architecture

## Decision

**结论：已触发。** 用户裁定（2026-09-22）：**多站点部署 = ADR-0033 §5.4 触发**。
理由：多站点是「平台代码 / 镜像」与「外部工具资产」物理解耦的需求来源——各站独立交付时，
若继续靠人肉同步中心 `tools/` 源码目录或把工具合入平台仓，会持续腐化平台主干并放大漂移面。

本评估把该裁定落成 §5.4 **第 4 条**触发条件（ADR-0033 **v1.11**），并撤销
「触发前不得排期」。条件 1–3 在 2026-09-20 快照下仍可不成立；**任一**条件成立即可排期。

**本 PR 不实现** Package Store 代码（`tar.gz` / `tools_cache` / 注册流）。实现跟踪
[#3075](https://github.com/DUElost/stability-test-platform/issues/3075)。

历史「未触发」快照（条件 1–3 对账）保留于
[`2026-09-20-adr0033-package-store-trigger-assessment.md`](./2026-09-20-adr0033-package-store-trigger-assessment.md)
（该文结论作为**当日**事实仍成立，已被本评估在索引面上取代为最新锚）。

## 2. 为何多站点足以触发（而不等条件 1–3）

1. **独立站点 = 独立中心存储**：每站各有一份 `tools/`；无内容寻址身份时，站点间只能靠目录复制，漂移成本随站点数线性放大。
2. **平台镜像 ≠ 工具资产**：多站点交付要把「可版本化的平台发布物」与「可 pin / 可校验的外部工具包」分开，否则工具小修会逼平台发版，或反向把工具树继续合入主仓。
3. **防腐出口**：D0/D3 权威已生效，但分发机制若继续停在源码目录过渡态，多站点运维会把过渡写成事实终态——与 §5.4「标注过的过渡」纪律冲突。
