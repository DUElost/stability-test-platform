# ADR-0051 v1.3：manifest 族级 kind 字段——python:null 二义的根因修复（2026-09-24）

Status: implemented
Class: architecture

## Decision

Phase 4a 的 `--python-absent` 让外部工具族也以 `python: null` 登记，把「null = 平台脚本族」
这个隐含约定击穿了：`script_catalog.script_entries` 按「任一 python null」判族，展锐两族被
误注册进 `script` 表（scan created=3 现场暴露）；`check_script_packages` 的族归类退化为
树集反推，ghost 保护（kind=script 族被整树删除）移交 PR 评审。

本单落地 ADR-0051 D8 预告的正解——**族级 `kind` 字段**：

- `tools[name]` 由 `{versions}` 变 `{kind, versions}`，`kind ∈ {script, tool}`；
  **C5 版本六元组不动**（kind 在族级，不是版本条目字段——不触 #3075 的"分发面与契约面禁混装"裁决）；
- lint：kind 必填 ∈ {script,tool}；族级 kind 不可变（base 无 kind = v1.3 迁移补写，合法）；
- `package_tool_asset --kind`（默认 script）；`script_entries` 只注册 kind=script；
- `check_script_packages` 归类 kind 驱动：kind=script 无树 → **恢复判红**
  （Phase 4a 移交人工评审的 ghost 保护由机器精确回收）；kind=tool 无树豁免；
- 存量 38 族显式迁移：35 script + `Start-Log-Scan` / `Scan-Result-GT` / `Monkey-Log-Scan-GT-SPRD`
  = tool；归类用 `git ls-files` 族名集交叉校验（无"有树标 tool"或"无树标 script"）；
- 站点 `packages/manifest.json` 副本由 publish 再生——`tool_cache._entry_for` 不读族结构，
  旧副本兼容、无需 fleet 动作。

生产数据清理（合入后部署清单）：`script` 表两行 Unisoc 误建行 admin `PUT is_active=false`
软退役（scan 新逻辑不再注册 tool 族，这两行会以 unregistered_active 报告直至退役）。

## Alternatives

- **`schema_version` bump 到 2**：弃——kind 是族级新增，旧消费者（resolver）不读族结构即可兼容；
  bump 反而制造"两版并存"的读面分裂，与治理方向相反。
- **继续用树集当 kind（Phase 4a 现状）**：弃——归类事实应由**登记面显式声明**（"声明即事实，
  随 PR 被审"，#3014 案 3A 同思路）；树集推断对 `--python-absent` 外部族是错的。
- **把误建的 Unisoc script 行直接 DELETE**：弃——行可能已被 plan/trace 引用，
  软退役（is_active=false）+ 409 守卫链路是既有语义。
