# 脚本版本膨胀终态可行性（#735 长效机制）

Status: implemented
Class: architecture

## Decision

产出 1 页可行性 [`docs/reviews/SCRIPT_VERSION_BLOAT_ENDGAME_FEASIBILITY_2026-09-10.md`](../reviews/SCRIPT_VERSION_BLOAT_ENDGAME_FEASIBILITY_2026-09-10.md)，回答 #735 §2「长效机制（差量分发 / 共享基础库）」是否值得立项，并给出四条路径的裁决：

- **量化基线**：`backend/agent/scripts/` 110 个版本目录 / 67,288 行，其中仅 14,475 行属各工具族最新版本，**复制冗余 52,813 行 = 78%**（`flash_firmware` 一族 16 版本 / 20,987 行，最新版 1,802 行）；
- **本质判据**：任何削减方案先要回答"历史版本还需不需要被**重新执行**"。当前**两侧都无证据**——仓内既无"重跑历史版本"的流程/需求记录，也无"保留全量副本直接导致故障"的记录；膨胀代价目前只体现为行数、评审噪音与 Agent 上下文成本；
- **P2「共享基础库」明确不做**：它把 78% 的空间成本换成"语义耦合 + sha 契约扩展"——一次库变更会同时改变所有引用它的历史版本的行为（除非逐版本 pin，等于复杂度转移），且 `_` 前缀辅助文件**连 entry sha 都不计**（`check-script-version-immutability.py` 头注自陈），共享库会把这一盲区从"辅助文件"扩大到"整个公共面"，与 ADR-0020 的立意相反；
- **P1「不可变契约收窄为『直至零引用退役』」= 本议题唯一值得新 ADR 的部分**：允许物理删除零引用已退役版本的目录（Git 历史 + 归档承担溯源），它是唯一能在**不触碰执行语义**前提下削减仓内行数的动作，其前置机具（引用计数诊断 + 退役）正是 #735 本体；要动则需同 PR 修订 `AGENTS.md` 硬不变量与 ADR-0020 契约 + 门禁判据；
- **P3「差量/打包分发」不重复立法**：与 ADR-0033 D3 包存储同向，归其 §5.4 条件落地轨道（ADR-0033 v1.2 §5.6-3 已留接口）。

**本轮不做**：不删任何版本目录、不改门禁、不动 ADR-0020 契约文本、不跑生产库统计（`plan_step` 引用分布与 47 个零引用活跃版本的行数占比列为待验证项）。落点：本次仅新增 1 份 review 文档 + 本 note。

## Alternatives

- **直接按 P2 立项**（把公共逻辑抽到 `scripts/_lib/`）：弃——收益未被量化（重复部分相似度未知），成本确定且波及 sha 契约、扫描器、verifier/self-heal、CI 门禁与 `plan_step.script_sha` 语义；把"每版独立可校验"换成"跨版共享可变面"，方向与 ADR-0020 相反；
- **直接按 P1 落地（删目录）**：弃——它要改 `AGENTS.md` 硬不变量（"已发布版本目录不可原地修改或删除"）与 ADR-0020 的不可变语义，属方向级变更，必须先有 ADR 而不是先有 commit；
- **什么都不做（连可行性也不出）**：#735 §2 已把该问题写成待决项，无文档承载会让它每季度被重新提出一次（"要不要新起 ADR"这类问题本身即重复成本的证据）；1 页纸的成本远低于重复讨论；
- **并行核查生产库 `plan_step` 分布以定论**：弃（本轮）——本机可能同时是生产库宿主，只读统计属 #735 / 生产诊断纪律范围，本文只登记为待验证项并给出判据。

## Verification

- 量化数据（命令见 review 文档附录，均在本 worktree 复现）：版本目录 110、工具族 32、`.py` 199 文件 / 67,288 行、最新版本合计 14,475 行、复制冗余 52,813 行（78%）；`flash_firmware` 16 版本 / 20,987 行（v1.0.0 344 行 → v1.3.11 1,802 行）；
- 机制证据（只读）：`tools/dev/check-script-version-immutability.py` 头注（2026-07-31 事故与 `_` 前缀盲区）、`backend/services/script_catalog.py` 的 `content_sha256` 快照语义（sha 不一致只记 `conflicts`、不动 DB）；
- 门禁：`venv/bin/python tools/dev/check_governance_surface.py --check` → `[OK] 治理面结构检查通过（阻塞项全绿：S1–S12、S5x）`；`venv/bin/python scripts/run_gates.py check:quick` → `[OK] check:quick (7 gates)`；
- 未跑：真机、生产库只读统计、backend/frontend 全量测试——本变更纯文档。

## Revisit

- 出现**真实的"重跑历史版本"需求**（例如某专项要求以旧版本复现历史 run）→ P1 的判据反转，改走 P2/P3 并重估组合 sha 成本；
- #735 退役闭环完成后，若"零引用版本行数占比"显著（例如 > 30%），P1 的收益即可量化，届时推动新 ADR；
- ADR-0033 §5.4 包存储触发条件成立 → P3 随该轨道落地，本文 P3 行需回头对齐（避免两处描述分叉）。
