# ADR-0036 定稿：评审确认 D1–D9 无修订（#1166）

Status: implemented
Class: architecture

## Decision

#1166（ADR-0036 通知投递语义契约评审与定稿）：把 ADR-0036 从 Proposed v0.1
推进到 **Accepted v1.0**，同步索引与落地状态。

**评审结论（D1–D9 逐项确认，无裁决修订）**：

1. D1 success=ACCEPTED≠DELIVERED、协议码不入正文——维持；
2. D2 三态失败（REJECTED_PERMANENT / REJECTED_TRANSIENT / UNKNOWN，
   UNKNOWN≠TRANSIENT）——维持；
3. D3 网络投递强制显式 deadline（数值属实现）——维持；
4. D4 retry owner=SAQ 唯一 + 投递级幂等成对硬约束——维持；
5. D5 统一 retry 策略（UNKNOWN 计入退避与上限）——维持；
6. D6 投递事实落 DB、词表向前兼容——维持，**附澄清**（见下）;
7. D7 at-least-once + 每通道去重键、不承诺端到端去重——维持；
8. D8 同步仅限管理员连通性测试——维持，**附澄清**（见下）;
9. D9 adapter 归一化、新渠道不得自定义成功——维持。

**两处 editorial 澄清**（不改裁决，只消歧）：

- D6：小写状态词是**投递生命周期**、大写结果是**单次尝试结果**——一次投递
  含多次尝试，实现把尝试结果归并进生命周期，两层不得混用同一列；
- D8：D6 的落库义务约束生产投递（D4 异步路径）；管理员连通性测试不写投递
  事实表（结果仅接口反馈 + 审计日志）。

**落地状态校准（§5）**：#1120 / #1117 / #1122 三个缺陷单均已关闭；其中 #1117
的**ADR 语义级验收**（统一 retry owner / 投递级幂等 / 投递事实持久化 = D4–D7）
未完成，由 #1167 台账 P2–P5 承接（#1122 属 D3 的字段级落地，非 D4 队列边界
定案）。

## Alternatives

- 本次评审提出裁决修订：九项逐条复核后无可修订项（ADR 的「不写协议码/参数
  数值」边界恰恰是它能跨渠道稳定的原因）；clarification 用追加条目而非改写
  原文，保留 v0.1 的决策痕迹；
- 保留 Proposed、等 #1167 实现完成再 Accept：与 ADR 流程（Accepted = 作为
  当前基线执行）相反——实现必须先有基线契约，否则重演「#1117 各自发明成功
  定义」的教训；且 #1167 自述 P3/P5 阻塞于本单。
