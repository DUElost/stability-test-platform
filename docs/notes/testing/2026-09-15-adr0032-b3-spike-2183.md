# ADR-0032 B3 spike 执行：UNISOC 复用 MTK merge 工具已验证（#2183）

Status: implemented
Class: testing

## Decision

执行 ADR-0032 §B3 的五项 spike 验收（`docs/adr/ADR-0032-…md`），把 D3「UNISOC **复用同一**
merge 工具」由**未验证断言**转为**已验证**。结论：**D3 成立**，ADR 升 v0.8。

### 五项验收实测结果

| # | 验收项 | 结论 |
|---|---|---|
| 1 | 15 列 `aeeexp` 同构 | ⚠️ **列数同构，两列命名有差异** |
| 2 | `{host_id}_Result_*_org.xls` 可注册 | ✅ |
| 3 | 分平台 merge 试跑 | ✅ |
| 4 | 双 merge 产物均发布 | ✅ |
| 5 | 无 `_org` 后缀产物不进 merge glob | ✅ |

### 第 1 项的精确化（本次 spike 的核心产出）

ADR 原文写「15 列 `aeeexp` **同构**」。实测两平台**均为 15 列**，但**两列命名不同**：

| 位置 | UNISOC | MTK |
|---|---|---|
| 第 6 列 | `ExpType` | `ExpType␠`（**尾随空格**） |
| 第 14 列 | `DeviceCount` | `DeviceId` |

- **抽样 40 UNISOC + 40 MTK**（盘上计 853/320），**各自表头 100% 一致**——差异稳定，非偶发；
- **merge 工具能消费该输入**，且**输出表头统一为 MTK 形态**（实测输入 15 列 → 输出 15 列，
  差异恰为上述两列）——即**工具内部已做列名归一**，「同一工具」成立；
- 但若把「同构」读作「列名逐一相同」，该表述**不准确**。已在 ADR 中精确化。

## Alternatives

- **不执行 spike，仅维持「待验证假设」** → 否决：2026-09-15 owner 裁决（D-1a/D-1b/D-1c）
  已把 B3 **升格为下一里程碑门禁**，且明确「完成前任何依赖『双平台 merge 均可用』的容量/
  超时预算结论必须标注未验证」；不执行的代价是**下游预算结论持续悬空**。
- **只做静态比对（读列数不下发工具）** → 否决：列数相同**不足以**证明「同一工具可消费」——
  语义错位（如 `DeviceCount`↔`DeviceId`）正是静态比对看不见的风险；本 spike 的实际价值
  恰在于证明**工具能归一**。
- **经控制面 HTTP 全链路跑（`run_merge_sync`）** → 本版未做：需构造完整 PlanRun/产物
  登记链路，成本远高于「验证工具能力」这一 B3 的核心问题；**记为 Revisit**（见下）。
- **把「列名差异」直接判为 D3 不成立** → 否决：工具输出已归一，事实层面「同一工具」成立；
  差异影响的是 ADR **措辞精度**而非决策，故精确化表述而非推翻 D3。

## Verification

- **列数**：UNISOC/MTK 输入各 15 列（`xlrd` 读取 `ncols`）；
- **表头差异**：40+40 抽样各组内 100% 一致；两平台差异恒为 `ExpType`/`DeviceCount`（UNISOC）
  与 `ExpType␠`/`DeviceId`（MTK）；
- **工具可消费**：UNISOC 输入经 `-merge_files_list` 实跑成功，产出
  `Result_MergeFiles_org.xls`（285 行）+ `Result_MergeFiles.xls`（4 行）+ `statistics.txt`；
- **输出归一**：merge 输出表头 = MTK 形态，与输入差异恰为上表两列；
- **MTK 对照**：同形执行成功（5 行 / 2 行），两平台产物**结构一致**；
- `python tools/dev/check_governance_surface.py --check` → **S1–S14、S5x 全绿**
  （含 S12：ADR-0032 头部 v0.8 ↔ README 主表 ↔ M7 看板行同步）；
- **未跑**：控制面 HTTP 全链路（见 Revisit）；Z258 真机验收（B3 之外，保持原状）。

## Revisit

- **平台侧发布路径未验证**：本 spike 验证**工具能力**，未验证 `merge/unisoc/` 在
  **平台侧**（`run_merge_sync` → `PlanRunArtifact` 登记 → 发布）的端到端路径。
  触发：首次真实 UNISOC run 走完归档链时，按 `run_context.merge_platforms`（PR #2174 新增）
  核对分平台产物。
- **列名归一的长期风险**：该归一**未见于文档**、属工具内部行为。若工具改版或侧参数变化，
  可能出现「列数仍 15、语义已错位」的**静默失败**。触发：工具升级或新增平台时，
  以「输出表头比对」为验收项重跑本 spike。
- **Z258 真机验收**：Watcher 冒烟 + 归档端到端仍未执行（B3 之外，ADR §验收清单原状保留）。
