# 前端导航二期：三组收敛 + 三级频率分层（v1.2/v1.3）

- 日期：2026-08-28
- 类型：feature（信息架构治理二期）

## 决定了什么

在 [PR #503](https://github.com/DUElost/stability-test-platform/pull/503)（方案 A）合入后，用户两次实测反馈驱动两步演进（方案文档 v1.2/v1.3，[`FRONTEND_NAV_IA_REDESIGN_2026-08-28`](../../reviews/FRONTEND_NAV_IA_REDESIGN_2026-08-28.md)）：

1. **v1.2 三组收敛**：7 组 → 工作区 / 资源与成果 / 平台管理，并引入**默认折叠**（非活跃组只显示组名，`aria-expanded` 语义开关；路由切换自动展开活跃组，仅挂载时初始化一次、此后用户手动开合优先）。
2. **v1.3 三级频率分层（定稿）**：
   - 一级（高频常驻）：工作区（仪表盘/项目登记簿/Plan 管理/执行 Plan/执行记录）、分析报告（测试结果/问题追踪）；
   - 二级（中频折叠组）：资源（主机集群/物理设备/脚本库/文件服务器〔adminOnly〕）；
   - 三级（低频收角落）：更多功能折叠组（WiFi 资源池/定时调度）+ **用户管理/通知管理/审计日志/系统设置移入右上角 UserMenu 下拉**（与文档/修改密码同层）。
   - 首屏一级视觉约 11 行（对比方案 A 前的 7 组 17 项约 24 行）；路由 path 全保持。

## 放弃的备选

- **维持 v1.1「admin 入口单一来源=侧边栏组」原则**：撤销——单一来源让位于频率分层；admin 低频管理页与账号域同属三级入口（用户明确指定移回下拉）。
- **继续组内重排**：用户点名批评「并非因为对当前界面已有大量改动而不往分层方向想」——IA 演进以使用频率为第一判据，不迁就既有改动量。
- **「项目」独立一级**（v1.1 Q2）：覆盖——并入工作区组内首位，保留语义位置（ADR-0029:329 历史决策不动）。

## 如何验证

- `tsc --noEmit` 0 错误；eslint `--max-warnings 0`；全量 vitest 85 文件 621 用例通过。
- 浏览器实测（开发态 + 演示数据）11 项全过：四组结构、「平台管理」组移除、WiFi 资源池不在一级可见、活跃组自动展开（`aria-expanded` 语义核验）、UserMenu 下拉含文档/修改密码+四管理页+退出登录。
- 注：折叠态核验须用 `aria-expanded`——Playwright `isVisible` 不计 `max-h-0` 祖先裁剪，会误报可见。

## 何时重议

- 页面使用频率发生实质变化（如 AI 助手上线后高频工具入口调整）时按同法重分层。
- 二级/三级组内新页面默认入对应频率组；出现新的高频页面才动一级。
