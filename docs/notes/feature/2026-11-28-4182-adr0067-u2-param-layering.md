# Agent Note: ADR-0067 U2 — 五层参数合并序、统一判定集、v2 确认指纹、快照冻结与 `log_prepare@1.1.0` 种子默认（#4182 Phase 3）

Status: implemented
Class: feature
Issue: #4182
Date: 2026-11-28
ADR: ADR-0067（Accepted v1.0，D2–D5 / §5 U2）

## Decision

按 ADR-0067 v1.0 §5 U2 实施后端五层参数合并引擎、统一 `#2649` 有效判定设备集、`stp-l1-v2:` 确认指纹、`plan_snapshot["project_log_profile"]` 顶层不可变冻结、L1/L2/L3 投影扩展与 `log_prepare@1.1.0` 种子默认：

1. **唯一五层参数合并序与 Schema 强校验（`backend/services/script_params.py`、`backend/services/plan_dispatcher_core.py`、`backend/api/routes/scripts.py`）**：
   - `merge_effective_params` 升级为 `schema_default < script_default < project_preset (仅非 null 键且仅作用于 log_prepare) < step_override (保留显式 null 覆盖)`；
   - `validate_params_against_schema` 增补 `nullable`（放行 `aee_mode`/`mtk_sublog_cmd` 显式 `null`，继续拒绝非空字段 `null`）、`minimum`/`maximum`、`pattern` 与 `array`（`minItems`、`items`、`required_items`）校验；`scripts.py` `_VALID_PARAM_TYPES` 同步允许 `"array"`；
   - 第 5 层 `inject_wifi_params` / `inject_network_params` / `inject_suite_params` 采用显式填空谓词（绝不把布尔 `False` 视为空值），保持既有空串/`0` 填空与 `#975` 冲突硬拒优先序完全兼容。
2. **叶服务 `backend/services/project_log_profile.py`（ADR-0067 D3）**：
   - 提供 `partition_serial_conflict_devices`，供 `preview_plan_dispatch_sync` 与 `prepare_plan_run` 共用同一 `#2649` `serial_conflict` 拆分口径（全冲突时两处统一拒绝；部分冲突时 `preview["device_ids"]` 保留原始请求集，两处均只对 `evaluated_device_ids` 做归属一致性判定，消除确认环死锁）；
   - 提供 `resolve_project_log_profile_for_dispatch`（五条件判定 + 单次 `READ COMMITTED` 归属读快照）与 `resolve_project_log_profile_static`（无目标设备静态 L1 投影产出 `pending_devices`，对无效/SEED/ARCHIVED `project_key` 返回 `skipped_project_inactive` 而不返回 404/409）。
3. **v2 确认指纹与无环锁序（`backend/services/plan_confirmation.py`、`backend/services/plan_dispatcher_sync.py`、`backend/api/routes/plans.py`）**：
   - 升级至 `stp-l1-v2:` / `stp-plan-confirmation-v2`，拒绝旧 `stp-l1-v1:` 与 `pending_devices`；受控 `project_log_profile` 块仅在 `applied` 时纳入 `log_profile_version` 与规范化 `effective_profile`；
   - `load_plan_graph_for_confirmation` 按固定无环锁序 `Plan (FOR SHARE) -> TestProject (FOR SHARE)` 锁定并与 `update_project` 的 `TestProject (FOR UPDATE)` 配对；
   - `preview_plan_dispatch_sync` 与 `prepare_plan_run` 各自单次调用 `resolve_project_log_profile_for_dispatch` 并复用结果。
4. **快照顶层冻结与 L1/L2/L3 投影对齐（`backend/api/schemas/plan_parameter_projection.py`、`backend/services/plan_parameter_projection.py`、`frontend/src/utils/api/types.ts`、`frontend/src/components/parameters/draftParameterMerge.ts`、`frontend/src/components/parameters/ParameterProjectionList.tsx`、`tests/fixtures/plan_parameter_merge.json`）**：
   - `build_plan_snapshot` 写入顶层 `plan_snapshot["project_log_profile"]`，绝不改写 `plan_snapshot["steps"][i]["params"]`；`build_lifecycle_from_snapshot` 只消费冻结块，不回读活表；缺键历史快照按未启用兼容；
   - `ParamSource` / `ParameterSource` 扩展为五值（新增 `project_preset`），`DraftParameterProjectionIn` / `DraftParameterProjectionRequest` 新增可选可空 `project_key`（维持 `extra="forbid"`），共享夹具 `tests/fixtures/plan_parameter_merge.json` 覆盖 6 项 ADR-0067 用例并钉死 `log_prepare@1.1.0` 容量边界。
5. **`log_prepare@1.1.0` 发版登记与幂等种子迁移（`tool_manifest.json`、`backend/alembic/versions/a67u2b3c4d5e6_seed_log_prepare_v110_defaults.py`）**：
   - 通过 `check_script_packages.py --register log_prepare 1.1.0` 登记新版本（不改脚本执行逻辑，不动已发布 `log_prepare@1.0.0`）；
   - 新增幂等 Alembic 迁移 `a67u2b3c4d5e6`（`down_revision = b12u4a1b2c3d4`，自包含内嵌 `#942/#2055` `_raise_if_any_version_referenced` 引用保护）写入权威 `param_schema` 与 `default_params`；`POST /api/v1/scripts/scan` 经既有 `changed_from_empty` 路径补齐 `capabilities`/`package_sha256` 且永不覆写默认参数；
   - 在 `tests/test_pipeline_template_script_pins_2865.py` `EXCEPTIONS` 登记 `script:log_prepare` 遮蔽窗口临时豁免（pin 维持 `1.0.0`，删除条件写明待 U2 生产 `--publish` + `scan` 激活后由 U3 追平 10 套模板至 `1.1.0` 并移除）。

## Alternatives

- 在 `plan_dispatcher_core` 内直接查询 `TestProject` 与 `ProjectModel`：会破坏 `build_lifecycle_from_steps` / `build_lifecycle_from_snapshot` 纯函数边界并制造跨服务环依赖；拆出零服务依赖的叶模块 `backend/services/project_log_profile.py` 保持 `.importlinter` C1/C5 零违规。
- 原地回填 `log_prepare@1.0.0` 的 `default_params`：违反 `AGENTS.md` 硬不变量与 `#942` 种子迁移治理，改为按 ADR-0067 D2.6 登记 `1.1.0` + 种子迁移。
