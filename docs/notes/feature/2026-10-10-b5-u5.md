# B5-U5 首批十族参数说明：内容登记表与逐版本溯源

Status: implemented
Class: feature

> 交付形态：本单元以 **draft PR** 交付内容供逐族复核；Owner 尚未指定熟悉脚本的复核人（§3.6 合入闸门），
> 因此「已实施」只指登记表与内容测试已落地并实跑，不含内容复核通过，也不含生产激活（§5 一次部署后生效）。

## Decision

实施 [批次 B5 方案 §3.3/§3.6/§4.2（#3653 正文 v1.2）](https://github.com/DUElost/stability-test-platform/issues/3653)
的单元 U5（[#3658](https://github.com/DUElost/stability-test-platform/issues/3658)）：为 §3.6 选定的首批十族
建立 `backend/schemas/param_docs/<script_name>.json` 中文参数说明，格式与解析规则完全沿用 U1 已合入的
登记表框架，本单元不改 loader、不改投影、不改执行。

首批边界按方案给定，实施者不扩族：`check_device`、`ensure_root`、`aee_prepare`、`unisoc_probe`、
`monkey_teardown`、`flash_firmware`、`monkey_check`、`monkey_launch`（引用量前八族）+ `monkey_setup`、
`connect_wifi`（D4 安全覆盖族）。指定版本共 19 个 (族, 版本) 组合。

条目取值规则（本单元的选择，逐条对应 §3.3）：

- **路径按读取面取叶子键**：说明写在脚本实际 `get` 的键上；嵌套对象（`monkey_setup` 的步骤配置、
  `connect_wifi` 的 `wifi` 组）写成段数组，例如 `["wifi","password"]`，与字面键 `["wifi.password"]`
  不相等（§3.3 反例）。
- **数组位置不绑定**：R2 把「数组元素的嵌套路径」交给首批内容验收约定。本批的约定是**说明挂在容器键**
  （如 `push.files`、`pull_paths`），元素形态写在 `meaning` 里，登记表不出现整数段——元素数量随计划
  变化，按下标登记会随漂移失效。内容测试对这条约定有守卫（`test_nested_key_lookup_uses_string_int_segments`）。
- **通用条目只用于「该族每个版本都读这个键」**：由发布源码逐版本取证得到键的首次出现版本；只在部分
  版本出现的键一律给 `version_range.min_inclusive`，让更早版本回落到 schema/键名，不把后一版才有的
  含义套到旧版本。
- **同键跨版本含义变化用「通用 + 一条范围」或两条互不重叠的范围**：`flash_firmware.pre_reboot_wait_seconds`
  在 1.3.3 从「重启后 sleep」改为「发重启前的提前量」，用 `[1.0.0,1.3.3)` 与 `[1.3.3,∞)` 两条；
  `monkey_setup.wifi.ssid/password` 在 2.3.13 起按单个 shell 参数转义，通用条目只讲含义、范围条目补转义事实。
- **无参数族不给空说明**：`aee_prepare` 登记 `entries: []`，其 1.0.0/1.0.1 发布源码只 import
  `adb_path/device_serial/output_result`，既不取 `params()` 也不引用 `STP_STEP_PARAMS`（见内容测试
  `test_aee_prepare_is_a_no_param_family` 的判据）。
- **敏感只标口令**：首批只有 `monkey_setup ["wifi","password"]` 与 `connect_wifi ["password"]` 标
  `sensitive: true`；内容测试断言这两处之外没有敏感条目，避免把普通参数掩成不可确认。

条目文字的三条取舍（第 1 轮十族内容复核后收紧，见「Verification」）：

- **「读了这个键」不等于「这个旋钮生效」**：说明必须写该版本里这个值的**实际去向**。例：`monkey_setup`
  2.3.13 的 `fill.timeout_seconds` 被 `step_fill` 读出并传给内部分块写盘函数，但该函数不使用这个入参
  ——每块固定 120 秒、容量回读固定 10 秒、循环无总 deadline，故说明写成「当前版本不生效」，不得写「等待上限」
  并把用户引向调它。同理 `install.required_version` 是**安装前**的短路判据（且为子串命中），不是装后校验。
- **不得把设计意图写成参数能保证的性质**：`unisoc_probe` 的「刻意不执行任意命令」是脚本自身的命令集设计，
  但 1.0.1 把 `extra_paths` 原样拼进设备侧 `ls` 命令、无路径校验也无引号化，因此说明里撤去「只能增加被 ls 的
  路径」这类保证，改写成可观察到的风险事实。脚本侧修复属另一个发布单元，不由说明代替。
- **注入渠道要写准落点**：平台派发期的 WiFi 注入写的是**步骤参数**（`inject_wifi_params` 填
  `step.params.ssid/password` 与 `step.params.wifi.ssid/password`），主机环境变量只是脚本自己的兜底；
  说明不得写成「注入的是 STP_WIFI_*」。

## Alternatives

- **把说明写进各脚本版本的 `param_schema`（ADR-0060 方案甲）**：被 `plan_step` 引用的版本不可原地改，
  补一句说明要发新版本、重指 Plan、过激活闸门，并加重版本膨胀（#735）。本批不采纳，沿用方案乙的代码登记表。
- **所有条目都不带 `version_range`（一把通用）**：省字面量，但会把 1.0.2 才有的「重试预算」含义套到
  1.0.0，把 1.3.3 才改的 `pre_reboot_wait_seconds` 语义套到旧刷机版本——正是 §3.6 禁止的「因同名而给所有
  版本通用说明」。不采纳。
- **用流水线模板（`backend/schemas/pipeline_templates/*.json`）作为键的事实源**：模板只给少量步骤显式
  填参（monkey 模板多为 `params: {}`），拿它当覆盖面会漏掉脚本真正读取的键，且模板版本与 Plan 现行
  引用会各自漂移。本批只用它交叉核对 pin 住的版本确实存在，不作为键源。
- **内容测试改为读取 git 历史重建每版本源码**：能自动化溯源，但测试将依赖完整历史与工作树布局，
  浅克隆/CI 环境下不稳定，且把「取证」变成每次跑测试的开销。改为在测试里固定「逐版本读取面」断言，
  溯源证据落在本 Note 的提交号 + `package_sha256`，由熟悉脚本者按族复核。
- **给 `push.files` 的元素键按下标登记**（`["push","files",0,"remote"]`）：符合 §3.3 的整数段语法，
  但元素数量由计划作者决定，按下标登记必然漏项。改为说明挂在容器键并在 `meaning` 里写元素形态（见 Decision）。

## Revisit

- **R2 未闭合项**：数组元素路径（`push.files[].remote`、`pull_paths[].device`）目前挂在容器键，投影按
  叶子取值时这些元素路径会回落到键名。若 U2/U3 的清单在真实计划里让元素键显得突兀，需要 ADR-0060
  复议「数组段路径」的表达（通配段或元素级条目），本批不自造语法。
- **库侧 schema 的额外键**：十族的 `param_schema`/`default_params` 行未经生产库核对（无 `stp_ro` 凭据）。
  若后续取得只读凭据，应核对是否存在「schema 声明但源码不读」的键——那种键的说明只能由脚本作者先删声明
  或补实现，登记表不替它编造含义。
- **登记表的漂移守卫**：`test_head_version_documents_every_key_the_script_reads` 只对**头版本**有效
  （依赖 `tool-manifest` 门禁「族树重建 sha == 最新未退役条目」这一不变量）。非头版本的读取面是固定断言，
  新版本发布后不会自动核对；若要把旧版本核对自动化，需要一个「按 manifest 重建各版本包并抽键」的离线工具，
  属新增门禁面，本批按 §6 不做。
- **退役版本的说明**：首批指定版本里含已退役条目——`flash_firmware` 1.3.15 在 manifest 已 `retired:true`
  （该族 head 为 1.3.18），而 §3.6 的引用量快照显示 Plan 仍引用它。说明按区间覆盖这种版本是必要的：
  scan 的 `retire_blocked` 语义下，被 `plan_step` 引用的行不会翻 `is_active`，人仍要在确认页看懂它。
  若某族退役面扩大导致旧含义不再值得保留，走 ADR-0051 D5 删除流程。
- **本轮复核暴露的两个脚本侧缺陷（不由本批修）**：
  `monkey_setup` 2.3.13 的 `fill.timeout_seconds` 传进内部函数却没被使用（填盘无可控超时）；
  `unisoc_probe` 1.0.1 把 `extra_paths` 原样拼进设备侧命令（无校验、无引号化，对照 #3173/#3463 的 F3 判据是同类面）。
  两者都要靠脚本新版本表达，属 ADR-0051 的发布单元动作，**不是**本 PR 的内容通过条件；本批只在说明里如实登记现状。
  若要处置需另立单，由 Owner 决定是否排期。
- **含义正确性**：结构绿与源码取证都不等于「熟悉脚本的人认可这句话」。逐族复核结论（复核版本、动作含义/
  单位/注意事项是否正确）必须由被指定的人在 PR 评论给出，本 Note 不代其结论。
