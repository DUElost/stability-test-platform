# B5-U4 运行设计与按设备下发安全视图（#3657 / #3653）

Status: implemented
Class: feature

## Decision

按 #3653 §3 分组表 U4、§1.1 Drawer 行、§3.5 U4、§4.2 U4、§4.3 与 ADR-0060 D1-4/5/6、D4-2、D6-1/3 实现，不另设计。

`PlanSnapshotDrawer` 仍接收 detail 已返回的 `plan_snapshot` 作为步骤身份（script 深链、timeout/retry/enabled）。参数、设置、watcher 与折叠 JSON 不再读取 `default_params` / `param_schema` / 原始 `watcher_policy`。默认展示 `detail.parameter_projection`（L2）；设备选择器选中具体 Job 后，经已有 `api.planRuns.jobParameterProjection` 与 `planRunKeys.jobParameterProjection` 读 L3，并展示 `job_id` / `device_id` / `host_id` / `authority` / `read_at`。清单复用 U2 `ParameterProjectionList`（watcher 独立分区）；折叠 JSON 只 stringify `safe_debug`。

`usePlanRunDetailData` 增加可选 `projectionJobId`，仅在选中 Job 时启用 L3 查询；键含 `jobId`，切换设备不串缓存。页面在关闭抽屉时清空选中 Job。L2/L3 缺失或读取失败走「没有安全投影时不展示原始参数」；未物化/历史缺口由服务端投影态表达，前端不回读当前 Plan/Script，也不把 env 回落链默认数字填进值格。

## Alternatives

- 在 Drawer 内自行合并 snapshot 与当前 Script。方案禁止回读当前行补历史，且必须消费服务端投影。
- 为 L3 新建专用组件或改 `ParameterProjectionList`。方案要求复用 U2 公共清单，本单元不改共享组件。
- 用页面已有 `selectedJobId`（设备详情抽屉）兼作 L3 选择。快照视图需要独立选择，避免与设备详情抽屉串状态。
