# memory-lint：记忆目录机械化体检（#1585）

Status: implemented
Class: feature

## Decision

三轮 memory 腐化点人工扫描（2026-09-11/12，15 处免疫 / 7 类形态）中，四类
可完全机械化，固化为 `tools/dev/memory_lint.py`：

- **结构（ERROR）**：非索引文件 frontmatter 完整（name/description/type ∈
  user/feedback/project/reference）；
- **索引（ERROR）**：`MEMORY.md` 无 frontmatter、≤200 行、每行 ≤150 字符；
  索引 ↔ 文件**双向**一致（死链与未索引文件都报）；
- **断链**：正文反引号引用的路径存在性——仓库相对路径缺失 = ERROR；
  `~`/绝对路径缺失 = WARN（环境迁移可能合法）；命令式 token（如
  `` `python tools/dev/x.py --strict` ``）按词拆分、跳过 flag 与命令词，
  只检查路径部分；含占位符/通配（`...`、`<`、`*`）的引用跳过；
- **可疑绝对断言（WARN）**：`不会跑 / 不会重跑 / 完全不跑 / 零容忍 /
  永远是`、裸计数 `存量 **N 个**`、`每 N 天`——提示改为「条件自证 / 现查为准 /
  指向权威来源」。

设计取舍：

- **只读**：绝不改 memory 文件（措辞/语义是维护者的判断）；
- **默认路径**：`~/.codebuddy/projects/<path-slug>/memory`（本项目约定），
  `--path` / `--repo-root` 可覆盖；
- **不进 CI/run_gates**：检查对象在 `$HOME`（跨机器不成立），定位为手动/
  例行体检工具；`--strict` 供需要「零告警」时使用。

## Alternatives

- 进 run_gates/CI：门禁不应依赖开发者 home 状态（且 memory 目录在不同
  harness 下路径不同），会造成「本机绿、CI 找不到目录」的假门禁；
- 自动修复（改写措辞/补 frontmatter）：memory 是判断性文本，自动改写风险
  （可能把「条件自证」改成错误的具体条件）大于收益——工具只定位、人改；
- 语义检查（文件内矛盾、能力新增同步）也做进工具：这两类需要理解语义
  （如「当时不跑」vs「完全不跑」的语境），现有人工扫描保留，工具不做。

## Verification

- `pytest tests/test_memory_lint.py`：**16 passed**——合法集通过 / 缺
  frontmatter / 非法 type / 索引不应有 frontmatter / 死链 / 未索引文件 /
  超长索引行 / 断链两级严重度（仓库 ERROR、绝对 WARN）/ 命令式 token 拆词
  （存在不报、缺失报）/ 占位符与裸名跳过 / 绝对断言 WARN 与 `--strict`
  退出码 / 默认路径 slug 推导；
- **对真实 memory 目录实跑：0 error / 0 warn**（收敛干净）；
- 实跑同时暴露并修复了两处真实问题：①工具误报（原实现把
  `` `python tools/dev/check_test_containers.py` `` 整段当路径，现已按词拆分）；
  ②memory 两条措辞命中可疑断言（`永远是` → `一律用`、`完全不跑` → `（当时）
  不跑任何 repo 层测试`）——工具第一次用就产出了价值；
- `ruff check backend/ tools/ scripts/ tests/` 全绿。

## Revisit

- 语义类腐化（文件内/跨文件矛盾、能力新增同步、跨面重复）仍需人工扫描——
  建议每三轮机械体检后做一次人工语义轮（三轮节奏来自 2026-09 实践）；
- 若未来 harness 记忆目录约定变化（如 Codebuddy 改名/迁移），更新
  `default_memory_dir` 的 slug 规则即可（单点）；
- `--strict` 接入例行流程（如周检）需先观察 WARN 的误报率——当前 0 基线，
  介入时机由维护者定。
