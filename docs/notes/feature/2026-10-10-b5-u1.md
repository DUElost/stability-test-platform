# B5-U1 后端安全分层投影、登记表框架与共享 API 契约（#3654 / #3653）

Status: implemented
Class: feature

## Decision

按 #3653 §3.1、§3.3 框架、§3.4、§4.2 U1、§4.2.1、§4.3 实现，不另设计。

投影只调用现有 `merge_effective_params`、lifecycle builder、`inject_wifi_params` / `inject_suite_params`（深拷贝后探测填空路径）和 `enrich_job_metadata`。不深合并，不调用 `suite_binding.step_params_for_dispatch`，不把当前池配置或当前 PlanStep/Script 回读进 L2/L3。来源只有 schema_default、script_default、step_override、dispatch_injection；证明不了则为 null，并带诊断「来源不可追溯」。五态里的 actual 不产出。L4 不产出。

掩码在响应前把敏感值写成 null，`sensitive=true`，`is_set` 只表示原来有没有值。敏感路径是内置注入路径、登记表全部版本的 sensitive 并集，以及 `sensitive_query_keys()` 的大小写不敏感精确键名。字面键 `wifi.password` 不等于嵌套路径 `['wifi','password']`。嵌套路径上的 schema `default` / `enum` / `const` / `examples` 按同一相对路径清除。`enum` / `examples` 最外层是候选值，这一层下标不是参数路径；值内部的整数下标（如 `("servers", 0, "psk")`）必须保留并参与清除。旧的 `default_params` / `param_schema` / preview `lifecycle` 仍按原样返回，不标成安全投影。

`barrier_max_wait_seconds` 未设时状态是 env_fallback，值保持 null。回落文案写明 Plan → `STP_BARRIER_MAX_WAIT_SECONDS` → 1800，非法环境变量回到 1800，环境变量 ≤0 才表示无硬顶。这是 #3652 标明的现行代码，不宣称 ADR-0060 §5 已闭合，也不把 NULL 写成「无硬顶」。

参数说明登记表只提供说明。缺文件时为空。版本是三段非负整数。说明不进入合并，也不进入 lifecycle。`confirmation_fingerprint` 只加在前端 `PlanRunCreate` / `PlanRunPreview` 类型上；后端 `PlanRunTrigger` 仍是 `extra=forbid`，本单元不接受该字段。

新端点不声明 `response_model`，避免形状棘轮把新模型名或新的 `ApiResponse[dict]` 算进 scope 外的台账。运行期仍返回 `ApiResponse`。`plan_runs.py` 的 L3 路由保持薄壳，文件行数停在封顶 507。L2 详情的 `read_at` 取该 PlanRun 的 `started_at`，同一条未改记录的两次读取（含 `include_jobs` 开关）投影一致。

## Alternatives

- 在新端点上声明 `response_model=ApiResponse[ParameterProjection]`。形状契约的 opt-in 文件会要求登记新模型，而登记表文件不在本单元 scope。
- 把 `read_at` 写成每次请求的当前时间。已有详情对拍要求除 jobs 外逐键相同，墙钟会让两次读取不等。
- 为通过夹具 import 去改 `vitest.config.ts` 或复制 JSON。相对 import 在当前 type-check 与 vitest 下可用，没有走这条。
