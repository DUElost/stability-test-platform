## 决定了什么

按 [`FRONTEND_NAV_IA_REDESIGN_2026-08-28`](../../reviews/FRONTEND_NAV_IA_REDESIGN_2026-08-28.md)（v1.1，四项裁决全案采纳）实施方案 A 保守档：

1. 侧边栏三级信息架构：概览/项目/**执行**（并入定时调度）/测试资产/主机与设备/分析报告/**平台管理**（admin 组收拢 5 个散落入口：原 UserMenu 用户管理·操作日志·系统设置 + 原「主机与设备」文件服务器 + 原「运营配置」通知管理）；「运营配置」解散。
2. UserMenu 只留账号域（文档/修改密码/退出登录），admin 管理入口单一来源化。
3. 删除僵尸路由 `/resources`（6 行 redirect 组件，全仓零引用）。
4. 页头命名对齐：主机管理→主机集群、设备管理→物理设备、脚本管理→脚本库（含 PlanStepInspector 三处指引文案）。
5. 顺手修复 [`settings.ts`](../../../frontend/src/utils/api/settings.ts) 双拼路径 404（400281f 引入：axios baseURL 已含 `/api/v1`，全路径写法致系统设置页报错态；实证 401/404 分野后改相对路径）。

## 放弃的备选

- **方案 B 三段式大重组**（工作区/资源与成果/平台管理 + 页签形态统一 + 全站面包屑）：影响 6+ 页面与路由结构，与 AI 助手 PR 叠加放大回归面；页签统一已有 08-27 评审 C2 立案，独立专项另议。
- **「脚本管理」反向改名**（侧边栏改全名）：组名是实体词，反向造成「测试资产」组内语义矛盾；「管理」语义收敛给「平台管理」组。
- **「项目」并入执行组**：ADR-0029:329 明确锚定一级导航，改组须回写 ADR，代价不成比例。
