# B7 密度与分页 + P3-18 瓦片触达（issue #370）

Status: implemented
Class: feature

依据：issue #370（UI 审查 §6 第 7 位 + §7 钩子 + P3-18 并入）。产品决策
（用户确认）：**全局默认紧凑、不做切换开关**——运维工具密度优先，
60+ host 目标下默认就应紧凑；若有舒适模式反馈再 Revisit。

## Decision

- **三表行高紧凑**：主机/设备表 TableCell `p-3` → `px-3 py-1.5`
  （TableHead `px-3 py-2`）；审计表 `py-3` → `py-1.5`（含 chip/IP 两个
  漏网变体）。实测 63→**51/53**（主机/设备，行高下限由双行内容主导）、
  46→**34**（审计）。统计筛选卡行不动（B9 基线对齐的 KPI 卡）。
- **审计分页接 `PaginationBar`**：首页/末页/页码组/页大小（10/20/50，
  默认 50）；`pageSize` 常量改 state，切页大小重置到第 1 页。
  245,668 条 / 4,914 页从此可跳转。**props 语义坑**：组件 `page` 是
  1-based，页面 state 是 0-based——`page={page + 1}`，`onGoToPage`
  里 `-1`；首版传 0-based 渲染出「第 0 / 4942 页」。
- **设备空列按数据隐藏**：`hasNetworkData/hasTagData`（任意设备有值）
  条件渲染「网络」「标签」两列。生产实测：网络列（latency 全空）隐藏，
  标签列（有真实 tag）保留——**审查的「两列全空」快照已过期，逻辑
  按当前数据说话**。展开行内网络详情卡不动。
- **P3-18 瓦片 44px**：`DeviceMatrix.tsx` `TILE_PX = 32 → 44`（固定
  尺寸的高频点击目标，达到 44px 触达建议值）；cols 自适应公式自动
  少排（1440 宽实测 13 列），瓦片密度语义不变。

## Alternatives

- **紧凑/舒适用户开关**（否决，用户裁定）：localStorage 偏好状态穿透
  多组件 + 测试成本，收益未知；密度目标（60+ host）下默认紧凑。
- **空列做成手动列显隐**（否决）：按数据自动判定已覆盖痛点（列在
  数据出现时自动回来），显隐 UI 是多余复杂度。

## Verification

- 门禁：tsc / eslint（4 改动文件 `--max-warnings 0`）/ 全量 vitest 602 /
  build 全绿（DeviceMatrix 测试不断言瓦片常量，无同步）。
- DOM 7/7（`/tmp/ui-shot-rig/verify-370.js`，1440×900）：主机 51px /
  设备 53px / 审计 34px；审计分页含首页/末页/页大小，跳末页
  「第 4942 / 4942 页」生效；设备表网络列隐藏、标签列按数据保留；
  瓦片 grid 13 列 × 44px。

## Revisit

- 「舒适模式」真实反馈出现时再加开关（本轮否决依据）。
- 审计 4,942 页仍是纯页码跳转；若需要按日期/用户直达，那是筛选增强
  不是分页问题。
- 主机/设备行高下限现由内容（双行文本）主导；进一步压缩需砍内容
  行（如设备列型号并入 title），属信息密度取舍，未动。
