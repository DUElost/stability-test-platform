# B8 G1：设备日志事实底座

Status: implemented
Class: feature

## Decision

按 #3800 方案 v1.6 §3 G1 行与 #3863 落地设备日志事实底座：

- 发生身份 `occurrence_key = sha256(platform | serial | db_path | aee_ts 原文 |
  raw_event_type)`，唯一实现在 `backend/agent/contracts/occurrence_key.py`。Agent 在
  `AeeDbHistoryReconciler` 生成 DLE payload 时计算并附带；控制面只存储上报值，
  不从目录名、报表文件名或 xls 文本反推。
- `device_log_event` 新增可空 `occurrence_key` 与索引；存量行不回填。控制面 upsert
  只在 payload 显式携带时写入，与 `plan_run_id`（#1052）、`size_bytes`（#3829）同口径。
- 新增八张单数表：`issue_signature`、`issue_occurrence`、`issue_occurrence_event`、
  `partition_mode`、`scan_round`、`representative_selection`、`delivery_version`、
  `spill_ledger`（迁移 `b8g1c4a7d2e9`，父 `u9b6d3793a01`）。事实行只追加、不改写；
  对 `plan_run` / `job_instance` / `device_log_event` 只存引用 id，不建级联外键。
- 读写唯一入口是 `backend/services/issue_fact_store.py`。`partition_mode` 写入后
  不可改（D13 第 2 条）；`representative_selection` 进入「已选」后 `dle_id` 不可改
  （D7 第 6 条）。次数与机器数由查询按 `occurrence_key` / `serial` 去重，不落计数列。
- 本单元不接入 merge、调度或上传，不改变任何现行行为。合入后现网 merge、上传与
  extract 的结果与合入前一致。

## Alternatives

- **控制面从 `db_path` + 目录名重新计算身份**：违反 ADR-0062 §3 第 2 条，且控制面
  拿不到设备原文；否决。
- **给 `plan_run` / `job_instance` / `device_log_event` 建 `ON DELETE SET NULL`
  外键**：ADR-0056 D1 允许，但删除运行行会被外键级联动作放大成写事实行；本单元
  选择只存引用 id，让事实行的存续与运行行彻底解耦。
- **在 `issue_signature` 上存累计次数 / 机器数**：I1 要求计数是发生身份的去重查询
  结果；可累加列会被重扫、迟到补报和补充轮破坏；否决。
- **把发生身份写进 `issue_occurrence_event` 而不写 DLE**：后续轮次无法在不读事实表
  的情况下按观察幂等；且 #3863 明确 DLE 需要可空列；否决。

## Revisit

- 如果真实数据出现 `db_path` 或 `aee_ts` 缺失/不稳定，按 #3800 §7 第 1 条退回，
  不改用其他字段。
- G4 写入发生时要确认「同一事件目录承载多个问题」的映射方式：本单元按
  `(occurrence_id, dle_id, signature_id)` 去重；若影子运行发现同一 `occurrence_key`
  需要对应多个签名，需回到规划者裁定，不在本单元私自放宽唯一约束。
- `issue_occurrence.occurrence_key` 允许为空以承接 fail-open；G4 需在写入时标注
  来源未证实，并在影子运行对拍次数口径。
- 若后续单元需要按平台过滤发生查询，本单元已提供 `platform` 参数；若需要按
  「本轮观察到」而非「首见轮次」计数，应在 G4 的方案里明确并另立查询，不修改本表。
