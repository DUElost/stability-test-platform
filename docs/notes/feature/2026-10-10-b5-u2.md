# B5-U2 确认指纹与执行前参数清单（#3655 / #3653）

Status: implemented
Class: feature

## Decision

按 #3653 §3.2、§3.5 U2、§4.2 U2、§4.3 U2 与 ADR-0060 D5 实现，不另设计。

指纹是 `stp-l1-v1:` 加 HMAC-SHA256 的 64 位小写十六进制。密钥复用 `JWT_SECRET_KEY`（`backend.core.security.SECRET_KEY`），域分隔是 `stp-plan-confirmation-v1`。不新增 env，不记录密钥或 canonical 原文。canonical 只含方案点名的 Plan 列、PlanStep 列，以及被引用脚本的 `(name, version)`、决定合并的 `schema.default` 与 `default_params`。参数说明、设备与 WiFi 选择、套件内容、主机管控不进入文档。

preview 与 prepare 用同一次 `load_plan_graph_for_confirmation` 读到的 Plan、步骤和脚本元数据计算或比较，比较通过后用这批对象写 snapshot，不再另读一批。PostgreSQL 上这次读取对 Plan 取 `FOR SHARE` 并 `populate_existing`，锁留到 prepare 提交。SQLite 不取行锁，也不当作锁证据。

`confirmation_fingerprint` 在 `PlanRunTrigger` 上可选。缺省或 JSON null 不比较，SCHEDULE、CHAIN、AI 与旧调用不改签名。人工确认路径必须带上 preview 返回的指纹；格式非法是 422。不一致在创建 PlanRun 之前抛 `PlanConfirmationChanged`，路由先于通用 `PlanDispatchError` 捕获，返回 409，`detail.code` 为 `PLAN_CONFIRMATION_CHANGED`，消息为「计划配置已变化，请重新预览并确认」，响应不带回旧配置或新 token。

执行页只通过 `ParameterProjectionList` 消费投影。敏感值只显示已设置或未设置。缺投影或出错不回退原始 JSON。Cockpit 不再引用 `planTiming`。设备或 WiFi 选择变化会作废在途预览；备注变化不作废。409 清掉预览和指纹，保留设备、WiFi 和备注，操作员必须再点一次预览、再点一次确认。

## Alternatives

- 用内容哈希代替 HMAC。方案指定 HMAC 与现有 `JWT_SECRET_KEY`，没有另选。
- 用跨 HTTP 请求的锁保住预览。方案要求的是同一次 prepare 事务里比较到冻结，不是跨请求锁。
- 让前端自己比较指纹。比较只在服务端对实际读取对象进行。
