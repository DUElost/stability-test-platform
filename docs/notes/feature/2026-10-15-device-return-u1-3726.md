# Agent Note: B6-U1 Agent 解除执行保证与解除结果回报 (#3726)

Status: implemented
Class: feature

## Decision

按规划方案 [#3723](https://github.com/DUElost/stability-test-platform/issues/3723) v1.2 §3.0 / §3.2 落地 Agent 侧设备归还契约（阶段 A）：

1. 新建共享契约 `backend/agent/contracts/device_return.py`（本单元拥有）：六值解除结果、专项归还/欠账机器值、`FAMILY_STEPS`、空 `ONBOARDED`（U5 登记）、足迹判定、`EXECUTING_DISARM`、租约已失冲突处理。
2. `_run_step_with_permit`：`teardown` 阶段不因 `_canceled`/lease-lost 放弃 permit 等待，上限为步骤墙钟；`SchedulerShutdown` 立即返回并记 `incomplete`。
3. `cancel()`：活动进程处于 `teardown` 时只置取消标志，不杀子进程（M2）。
4. `ABORT_LOCAL`：worker 存活时推迟 `delete_active_job` / `clear_fencing_token` 到 `_cleanup_after_job_exit`；`CLEANUP` 保持立即清理。
5. `manual_exit`：执行解除（ADR-0061 D3.4 修订原 ADR-0022 BO4）；未接入专项跑该专项完整 teardown 步骤。
6. 优雅停机：先 abort → 最多等 20s 收尾已开始的解除 → 再 `scheduler.shutdown()` → leftover 按 `incomplete` 写入本地 outbox → drain → 再关 LocalDB；不改 systemd unit。
7. 终态载荷透传 `disarm_results`；解除步骤期间上报 `EXECUTING_DISARM`；租约 409 时不执行解除并记 `not_executed`/`lease_lost`。

开工前检曾与僵尸 Registry 记录重叠；规划者在 [#3723 评论 6184041214](https://github.com/DUElost/stability-test-platform/issues/3723#issuecomment-6184041214) 裁定授权开工，僵尸记录已 abandon。

## Alternatives

- 扩大 `ONBOARDED` 或改脚本族：属 U5，本单元明确不做。
- 改 systemd `TimeoutStopSec`：§6 禁止；用 20s 解除窗口 + 既有 30s unit 预算。
- 在 `job_runtime.py` 注入 `job_runner_slot`：超出 U1 scope；改为在 `build_cancel_recovery_job` 闭包挂 `is_worker_alive`，`ABORT_LOCAL` 回落 `active_jobs_by_id`。

## Verification

反例（`backend/agent/tests/test_device_return_u1_3726.py`）用 `_PRE_FIX_BEHAVIOR` 可逆变异证明修复前红、修复后绿：

| 反例 | 修复前（变异） | 修复后 |
|---|---|---|
| permit=1 三 job 同时中止 | 仅 1 个 teardown 执行 | 3/3 执行 |
| teardown 中 cancel | 子进程被 terminate | 不 terminate |
| ABORT_LOCAL + worker 存活 | 立即清 fencing | 推迟清理 |
| manual_exit | SKIPPED | 执行 disarm |
| 停机顺序 | scheduler 先于 abort | abort → wait → scheduler |
| 停机有界 outbox（复核 A） | `executor.shutdown(wait=True)` 无界阻塞，到不了 `outbox_drain.drain_sync` | `wait=False`，即使仍有 active runner 也会进入 drain |
| SchedulerShutdown→incomplete（复核 B） | `started=False, incomplete=True` 被映射成 `not_executed` | 显式 `incomplete` 优先于 not started；`lease_lost` 仍优先 |
| 停机 incomplete 落 outbox（复核 C） | `wait=False` 进入 drain 后关 LocalDB，解除 worker 仍在跑 → outbox 空 + 迟到 `TerminalReportLostError` | 关库前对 leftover 写 `incomplete` 入本地 outbox，再 drain |
| 六值映射 / 租约已失 | 单测直达 | 单测直达 |

复核返工（PR #3733）：修 A=`graceful_shutdown.py` 停机 executor 有界；修 B=`device_return.map_step_outcome_to_disarm_result` 优先级；修 C=`_persist_incomplete_disarm_to_outbox` 在 `local_db.close()` 前持久化未完成解除（§3.2.4）。

门禁（worktree 内实际运行）：见 PR 正文 / 复核评论。

## Revisit

- U2 合入后：控制面持久化 `disarm_results`、识别 `EXECUTING_DISARM`、兼容推导。
- U5：向同一契约文件追加 power-cycle `ONBOARDED`；manual_exit 改为只跑 `powercycle_disarm`。
- 若优雅停机在 30s unit 内仍无法有界收尾已开始的解除 → 触发 #3723 §7 退回。
