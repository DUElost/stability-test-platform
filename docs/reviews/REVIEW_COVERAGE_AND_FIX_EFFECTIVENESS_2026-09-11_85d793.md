## 0. 四个问题的结论

1. **R01–R15 的分区基本完整，但覆盖证据尚未闭合。** 接受逐区静态审查已经交付；统一基线、跨区两条端到端链路、存量升级、真实部署条件和故障/规模验证不能由此自动推导为完成。
2. **整改已有实质收益，但不能对所有 CLOSED Issue 整体背书。** 本会话对 #901 和 #1123 的已关闭修复分别取得隔离反例；它们不是仅仅缺少更多测试，而是存在未兑现的验收条件。
3. **ADR-0034 的协作骨架值得保留，当前主要闭合的是代码集成，而非问题解决。** 独立 worktree、Registry、PR 和 FIFO 不能替代语义组合验证、部署验收与真实关单核销；经济可持续性仍需实测。
4. **存在过渡止血、实现不完整及需要组合治理的事项。** 应按共同不变量和因果依赖治理，而不是按目录或 Issue 数拆补丁。本文提出 10 个候选治理主题，**不等于要新建 10 个 Epic、10 个 ADR 或同时启动 10 路执行**。多数属于落实/修订既有契约，少数方向性选择才需要 ADR。

第一性原理的判据是：**真实失败模式是否被消除、完成事实是否可证明、下一次同类变化是否更安全**。长期复利的判据是：同类回归与维护成本下降，而不是 CLOSED、PR、代码量、规则量或 Harness 数增加。

### 3.2 F01：#901 CLOSED，但 refresh 原子消费未完整成立

- 类型：确定代码缺陷；沿用原单 P1 关注级别；E1 + E2。
- 原单验收包括原子消费与并发刷新回归。
- 位置：`backend/api/routes/auth.py:396`、`backend/api/routes/auth.py:435`、`backend/api/routes/auth.py:448`；`backend/services/token_blacklist.py:32`。
- `revoke()` 通过冲突插入返回是否首次消费；调用方忽略 `False`，仍然签发 token。
- 可达交错：A/B 都先查到未撤销 → A 插入并提交 → B 冲突返回 False → A/B 都继续签发。顺序重放测试不能覆盖这个交错。
- 隔离诊断直接调用真实 refresh 处理函数，替换鉴权/数据库边界，分别返回 `revoke=True/False`；结果 **1 passed、1 failed**，失败为 `200 != 401`。这是消费失败分支的确定性验证，不是实际 PostgreSQL 并发压测。
- 最小出口：签发必须以服务端原子消费成功为前提，补并发刷新、refresh/logout 竞争和顺序重放回归。客户端锁只能改善 UX，不能成为安全正确性的权威。
- #1039 的 Web Locks 与 `/auth/me` 探活不得当作完整替代；internal HTTP 的适用边界已有 #1200 承载。

建议重开 #901 或建立明确关联的残余项；本轮未执行该 GitHub 写操作。

### 3.3 F02：#1123 的互斥在真正取消时提前释放

- 类型：确定代码缺陷；建议按潜在结果并发写风险优先处理，实际生产数据破坏未观察；E1 + E2。
- 位置：`backend/tasks/saq_tasks.py:98`，尤其 `:123` 的 `await asyncio_to_thread(...)` 和 `:125` 的协程 `finally`。
- 当前代码在等待协程结束时执行 `_SYNC_OVERLAP_GUARDS.end(key)`。取消协程会进入 finally，但不能停止已经运行的同步线程，因此 guard 先于真实工作退出而释放。
- 隔离诊断使用真实 Python 线程与 Event：第一线程开始并阻塞 → 取消等待任务 → 第一线程仍未结束 → 同 key 启动第二任务 → 第二线程实际进入。没有调用 merge 工具、NFS 或数据库。
- 非取消对照通过，取消路径失败：**1 passed、1 failed**，失败断言为 `retry started while the first synchronous worker still ran`。
- 既有 `test_saq_tasks.py` 的互斥测试覆盖手工占位、等待和异常释放，但没有证明“真实 to_thread 已运行后取消”这个生命周期交错。
- 最小出口：释放权绑定真实同步工作完成，并覆盖提交前取消、提交失败、工作异常三个出口；不能简单挪一行 finally 而引入永不释放的新窗口。

该缺陷**不需要多 worker 才发生**。不能只把 #1123 归类为“单进程已解决、以后横向扩展再议”，也不能靠继续加大 #1085 超时避免正面处理。建议复开/续跟 #1123，不必等大型架构重做。

### 3.4 F03：#942 的种子治理存在权限层级与语义不一致

## 4. Q3：现有多 Harness 修复模式的判断

### 4.1 保留什么

保留 Issue 溯源、独立 worktree、Registry 前检/查重、声明与实际 diff 对证、受保护 PR、FIFO 集成、测试与 Agent Note。选择 Harness 的权利仍在开发者，`declare` 是登记，不是自动派单或目录所有权。

独立 worktree 隔离文件修改，FIFO 串行化 Git 集成；它们都不能保证两个局部正确的修改组合后仍然正确。默认 `1 Requirement → 1 Harness → 1 PR` 不等于机械规定一个 Issue 只能有一个孤立的小补丁；需要共同验证的接口迁移必须显式编排依赖。

### 4.2 补齐什么

第一轮只读查询的分支保护要求审批数为0；PR-Agent 是 advisory，security concern 也不阻断普通合入。PR 路径有意跳过全量 backend/Vitest/Docker，见 `.github/workflows/ci.yml:229` 与 `.github/workflows/pr-agent.yml:95`。这不是“从无人审查”的证明，但确实没有强制独立复核保障。

最小补强不是给每个 PR 堆全量门禁，而是：

1. 鉴权、事务、迁移、执行协议、部署和 CI 权限变更，增加按影响面选择的必跑回归和独立复核。
2. 验收先写可失败的不变量，覆盖旧调用方、异常、竞争交错与旧数据；不能仅证明新实现符合作者自己的假设。
3. 代码交付单可以在合入且约定验收满足后关闭；生产故障单还需匹配部署/版本的运行证据；风险接受单保留残余和复议出口。
4. 合入后核销真实 Issue 状态、已验证 SHA 和 Execution；不能以 closing keyword、缓存 READY 或 PR body 代替事实。
5. 红队首应有可见的人工处置出口，如现有 draft/eligible 范围内的有意调整；不绕过 required checks、不手工 Merge。若改变 FIFO/准入语义，先修订现行契约。

推荐闭环：

```text
发现 → 证据化确认/去重/风险接受 → 定义可失败验收
→ 开发者选择 Harness + declare → 独立 worktree 修根因
→ 按风险验证与复核 → FIFO 合入 → 匹配环境验收
→ 关单核销/Execution 收尾 → 同类复发回看
```

沿用 #1035 的限期经济性观测，不另建永久台账：关注复发/回归、确认到验证解决的时间、主干红灯/队首阻塞时长、人工干预与未来维护成本。2026-10-15 的裁决/退役期限仍以原台账为准。更多会话或更多关闭项不能单独证明净收益。

| 修复不完整 B | 宣称的验收条件在当前基线有反例 | F01/#901、F02/#1123；不能只补一个 Revisit 就算结案 |
| 显式风险接受 A | 已由有权者接受当前边界，目标与触发条件另存 | #909/ADR-0024、#906/ADR-0035；不是“风险已经消除” |
| 待验证 V | 源码提示条件性风险，缺真实规模/环境证据 | 跨进程副作用、真实 NFS 恢复、渠道 UNKNOWN 的重复后果 |

**明确的过渡案例：#1273。** `docs/notes/bug-fix/2026-09-10-truncate-deadlock-retry-1273.md:25` 已诚实标注：退避处理瞬态循环等待，但未定位泄漏会话/后台线程。重试并非错误，错误是让“再红了才找根因”成为永久出口。应有定位任务与观测信号，并在隔离全量测试中验证资源生命周期。

**结构性过渡候选：#1172。** 为适配 #986 的内部 commit，把聚合移出 SAVEPOINT，并在终态候选后结束本 tick。这消除了已复现异常，但把调用约束与吞吐代价转给后续代码。默认 reconciler 间隔15秒（`backend/scheduler/app_scheduler.py:33`）；部分检查每 tick 至多终态化一个候选（`device_lease_reconciler.py:174`、`:255`）。不能未经规模预算就把“下轮会处理”当作充分验收，也不据此宣称生产已超时。

**合理边界但不能扩张承诺：#1122。** SMTP per-socket timeout 和有界池是合理资源防御；fire-and-forget 满队列时丢弃只适用于明确的 best-effort 通知。不能把这个池复用到必须可靠交付的业务路径，或把单次 socket 超时宣称为整条邮件的 wall-clock deadline。

**正面的临时设施：#1035。** 有明确决策问题、截止日期和自杀条款的临时测量仪器，比为“防腐”新增永久管理系统更符合长期复利。

## 6. 组合治理候选：按因果与不变量，不按目录分片

CG 编号仅用于本文汇聚，不新增 Registry 字段、执行角色、强制台账或目录所有权。C/O 分别表示本轮快照 CLOSED/OPEN。**组合治理不等于巨型 PR**：先统一边界和联合验收，再把有依赖的最小变更按顺序交付。

### CG-01：会话消费与部署安全上下文

- **关联**：C #900/#901/#902/#903/#1039/#909；O #1200/#46。
- **共同不变量**：服务端决定凭证是否仍有效及是否被唯一消费；HTTP/HTTPS 与浏览器能力不能改变安全语义。
- **优先工作**：先修 F01；再验证 internal HTTP 双标签和 refresh/logout 竞争。保持既有 PK/纪元校验，不回到 username fallback。
- **不是更好方案**：继续叠 `/me` 探活、延长客户端延迟，或无裁决地增加旧 token 宽限。
- **ADR**：原子消费缺口无需新 ADR；若采用会话族撤销、复用宽限或改变 internal 例外，应修订 ADR-0024，不另起竞争权威。
- **退出标准**：同一旧 refresh 在竞争下最多一次成功消费；失败响应不破坏另一个已合法建立的会话；各支持部署上下文均有证据。

### CG-02：终态事务、聚合与可恢复后续动作

- **关联**：C #986/#987/#989/#992/#1172；O #797；结果链的后继投递 #1110 为相邻接口。
- **共同不变量**：父 Job 终态/租约/聚合事实不被子派发回滚；事务只有明确的拥有者；后续动作失败后可从持久事实恢复。
- **优先工作**：把 `on_job_terminal` 的调用契约、锁序、SAVEPOINT 兼容性和批处理容量一起核对。区分“准入确实死亡”与“健康但慢”，不能靠次数耗尽替代执行所有权判断。
- **终态方向**：显式事务边界与提交后的副作用交接。先检查已有 DB 字段和 reconciler 是否足以恢复；只有证明 commit/enqueue 缺口无法覆盖时，才比较事务性 outbox。
- **ADR**：局部调用方修正属于现有执行协议；若选择跨领域的新事务/副作用所有权模型，才需要方向级 ADR。不得因几个调用点不便就引入通用工作流引擎。
- **退出标准**：父提交前/后分别注入失败；新旧调用方都安全；N 个过期候选的清理时限可计算且经隔离负载验证，不只一个候选通过。

### CG-03：取消、失租与真实副作用所有权

- **关联**：C #1003/#1004/#1005/#1006/#1009/#1176/#1203/#1123；O #799；升级 drain #1249 为相邻边界。
- **共同不变量**：等待者结束不等于实际工作停止；失去所有权的执行者不能继续驱动设备/写目标，旧执行者不能释放继任者的资源。
- **优先工作**：修 F02 的同步 worker 生命周期；Agent 侧联验失租、用户 abort、进程组退出、终态 outbox、清理和重新准入。二者共用验收原则，不强行共用锁或执行器。
- **现态证据**：`backend/agent/main.py:153` 失租清理仍摘活跃占位；`job_runner.py:94` 有保持所有权至 ACK 的用户 abort 路径。#799 要求辨别这两种语义，不能只复用“清集合”。
- **ADR**：在既有语义内修错误无需新 ADR；若改失租后 teardown 权限、无法确认停止时的隔离/重派政策，修订 ADR-0019/执行协议。跨进程执行与所有权策略应对齐 ADR-0027。
- **退出标准**：真实取消交错测试、继任者保护、进程树停止证据、未确认停止时的明确政策；不能把“task cancelled”当作物理停止 ACK。

### CG-04：事件与分轮结果的交付完成证明

- **关联**：C #1042/#1051/#1174/#1204/#1071/#1072/#1074/#1076/#1079/#1082/#1083/#1085/#1110/#1111/#1175；O #1052/#1053。
- **共同不变量**：事件和产物有稳定身份/轮次；已确认远端事实不被迟到消息降级；只有交付证据齐备才能完成和 prune。
- **优先工作**：按现有 scan/upload/merge 契约联测重复、晚到、跨平台、旧轮/终轮、中心不可用和死信重放。把字节预算、失败状态和人工恢复出口列为边界，不靠队列空/目录存在推断交付。
- **终态方向**：DB/本地持久事实承载可恢复状态，Redis 只承载队列与瞬时通信；guard、超时预算和 SAQ key 都不能替代结果身份与完成屏障。
- **ADR**：修复已有契约无需新 ADR；改变完成定义、终轮优先/补轮或报告快照语义，先对齐 ADR-0028/0032 与现有设计。不要给每个平台复制另一套状态机。
- **退出标准**：两条链的联合故障矩阵，死信不阻塞可恢复项，重放不降级权威态，删除本地副本前有可追溯的完整性证据。

### CG-05：通知投递状态而非“调用成功”

- **关联**：C #1117/#1120/#1122；#1214 的凭据错误信息是相邻安全约束。
- **共同不变量**：事件/通道投递身份稳定；渠道接受、明确拒绝与结果未知分开；重试有唯一负责方且不重发已知成功通道。
- **优先工作**：保留已实现的上抛、业务响应解析和持久 channel_delivery；消除 F04 的最近30条/缺 run_id 恢复边界，补真实 dispatcher 测试而非仅 mock 它抛异常。
- **终态方向**：稳定投递键 + DB 中每通道事实 + 有界重试/可观察 UNKNOWN。是否扩现有 JSON 或增加单数业务表是后续实现选择，不能提前把新表当作治理成果。
- **ADR**：完成已有 Proposed ADR-0036 的更新与裁决；现有源码已改善的背景必须先纠正。不再新建第二份通知语义 ADR，也不声称端到端 exactly-once。
- **退出标准**：无 run_id 事件、超过30条噪声日志、部分成功后重试、持久化失败、并发请求和 UNKNOWN 均有断言；关键通知不落到可静默丢弃的池。

### CG-06：脚本身份、运行绑定与资产生命周期

- **关联**：C #942/#975/#1028/#1030/#1276/#745；O #790/#810/#735；ADR-0033 的接入治理为方向入口。
- **共同不变量**：一次执行消费的是明确的版本/SHA/有效参数与本轮目录，而不是“当前最新”或可被旁路改写的标识。
- **优先工作**：先裁清 F03；关闭 API/迁移/扫描之间的可变身份旁路，落实本轮 run_dir 的生产与消费契约。保留已发布版本，新增行为用新版本，并记录真正启用的消费者。
- **资产治理**：退役是从可选择集合下线，不等于删除已发布文件；当前 PlanStep 零引用不等于无历史追溯价值。#735 的历史数量不当作本轮生产统计。
- **ADR**：ADR-0033 Accepted v1.2 已规定 D0/D3 即刻生效、D2 按族准入、包存储条件落地；不要重开同主题 ADR或以它为由先建完整包管理平台。改变全量不可变副本/默认参数例外才需修订 ADR-0020 等现有权威。
- **退出标准**：新旧库与 API/迁移路径一致、setup/check/finish 使用同一运行绑定、旧 Plan 可复现，已修新版本有明确采用/退役记录。禁止用增加共享可变 import 的方式“去重”历史版本。

### CG-07：主机信任与最小权限

- **关联**：O #906/#908/#1250/#1263/#46；其安装与升级接口连接 CG-08。
- **共同不变量**：只有经过验证的主体，才能以有界权限操作预期主机；持有共享秘密不等于主机身份可信。
- **优先工作**：分开核对主机密钥绑定、sudo 能力边界和 Agent 身份；它们有依赖，但不应打成一个超大安全 PR。
- **ADR**：ADR-0035 Accepted v1.2 已明确“当前接受共享 secret、目标主机级身份、迁移路径、触发检测来源”，且 #906 不随 ADR 关闭。触发满足按既有裁决实施，无需再开 ADR；要提前改变接受边界则修订原决策。
- **退出标准**：维护已接受风险的检测来源；主机密钥变更有独立验证；权限缩小有合法操作回归。真正迁移主机身份时验证单机凭据泄露不能冒充其他 host，而非只测 token 格式。

### CG-08：部署成功、维护窗口与回滚单元

- **关联**：C #948/#960/#1247/#1248/#1249/#1254/#1255/#1256；O #949/#1253/#1261。
- **共同不变量**：成功表示预期版本及其必要依赖/配置可运行；检查到重启之间不会重新准入；回滚边界不能只恢复一部分发布状态。
- **现态证据**：`host_updater.py:309` 的 is-active 失败仍只 WARN，返回路径 `:537` 可 ok；#949/#1253 不宜再分别增加一层显示补丁。#1254 的 agentctl 严格健康检查不能自动修好另一个入口。#1261 指出配置/依赖与代码回滚边界不同。
- **终态方向**：先统一各入口的成功/失败和维护契约；明确代码、schema 工件、依赖、配置及主机本地资源各自的发布/保留边界。失败后诚实保留维护状态或报告恢复失败，不伪报完成。
- **ADR**：单纯纠正退出码、工件遗漏无需新 ADR；若采用新的不可变 release 单元、切换和整体回滚模型，值得提出独立的部署契约 ADR 候选，不预占编号，先比较最小方案与运维成本。
- **退出标准**：干净安装、运行中升级、pip 失败、就绪失败和回滚失败均可复现；#1255 本轮已 CLOSED 且脚本已有 ON_ERROR_STOP/不足表数失败，但这不代替真实恢复演练。

### CG-09：测试可信边界与资源生命周期

- **关联**：C #934/#941/#1273；O #884/#1295/#1300。
- **共同不变量**：测试只能影响它创建/确认的隔离资源；未验证的环境不可被默认猜测；测试结束后自身会话/线程不污染后续测试。
- **优先工作**：默认隔离容器与测试配置入口、显式 URL 机器护栏、导入期不读取生产配置共同验证。URL/库名规则不应被当作测试身份无生产权限的替代品。
- **止血出口**：#1273 的有限重试可以保留，但要定位未收敛的会话/后台任务。用隔离库记录持锁者和 fixture 生命周期，不能在生产库诊断 TRUNCATE，也不能增加无上限 retry 或吞掉 ERROR。
- **ADR**：遵守现有测试安全边界通常无需新 ADR；不要为了回归通过新建一套测试调度平台。
- **退出标准**：误配先拒绝、不触达生产配置；默认容器路径无意外 skip；跨文件/重复全量运行有资源清理证据。定位并修好非预期竞争后，评估删掉过渡重试，而非默认保留永久分支。

### CG-10：开发生产线的事实、批准与核销

- **关联**：C #978/#1101/#1232/#1234；O #1035/#1246/#1293/#1294/#1298/#1299。
- **共同不变量**：批准的是正确来源/正确 SHA；只删除已被接纳的工作；质量结论绑定已验证版本；缓存和关闭状态不越权成为事实。
- **优先工作**：先修自动审批过滤、分支清理及 CI run 认领的确定错误；保留 Registry 查重、缓存失效与批量核销的收益。红队首有人工出口，不能靠绕过 checks 追求吞吐。
- **复利方向**：按风险加入真实影响面测试和独立复核，收尾链接验收证据；沿用 #1035 的限期观测与退役，避免追加永久僵尸台账。
- **ADR**：API 参数/错误判定修复无需新 ADR；改变队列准入、优先级、审批门槛或 Execution 语义，应先修订 ADR-0034/执行契约及对应工作流，不自动恢复一个未经测量的并发数字上限。
- **退出标准**：错误分支不被批准、复用但未合入分支不被删、失败 CI 不冒充新运行，队列阻塞可见可处置；最终按回归率和总交互成本判断收益。

## 7. 哪些需要 ADR，哪些不需要

| 层次 | 本轮建议 |
|---|---|
| 直接修确定缺陷 | F01、F02、错误成功返回、测试隔离错误、CI 错误参数；不以“等 ADR”拖延 |
| 同步/澄清已有权威 | #942 的 Proposed 状态与已采用 A、默认参数不可变边界；必须显式收口，不能仅改一条注释 |
| 落实已 Accepted 方向 | ADR-0033 的分期准入、ADR-0035 的触发与目标；不再建重复方向，也不把 Accepted 当已实施 |
| 完成已有 Proposed ADR | ADR-0036；更新其已被源码改变的背景，再裁决投递语义 |
| 修订已有方向 | 会话族/宽限 → ADR-0024；脚本不可变/发布形态 → ADR-0020/0033；失租/轮次/多进程语义 → 对应执行/采集 ADR；队列/Execution → ADR-0034 |
| 候选新主题，非本轮决定 | 跨领域事务与可恢复副作用所有权；Agent 发布单元与整体回滚契约。仅在最小方案比较后确认现有 ADR 无法清晰承载时新立，不预占编号 |

新 ADR 的必要条件不是“Issue 多”或“多个 Harness 都建议重构”，而是：**必须选择相互排斥的长期语义，影响跨模块/部署/迁移边界，并且只靠局部修复无法表达这个选择。** 同一主题遵守 `N Proposals → 1 Human Decision → 1 ADR`，本文不占据新的权威位。

## 8. 最小落地顺序与停止条件

1. **先保安全与确定性**：F01/F02 及测试/CI/主机权限高风险护栏；已有在窗 Execution 的 Issue 先协调原执行，不重复认领。本文不自动派单。
2. **先裁边界、后分实现**：优先收口 #942 语义和现有 ADR-0036；CG-02/03/04 明确事务、停止和交付的验收边界，再安排有依赖的 PR。
3. **用最小样板验证治理**：选择一条真实执行链和一条日志链，证明新边界降低补丁数量/回归；没有证据不扩展为通用平台。
4. **完成采用与迁移**：代码合入不等于新脚本已被消费、旧库已迁移、Agent 已升级。根据 Issue 的交付类型核销，不用另建庞大状态机。
5. **删除过渡而非永久堆叠**：为 T 类记录根因承载项、剩余风险、检测来源、下一次复议事件与删除/保留标准。root fix 到位后删除失去必要性的 fallback/重试/双轨；已发布脚本以新版本和退役策略处理，绝不原地改删。

不建议做：一 Issue 一 ADR；治理包一股脑合一个 PR；每个 PR 无差别全量 CI；默认所有修复双 Harness；先建包管理/工作流/调度平台再修已知缺陷；以文件/代码行数代替语义判断；为让旧测试绿而弱化不变量。

多 Harness 综合评审请逐项返回：认可/反证/条件成立、固定 SHA、代码或测试证据、是否已有 Issue/ADR、最小出口与不做什么。F01/F02 优先独立重现；F03 优先找既有裁决证据；F04 优先补渠道真实重试测试。聚合时按共同不变量去重，不按赞成人数或报告篇幅裁决。
