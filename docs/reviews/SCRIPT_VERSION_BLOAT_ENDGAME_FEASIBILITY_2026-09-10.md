# 脚本版本膨胀终态可行性（ADR-0020 全量副本契约）

- 日期：2026-09-10
- 性质：**可行性研究（背景分析，非 ADR、非设计定稿）**。回答 #735 §2「长效机制」提出的问题——「脚本多版本差量分发或共享基础库（而非每个 patch 全量复制代码树）」是否值得立项，以及若立项需要什么决策载体。
- 关联：[`#735`](https://github.com/DUElost/stability-test-platform/issues/735)（脚本版本膨胀治理与退役闭环）、[`ADR-0020`](../adr/ADR-0020-plan-step-one-shot-migration.md)（Plan-Step 一次性切换，版本目录不可变）、[`ADR-0023`](../adr/ADR-0023-script-traceability.md)（脚本溯源与 sha256 契约）、[`ADR-0033`](../adr/ADR-0033-tool-kit-ecosystem-integration.md)（v1.2 §5.6-3 已为本议题留下接口）、`AGENTS.md` 硬不变量（已发布版本目录不可原地修改或删除）

---

## 0. 结论摘要（TL;DR）

1. **复制的 78% 是"不可变 + 可复现"的代价，不是 bug**：`backend/agent/scripts/` 共 67,288 行，其中只有 14,475 行属于各工具族的最新版本，其余 52,813 行是历史版本副本。因此任何削减方案都必须先回答**一个问题**：「历史版本还需要被**重新执行**吗？」——这个问题目前**没有证据支持任何一侧**（§4）。
2. **不该立项的是"共享基础库"（P2）**：它把 78% 的空间成本换成"语义耦合 + sha 契约扩展"——一次库变更会同时改变所有引用它的历史版本的执行语义，除非每个版本 pin 库 sha（那等于把同一份复杂度挪个位置），且 `_` 前缀辅助文件**连 entry sha 都不计**（`check-script-version-immutability.py` 注释自陈），是比改入口更隐蔽的漂移面。
3. **唯一值得新 ADR 的是 P1：把不可变契约从"永久"收窄为"直至零引用退役"**，允许物理删除零引用已退役版本的目录（Git 历史 + 归档仍可回溯）。它是**唯一能在不触碰执行语义的前提下大幅削减行数**的动作，且其前置机具（引用计数诊断 + 退役）正是 #735 本体已在做的事。
4. **P3（差量/打包分发）不必新开 ADR**：它与 ADR-0033 D3 的包存储同向，归入该 ADR §5.4 的条件落地轨道即可。
5. **推荐动作**：先完成 #735 本体的退役闭环（零成本收益），把 P1 作为**独立方向级提案**推进（需 ADR，因为它要改 `AGENTS.md` 硬不变量与 ADR-0020 契约）；P2 明确不做，P3 挂 ADR-0033。

## 2. 不可变性买到了什么（先确认代价换来了什么）

- **DB 侧的 `script.content_sha256` = 扫描那一刻磁盘内容的快照**，扫描遇 sha 不一致只记 `conflicts`、**不动 DB**（`services/script_catalog.py`），所以 DB 期望值被永久冻结；
- 2026-07-31 事故（`tools/dev/check-script-version-immutability.py` 头注）：一次全仓 `ruff --fix` 原地改写版本目录 → 27 行 script 中 18 行 DB sha 与磁盘永久失配 → 平台仅有的两个 Plan 全部在准入阶段 `script_verify_failed`，**派发彻底中断**，且自愈推送修不好（推的是磁盘内容，对不上的是 DB）。这条门禁拦的是"会静默打断生产派发的二值违约"，不是风格；
- 因此**全量副本不是懒政，是"历史可复现 + 派发二值安全"的实现方式**：每个版本的字节独立、可校验、可 pin（`plan_step.script_sha`，ADR-0023），重跑/重试任何历史步骤都能在 Agent 上通过 precheck；
- **已知盲区**：`_` 前缀辅助模块不计入 entry sha，改它们连 `conflicts` 都不报（同门禁注释）；#888 另记"不可变门禁放过旧 `v*` 目录内新增文件"。

**推论**：任何引入"共享代码"的方案，都会把上述盲区从"辅助文件"扩大成"整个共享库"——除非把 sha 契约从「单入口文件摘要」升级为「组合摘要（入口 + 共享库 pin）」，并同步扫描器、Agent verifier/self-heal、CI 门禁与 `plan_step.script_sha` 语义。这是 P2 的主要成本，不是附带成本。

|---|---|---|---|---|
| **P0** | 维持现状 + 完成 #735 本体（修退役诊断工具、退役 47 个零引用活跃版本） | 移除前端可选面与误用面；**不减少仓内行数**（退役只置 `is_active=false`，不删文件） | 零（#735 已在做） | 无需 ADR |

## 4. 本质判据：历史版本还需不需要被重新执行？

- **需要**（真机重跑旧版本、或以旧版本追加步骤）→ 必须保留字节；只能走 P2/P3（存储层优化），且 P2 的语义耦合代价必须被证明小于收益；
- **不需要**（历史版本只需"可审计、可回溯"，不需"可再派发"）→ **P1 就够了**：保留到零引用为止，之后删除目录，Git 历史与归档承担溯源职责；
- **当前证据**：两侧都没有。仓内没有任何"重跑历史版本"的流程或需求记录；同时也没有"因保留全量副本而付出直接故障代价"的记录——膨胀的代价目前体现为**行数、评审噪音与 Agent 上下文成本**，不是生产事故。
- **待验证（未做，需生产只读）**：`plan_step` 对旧版本的引用分布（引用数是 0 是否等于"永不重启"），以及 47 个零引用活跃版本对应的行数占比。两者都属 #735 执行范围的只读统计，本文不代跑（本机可能同时是生产库宿主，测试纪律见 `AGENTS.md`）。

## 5. 建议与出口

1. **立即可做（零成本）**：#735 本体——修 `check_unreferenced_script_versions.py` 的 sync-engine/asyncpg URL 崩溃，退役零引用活跃版本；
2. **P1 单独提案**：若要动，走**新 ADR**（或 ADR-0020 v2）正式裁决「不可变 = 直至零引用退役」，同 PR 修订 `AGENTS.md` 硬不变量与 `check-script-version-immutability.py` 判据；**这是本议题唯一需要新 ADR 的部分**；
3. **P2 明确不做**：在"重复部分相似度"与"库变更影响面"两项量化证据出现前不立项——共享库会把不可变性从"每版独立可校验"变成"跨版共享可变面"，与 ADR-0020 的立意相反；
4. **P3 挂靠**：写入 ADR-0033 §5.6 复议触发器的既有接口（包存储三条触发条件），不重复立法。
