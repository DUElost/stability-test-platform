## 发现与证据

### F01 · ADR-0033 D3 的两套 manifest/DB 派生方向冲突

- **类型 / 程度**：确定的文档契约漂移 / P2；不是“平台脚本 DB 权威已失效”。
- **证据**：`docs/adr/ADR-0033-tool-kit-ecosystem-integration.md:130`–`:138`
  仍写 `tool_manifest.yaml`、注册时编译进 `script` 行、升级外部工具包必须新建
  script 版本；`docs/design/2026-09-external-tools-integration-and-package-architecture.md:148`
  仍以 YAML 为范例。而已落第一切片是 JSON：
  `docs/notes/feature/2026-09-22-adr0033-phase-b-slice1-3075.md:10`–`:33` 明确
  **外部工具** manifest → 包发布 → 站点副本 → cache，且禁止反写 `script` 表；
  `tool_manifest.json:1` 是现行载体。
- **边界 / 建议**：0051 D3 的“DB script catalog 唯一运行时权威”适用于**平台
  script 版本**；#3075 C2 的 Git manifest 唯一发布事实源适用于**独立外部工具**。
  在被接受的 ADR-0033 D3 和设计里按对象分开这两条路径，写明何时建立 `script`
  行、何时绝不能建立；同步 YAML/JSON、`tools/`/`packages/` 的当前布局，不再用
  一句话兼称所有工具。本轮不代 owner 修改方向级裁决。

### F02 · D0 新族门禁检验声明，不检验被声明的内容

- **类型 / 程度**：设计风险 / P2；已跟踪
  [#3093](https://github.com/DUElost/stability-test-platform/issues/3093)（本轮查询为 OPEN）。
- **证据与触发**：`tools/dev/check_new_script_family.py:75`–`:101` 从 PR diff/提交
  文本抽取 `ADR-0033 归类：<family> = platform-authored` 即放行，`external-tool`
  或未声明才判红；未读取族内容证明“平台自研”。这能拦**未声明**与**主动承认外部
  工具**的 PR，不能证明自声明为 platform-authored 的新增族确实没有第三方源码。
  [#2546 的 2026-09-21 勘误](https://github.com/DUElost/stability-test-platform/issues/2546)
  已明确 `unisoc_probe`、`unisoc_signal_trigger` 等平台自研脚本不是 D0 对象；
  **族数/版本目录数不能充当外部工具进入量**。
- **建议**：维持分级准入边界，但把结果明确标成“声明已核”而非“源码已核”；
  对带外部资产族增加独立证据或人审记录。不要把所有新平台脚本误判为 D0 违规。

### F03 · D2 Tool Contract 自动门禁只验 fixture，且可 exit 0 跳过

- **类型 / 程度**：确定的自动准入覆盖缺口 / P2；
  [#3094](https://github.com/DUElost/stability-test-platform/issues/3094) 本轮查询为 OPEN
  （Issue 标签 P3；本轮按自动准入缺口重评为 P2，不代表问题影响已在生产发生）。
- **证据与触发**：`tools/dev/verify_tool_contract.py:33`–`:35` 默认靶子是样板；
  `.github/workflows/ci.yml:250`–`:254` 与 `scripts/run_gates.py:130`–`:135`
  都未传 `--entrypoint`，所以 CI/quick 只能证明**验证器和 fixture 正常**，不证明
  任何新族满足 `--check-env`、`summary.json` 或退出码契约。`tools/dev/verify_tool_contract.py:186`
  –`:190` 的 `STP_VERIFY_TOOL_CONTRACT=0` 打印 SKIP 并返回 0；
  `tools/dev/env_inventory.py:39` 仅扫描 `backend/`，未覆盖这条工具开关。
- **现有防护 / 建议**：脚手架支持手动传真实 entrypoint，CI 中的 D0/manifest
  检查也存在，但并不替代 D2 验收。把新增工具清单接入实际 entrypoint 扫描，
  或将 CI 名称如实标成“fixture 自检”；跳过须可见、不能被解释为准入通过。

### F04 · S15③ 没有实现“ADR 版本 bump 同 PR 改归属表”

- **类型 / 程度**：确定的承诺与判据差异 / P2；#2546 Close 后遗留。
- **证据与触发**：`docs/design/2026-semantic-ownership.md:98` 把“版本 bump 且头部
  已写归属域 → 本表须同 PR 出现”列为已生效；但
  `tools/dev/check_governance_surface.py:945`–`:960` 的 S15③ 只遍历当前 ADR 字段，
  检查所填 **key 是否在表里**。调用点 `:1739`–`:1752` 不读取 base/head 的 ADR
  版本 diff，也不检查归属表是否出现在同一 PR。
- **影响 / 建议**：若已有 key 的 ADR 内容和版本变化、表行未变，S15 仍可绿；
  这不推翻 S15① 的 key 唯一、② 的锚恰命中一次、⑤ 的 Accepted 状态检查。
  要么实现可核的 diff 联动，要么把 §4.2③ 明确降为人工纪律，不能称已由门禁保证。

### F08 · manifest 与脚本目录的数字各自成立，不能混作一套

- **类型 / 程度**：口径提示兼文档维护 / P3。
- **证据**：本轮仅对仓内文件计数：`tool_manifest.json` 是 **36 族 / 211 条目**，
  含 `Start-Log-Scan` 外部工具样板；`backend/agent/scripts/` 是 **35 族 / 210 个
  `v*` 版本目录**。0051 首页 `:9` 的 35/210 是**平台脚本子集**，不能当全 manifest
  口径；其 D2 `:103` 还保留历史的“208 个版本目录”，而阶段表 `:191` 已写“210 个”。
  这与 F06 的“未发布”旧描述须一起消歧。
- **建议**：每次报数标注“平台脚本子集”或“整个 manifest”，注明计数时点；
  不因数字不同误判包丢失，也不以 Note 的站点发布记录反推出每台主机已使用包。
