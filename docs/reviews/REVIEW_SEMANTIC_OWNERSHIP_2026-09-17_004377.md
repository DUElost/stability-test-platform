## 重点问题 F1–F7 逐条回答

- **F1 立项必要性**：成立，且判据应是**已发生的歧义**而非文档数量——X1（三处字面相同的「唯一权威」）与 X3（三处归属）是实证；
  「就地写清」路线（C）的成本已由三处双标证明：**#530 的逐对收口只解决了日志域一次，X1/X3 仍在**。
  量化判据建议：**四域名单内出现 ≥3 处「字面相同、限定词不同」的权威声明**（本基线 X1 占 3 处）即触发立项。
- **F2 是不是第 5 份平行权威**：**取决于是否挂内容裁决权**。挂上 → 会（A-02）；只挂归属权 + 表内一行一 owner
  + 文件体量受 S6 约束 → 不会。它与四份既有文档的边界：storage-roles 管**角色语义**、execution-contract 管**执行语义**、
  DOC-MAP 管**导航**、AGENTS.md 管**不变量**；四者都不回答「归谁」，故无 supersede 关系。
- **F3 判据可机读性**：三条中只有**锚的存在性/唯一性**可机读；「同一概念 ≥2 owner」不可机读（X2 是反例：
  分层权威在字面上与「双标」同形）。→ 降级方案不是「改人工清单」，而是**把判据移到表内**（见 A-01/F7-01）。
- **F4 三处收口口径**：见 §X1–X3，三条均为**单行裁决**且不需改任何 ADR 的决策方向。
- **F5 F-1 窗口的时序**：**不能等**——因为该条**不在 S11 锚表内**（F1-03），等下去只有「无人察觉」一种结果。
  先做两件可机读的事：① 给该条挂锚（或在总原则节引入锚表）；② 采纳 F5-01 的「语义 owner 指针 + 版本 bump 同 PR 复核」。
  「S1x 校验锚点与 Accepted ADR 语义一致」的**一般形态不可行**（自然语言蕴含不可判定），不要写进方案。
- **F6 多 Harness 适配**：`归属域` 字段取「触碰即补」，四域名单内 ADR 先补；与 ADR-0034 的衔接点是
  **S12 已有的「版本记录块」机制**（ADR bump 时本就要动头部行与派生面），把「归属域行须同 PR 复核」搭在它上，不新增常驻入口文本（S9 约束）。
- **F7 验收可测性**：建议三条，全部可机读：
  1. S15 自测**红绿双向**：合成「同一概念两行 owner」「锚命中 0 处」「锚命中 >1 处」三种输入，前一种对该概念判红、后两种判红；
  2. **ADR bump 涉及归属域行 → 该表须同 PR 出现**（可用 S12 的版本记录块触发，机械可判）；
  3. X1/X2/X3 收敛为「表内一行 + 被指向文档一行交叉引用」，且这三个文件里**不再出现字面相同的「唯一权威」**（正则可判，且是对**存量**的收敛判据）。
  去掉 issue 原建议里的「出现新的双标时 S15 必红」——「新的双标」本身不可机读。
