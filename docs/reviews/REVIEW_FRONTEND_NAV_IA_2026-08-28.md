## 三、开放问题裁决（§8）

### Q1. 档位：方案 A vs B —— **裁决：方案 A**

- A 是纯导航树重排：path 全保持、影响面收敛于 `Sidebar.tsx` / `AppShell.tsx` / `router/index.tsx` / 3 个页头 title / 相关 vitest 断言，与 AI 助手 PR 可完全解耦（PR1 可独立先行）。
- B 的三段式大重组 + 页签形态统一波及 6+ 页面与路由结构，与 AI 助手 PR 叠加会放大回归面；页签统一已有 C2 立案（ARIA 部分），形态统一应独立专项。
- 补充理由：P4 页签形态统一与 P5 面包屑补齐属「体验增强」非「导航可理解性」问题，不阻塞 AI 助手落地。
- **注意点**：定时调度移入「执行」组——调度虽是低频配置，但归入「执行」组语义可辩护（预排执行），且调度是普通用户可见功能不能进 admin 组；该归类合理，采纳。

### Q2. 「项目」组去留 —— **裁决：保持独立一级**

- ADR-0029 明确锚定「项目」为一级导航分组（`ADR-0029:329`），并入「执行」组须回写该 ADR——为一页导航美学付出架构决策修订成本不划算。
- 项目是跨测试编排/测试资产/分析报告的**横向聚合实体**（详情页含设备/计划/结果/jira 四块），独立一级语义成立。
- 方案 A 已将其位置保持不变（概览之后、测试编排之前），与 ADR-0029 完全一致。

### Q3. AI 入口形态 —— **裁决：侧边栏 pinned（v1），Header 抽屉留 v2**

- ADR-0031 v1 前端形态是「/assistant 独立页」，pinned 入口是成本最低的直接落地路径；Header 抽屉是增强壳层（组件已按可复用拆分，实施计划 §4）。
- 「AI 是横切入口非业务分类」原则正确：不放「平台管理」（非 admin 也要用）、不埋业务组（语义不符）。
- **实现注意点**：
  1. collapsed 模式缩为图标 + tooltip（文档已列），需与 `Sidebar.tsx` 现有 collapsed 渲染路径（`opacity-0 w-0`）保持一致；
  2. 移动端抽屉侧边栏同位置出现（`isMobile` 分支）需单独处理；
  3. pinned 块建议带明确 `aria-label`（如「AI 助手」），非链接样式注意与业务组的视觉区分不依赖纯颜色（可访问性）；
  4. admin 齿轮入口在助手页头 → `/settings/ai-assistant`，与实施计划 §4 一致。

### Q4. 命名方向 —— **裁决：页头改「脚本库」（方案 A 建议）**

- 侧边栏是分组导航，组名（脚本库/WiFi 资源池）是实体词，与组内项语义一致；页头用「管理」后缀与「平台管理」组重复且掩盖实体本质。
- 反向方案（侧边栏改「脚本管理」）会造成「测试资产」组内混入非管理语义项，组名矛盾。
- **实现注意点（文档 §7 建议显式列出）**：命名对齐将破坏 3 处既有测试断言——`HostsPage.test.tsx:230/238/247`（「主机管理」→「主机集群」）、DevicesPage 页头断言（如有）、ScriptManagementPage 页头断言（如有）。PR1 需同步更新断言而非仅快照。
