## 4. Q3 修复模式：五稿一致部分 + 本稿补充

### 4.1 一致成立的骨架（第一性原理层面，无需再议）

| 决策 | 为何成立 |
|---|---|
| 审查与修复分离 | 避免审查者为自己刚写的代码背书 |
| Registry 是 visibility-only，非调度器 | 并行不伪造全局锁；`effective_scope = declared ∪ derived`（diff 为 ground truth） |
| issue 为工作单元 + 独立 worktree/branch | 可追溯、可并行、可回滚 |
| 同主题 ≥3 issue → 升格 ADR | R11 #1117/#1120/#1122 → ADR-0036：避免点对点补丁语义打架（**真复利**） |
| Agent Note 四段式 | 降低 harness 切换成本；**实测合规率 100%（09-07 后）** |

### 4.2 本稿实测的模式数据（补五稿之数）

**吞吐（PR 开→合中位延迟，按合入日）**：

```

**这是「集成收尾是瓶颈」的量化证据**，而非印象。

**Execution Registry 漂移（削弱其可见性价值）**：

```

**main 上不存在的路径**。一个 69% 陈旧的仪表会制造虚假安全感——
正是 #1035（ADR-0034 Evidence 台账）自杀条款要防的情形。

**FIFO 死锁机制（本稿核对 `scripts/ci/pr-automerge-queue.sh` 确认）**：
队首 = `sort_by(.createdAt)` 最老的 open non-draft PR；仅队首挂 auto-merge；
任一 required check 非 SUCCESS 即 `exit 0`（"skip head update"）；
`pr-update-branch.yml` 调用同一脚本 → **自救路径被同一道门挡住**。
脚本已有 `cannot update pr branch due to conflicts` 的**冲突**解毒路径，
但**无「红 check」解毒路径**；#1246 建议的三条处置（逃生重试 / 显式告警 / 人工打破）**至今未实施**。

## 6. 对 R01–R15 的总体定位（收敛结论）

**R01–R15 已完成的**：15 个分区的**静态只读**审查，产出 177 条发现（107 已关），
建立了「台账 + 子项 issue」的可追溯结构，并驱动了一批高质量的根因修复。

**R01–R15 未完成的**（不构成「全面审查交付完成」）：
1. 跨区收口（总纲 §6 硬条件）——**未开始**；
2. 逐维覆盖记录与逐轮区域报告——**零存在**，导致覆盖完整性不可审计；
3. 动态/运行验证——**15/15 轮均为静态**；
4. 存量的 150 条 pre-R-era 缺陷池——**未被任何轮次纳入**；
5. 治理面自身的一致性——**未被任何轮次纳入**。

**因此**：可以宣称「R01–R15 分区静态审查已开展并产出有效发现」；
**不可宣称**「全面审查覆盖已完成」或「审查面已穷尽」。
