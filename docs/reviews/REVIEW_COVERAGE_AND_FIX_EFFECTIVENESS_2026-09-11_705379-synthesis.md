### 1.4 系统性与物理运行时盲区（深度横切面）

依据底层代码与测试的深度审查（详见 [`docs/notes/audit-failure-mode-resilience.md`](../notes/process/2026-09-11-failure-mode-resilience.md)），R01–R15 静态分区审查还遗漏了以下六项致命的系统性/运行时横切面：

1. **混沌工程与真实依赖断死韧性（Chaos & Outage Resilience）**：
   - 全仓 `chaos/toxiproxy/circuit-breaker` 检索命中为 **0**，无任何真实依赖断死或网络分区测试；测试全部依赖 `monkeypatch`（如 `test_health_saq.py:105` 虚拟异常）；
   - [`backend/main.py:147`](../../backend/main.py#L147) `redis_client = await aioredis.from_url(...)` **全局缺少 `socket_timeout` 与 `socket_connect_timeout`**。黑洞网络分区下，所有 SAQ 入队与 Socket.IO 会话操作将直接挂死在操作系统 TCP 超时上，导致控制面雪崩。
2. **重连风暴与退避抖动缺失（Reconnect Storm & Jitter）**：
   - [`backend/agent/socketio_client.py:212-230`](../../backend/agent/socketio_client.py#L212-L230) 与固件刷机重试中，重试退避序列为完全确定的固定步长（1s, 2s, 4s...），全仓业务代码中 `jitter`（随机抖动）命中为 **0**；
   - 一旦控制面重启或网关闪断，全网 Host Agent 将在完全一致的节拍同步发起重连与 Claim 请求，击垮控制面与数据库。
3. **物理实机、硬件外设与驱动链路（Physical Device & Hardware Acceptance）**：
   - R01–R15 审查均在虚拟环境完成；USB Hub 物理端口掉电重置、ADB 守护进程悬挂、Fastboot 刷机半途断电的异常状态机、AEE 抓取签核，全部处于 `pending` 状态；静态代码通过不等于物理硬件抗干扰。
4. **长跑寿命与资源/句柄泄漏（Longevity & Leak Audits）**：
   - 平台自身作为 7×24 小时系统，缺乏长跑防衰减审查：
     - [`backend/realtime/log_writer.py:20-26`](../../backend/realtime/log_writer.py#L20-L26) `_locks: Dict[int, asyncio.Lock]` **无任何淘汰机制**，随不同 `job_id` 单调递增泄漏；
     - [`backend/agent/heartbeat_thread.py:84,185`](../../backend/agent/heartbeat_thread.py#L84) `_pending_reconnected_serials` 在心跳失败时无限累积。
5. **跨时区、时钟阶跃与 NTP 风险（Timezone, Clock Skew & NTP Steps）**：
   - Agent 脚本多处使用 `time.time()` 进行超时死等（如 [`mtbf_setup.py:236`](../../backend/agent/scripts/mtbf_setup/v1.3.0/mtbf_setup.py#L236)），而非单调时钟 `time.monotonic()`。NTP 对时回跳时死等挂死，前跳时用例早退；
   - 多处把本地 naive 时间通过 `replace(tzinfo=timezone.utc)` 强转修正，导致乐观锁冲突误判（如 `plans.py:718`）。
6. **客户端写请求幂等性缺失（Client-supplied Idempotency）**：
   - 全仓 104 个写端点中，**0 个支持客户端传入 `Idempotency-Key` 或 `X-Request-Id`**，仅有服务端派生的内部防重；前端或 Agent 在网络抖动重试 POST 时无端到端防重保护。
7. **文档-实现漂移与「修复后残留」波浪**：
   - 治理面本身需门禁（R15-F07 #1299）；轻量 PR CI 导致非确定性缺陷漏网；分区点修导致次生缺陷波浪（如 #1174–#1177、#1203–#1204）。

### 2.4 削弱复利的系统风险（领单时自觉纠偏）

1. **优先级偏斜**：易并行的 P2 快速合入，同时 pre-R 高杀伤力单仍 open（例：#789 终态计数竞态、#799 lease lost 双驱动、#810 MTBF 假阳性）。有效 ≠ 对准主链风险下降曲线。
2. **验证层停在 CI**：静态发现 → 单测/门禁绿 → merge。对 TOCTOU、真机、存储、长跑，只证明隔离环境可回归。
3. **关单纪律**：合入身份可能影响原生 `Closes #N`；合入后须核销 issue state。Acceptance checkbox 未勾仍可 closed——以代码+测试+Note 为 ground truth。
4. **Revisit 死信**：多数 Note 有 Revisit；若不进台账跟踪，终态出口不会自动发生。

**第一性原理**：关闭单位 = **错误路径被不可逆堵住 + 回归锁住 + 契约/文档一致**，不是 issue 状态翻成 closed。

## 3. Q3 — 修复模式：准确 / 有效 / 可持续

### 3.1 现行流程

```text
只读审查 → 确认是否为问题 → 开 issue（Rxx-Fyy + 总表）
  → harness 自行 declare（worktree + scope + --issue）
  → 独立分支 PR → required checks → FIFO auto-merge
  → Agent Note（Decision / Alternatives / Verification / Revisit）
  → 合入后 issue 核销 →（需求结束）
```

### 3.2 为何方向成立（第一性原理剖析）

| 原则 | 体现 | 判定 | 第一性原理价值 |
|---|---|---|---|
| **认知边界最小化** | Issue 为粒度划分工作单元 | ✅ | 大模型单次推理注意力与上下文窗口稀缺；将大系统解构为离散 Issue 可杜绝发散与胡乱重构 |
| **无锁物理隔离** | 独立 Git Worktree + 独立分支 | ✅ | Agent 间不通信、不共享内存上下文，以 Git 文件系统为硬边界，避免多 Agent 脏状态冲突 |
| **确定性兜底非确定性** | 确定性 CI 门禁 + FIFO 串行合入 | ✅ | 大模型代码生成本质是非确定性的，只有数学级严格的 CI 规则和主干单车道集成能杜绝系统腐化 |
| **事实来源唯一** | Registry visibility-only，以 Git Diff 为准 | ✅ | 避免伪造中央调度器；登记仅供可见性与审计，Diff 是物理现实权威 |
| **知识资产化** | Agent Note 四段式（决策/替代/验证/Revisit） | ✅ | 显式留存设计决策与终态出口，将离散经验转化为跨 Harness 复利资产 |
| **选择权原则** | 谁用哪 harness 由开发者决定 | ✅ | 避免调度器幻觉，确保人始终对整体系统演进拥有最终把控 |

### 3.3 不可持续的实证瓶颈（长期主义复利漏损）

| ID | 瓶颈 | 证据 | 本质与长期危害 |
|---|---|---|---|
| **W1** | **FIFO 队首中毒无解毒** | #1246（队首 required check 红 → 全绿 PR 亦停） | 编码可无限并发，但合入是绝对串行的稀缺通道；无解毒机制会导致多 Harness 并行反噬吞吐 |
| **W2** | **局部极优与全局架构碎片化** | 易修 P2 快关 vs 主链/pre-R 重单积压；同模块多补丁 | 各 Harness 本能是“最小改动关闭本 Issue”，导致 10 个 Issue 带来 10 个防御补丁，代码复杂度激增 |
| **W3** | **轻量 PR CI 与运行时深度风险剪刀差** | PR 仅跑 quick checks；全量/长跑留在夜间 | 快速门禁放行了浅层代码，但深层并发死锁与长跑泄漏在 Harness 关闭退出后才爆发，权责断裂 |
| **W4** | **Issue 工厂化与吞吐失衡** | ~244 open + 15 份台账 | 审查开单速率极高，但人类审阅与架构收口吞吐有限，导致低价值 Issue 淹没核心架构问题 |
| **W5** | **过渡止血缺乏收割机制** | #1273 重试掩盖连接泄漏 | 缺乏定时清理倒计时，临时止血方案随 PR 合入被遗忘，永久钙化为系统技术债 |
| **W6** | **决策类并发与权威漂移** | ADR-0035 曾双份权威 | 架构决策无法通过并发多 Agent 自行收敛，必须依赖人工裁决与 ADR 先行 |
| **W7** | **合入身份与关单耦合** | 密集合入日漏关 | 自动化关单受 PAT 与 mergedBy 影响，导致实际代码已合入但 Issue 仍挂起 |

**裁决：保留现行模式；把投资从「盲目加快单点关单」转到「解毒集成 + 治理包组合攻坚 + 跨区收口与真实混沌验证」。**

### 3.4 长期主义复利的四大关键升级

1. **启动总纲 §6 跨区端到端收口（P0，阻断盲目扫尾）**：
   - 停止继续在单个 R 区做低价值静态“挖洞”；
   - 必须以两条端到端主链（执行链、日志链）为主线，逐跳对证生产者、消费者、持久化与恢复协议，消除边界盲区。
2. **建立「同类聚类升格 ADR」硬规则（防止架构碎片化）**：
   - **同一模块若出现 ≥3 个同类 Issue，禁止 Harness 继续单独开单点修补**；必须先形成 ADR 或统一重构方案（如 GB-01…GB-11 模式），由单单认领转为包级推进。
3. **设立「过渡止血技术债追踪台账」（杜绝负债钙化）**：
   - Agent Note 中凡含有 `Revisit` 标注（如未定位根因、有界重试、临时互斥）的，一律打上 `tech-debt:revisit` 标签，设立 14–30 天强制清理倒计时，不完成不得视为主链健康。
4. **推进真实环境与混沌验证（突破 Mock 沙箱局限）**：
   - 在测试体系中补充真实依赖断死测试（Redis/PG 黑洞分区、进程硬杀 SIGKILL）；
   - 在真实物理手机和 USB 外设环境下执行 MTBF/刷机断点恢复 Acceptance 签核。

## 8. Q4 — 止血、组合治理与 ADR 升格

### 8.1 判定框架（第一性原理 → 长期复利）

| 问 | 止血 / 偏斜 | 可持续 / 复利 |
|---|---|---|
| 消除了什么？ | 堵住一条已知错误路径或加约束（预算、互斥、重试） | 消除**未定义语义**或收窄**不变量**（契约、状态机、单一权威） |
| 复杂度去向？ | 每修一单加一层特殊 case，概念数不降 | 概念数减少或冻结；新行为走统一机制 |
| 测试锁住什么？ | 单点回归 | 不变量 / 契约级回归 |
| 文档状态？ | Agent Note 写 Revisit 但无跟踪载体 | ADR Accepted 或 design 权威 + 实现 issue 闭环 |
| 再发同类 bug？ | 高概率（同根因换入口） | 低概率（机制覆盖一族） |

**升格 ADR 的触发（与 P1-5 一致，此处可操作化）**：

1. **同主题 ≥3 个 open/closed issue**，且修复开始**互相引用**（如 #1085 依赖 #1123 同型残留）；
2. **已关单仍留开放 follow-up** 指向同一未定义语义（如 R11 通知三单 → ADR-0036 Proposed + #1167 仍 open）；
3. **点修扩散到 N 个脚本版本**（#1028 四脚本同型 `_state_file`）而未抽象公共契约；
4. **进程内止血**已知无法覆盖下一部署形态（#1123 互斥 vs ADR-0027 多 worker）。

**防腐纪律**：禁止在已有治理包内再开「第四个点修 PR」而不先更新包内 ADR/设计裁决；过渡修复必须在 issue 或 Revisit 台账标明**终态出口与移除条件**。

## 9. 维护规则

- 若审查模式或 ADR-0034 **方向级**变更：先修订 ADR/契约，再回溯本文件 §3。
