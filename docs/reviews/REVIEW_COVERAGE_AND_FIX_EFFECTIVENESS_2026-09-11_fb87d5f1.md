## 3. 修复闭环模式审计（多 Harness 流程）

### CA-W01 FIFO 单车道无解毒路径（确定缺陷，P1，映射 #1246 / R15-R02）

- 09-09/10 实测：队首 #1205 一个确定性红 check 冻结 main，12+ PR（含全绿）无法合入；
  `pr-automerge-queue.sh` 对队首非 SUCCESS 直接 `exit 0`，自体无更新分支的自救路径，只能人工打破。
- 现状：仅加遥测（#1190），解毒路径仍 OPEN。全部变更只走这一条道 ⇒ 单点即全局。
- **建议去向**：CA-D03（沿用 #1246 三选项，建议组合 1+2：一次 `update-branch` 逃生 + blocked 结构化告警）。

### CA-W02 承载「无人复核合入」的自动化自身有 P1 缺陷（确定缺陷，映射 #1293 / #1294）

- #1293：自动审批脚本 `head_branch` 过滤实际无效（只读 API 复现：不存在分支名仍返回 ≈9744 个待审批运行，含 main），
  而仓库 required approvals=0，这道闸是唯一「审批者」——审批边界失效。
- #1294：夜间清理可能删除含未合入提交的复用分支。
- 两者均为「流程自动化层」缺陷：在修复落地前，合入链路的完整性有已知缺口。
- **建议去向**：按 R15 修复波优先级先行（如 #1304/#1305；#1303 已合入），综合轮确认回归覆盖。

### CA-W03 审查 SOP 与执行契约的纪律不对称（过程风险）

- 执行侧：`execution-contract.md` §10 明确「实现不得静默重新定义 Contract 语义」，
  且契约已版本化到 v1.12、有自测门禁（`run_gates.py` 的 `ai-work` gate）。
- 审查侧：交付形态从「逐轮报告」漂移为「GitHub issue 台账」却没有回改总纲（CA-C02）；
  同一仓库内两套纪律标准不一致。
- **建议去向**：与 CA-D01 合并裁决，按「契约先行」同标准修订总纲。

### 闭环结论

- **准确**：是。流程切中真实约束——单人注意力、外部平台可靠性、验证可信度；各机制职责与边界有权威契约定义且被 dogfood。
- **当前有效**：是。5 天 182 个 PR 合入（中位时延 0.4h）、158 条 Registry 记录约 92% 收敛，单人在环下该链路在真实产出。
- **可持续（复利）**：取决于四项收口——(a) #1246 解毒路径；(b) #1293/#1294 修复与回归；
  (c) 类级修复升级 + Revisit 收割；(d) 审查总纲版本化修订。
  **复利台账**：复利资产 = 回归测试、Agent Note/ADR 决策记忆、门禁机制、Registry 协同、backstop 自动化；
  复利负债 = 系统性根治单悬置、FIFO 单车道、审批/清理边界、未收割的 Revisit。
