## 0. 结论摘要（TL;DR）

1. 现状七大问题（§1.3 P1–P7）：admin 入口散落三层三处、僵尸路由、分组频次语义混乱、页签三种实现、跨页深链无Breadcrumb、命名不一致、AI 入口待定。
2. **推荐方案 A（保守档）**：组数 7→7，只做语义重排——新增「平台管理」admin 组收拢 5 个散落入口、解散「运营配置」、AI 助手做侧边栏置顶 pinned 入口、删除僵尸路由、命名对齐。**全部路由 path 不变**，零书签/肌肉记忆成本。
3. AI 入口设计：侧边栏 Logo 下 pinned 特殊块（视觉与业务组区分），v1 点击进 `/assistant` 页，v2 预留全局抽屉（Header 独立按钮）。
4. 方案 B（进取档：三段式大重组 + 页签形态统一）列为备选，建议拆独立专项不随本期。

## 2. 设计原则

1. **三层信息架构**：工作区（日频操作）→ 资产与成果（周/月频）→ 平台管理（admin 独占、物理收拢一处）。
2. **路由 path 全保持**：只重排导航树，URL 零变化——书签、深链、肌肉记忆零成本。
3. **admin 入口单一来源**：侧边栏「平台管理」组是唯一入口；UserMenu 只留账号域（文档/修改密码/退出登录）。
4. **实体命名一致**：侧边栏短名与页头 `{实体}管理` 共用同一实体词（脚本/主机/设备…）。
5. **AI 是横切入口不是业务分类**：不混入任何业务组，视觉上独立标识。

## 3. 目标导航树（方案 A 保守档，推荐）

```
（Logo 区）
★ AI 助手            ← pinned 特殊入口（§5），不属于任何组
────────────
概览                 仪表盘
项目                 项目登记簿            ← 保持独立一级（ADR-0029 锚点，位置不变）
执行                 Plan 管理 / 执行 Plan / 执行记录 / 定时调度
                      （定时调度自「运营配置」移入——调度的本质是预排执行）
测试资产             脚本库 / WiFi 资源池
主机与设备           主机集群 / 物理设备    （文件服务器移出）
分析报告             测试结果 / 问题追踪
平台管理 (admin)     用户管理 / 通知管理 / 审计日志 / 文件服务器 / 系统设置
                      （前三项自 UserMenu 上收；文件服务器自「主机与设备」、
                        通知管理自「运营配置」移入）
────────────
（收起按钮）
```

与现状的差异共 6 处：① 新增 pinned AI 入口；② 「运营配置」解散（定时调度→执行组、通知管理→平台管理）；③ 新增「平台管理」admin 组置底收拢 5 项；④ UserMenu 删 3 项；⑤ 删除 `/resources` 路由与目录；⑥ 命名对齐（§6）。**未动**：7 组骨架、全部 path、非 admin 可见项集合。

效果：admin 5 页从「三层三处」变「一层一处」；低频 admin 项整体沉底；用户级导航（非 admin 可见）从 12 项缩到 11 项且全部是高频工作区与资产。

## 4. 方案 B（进取档，备选不推荐本期）

三段式大重组（工作区 = 概览+执行中心+项目 / 资源与成果 / 平台管理）+ 页签形态统一（PlanRunLogs 并入详情页内 tabs、页内 tabs 统一单一组件 + ARIA）+ 全站面包屑补齐。**不推荐本期**的理由：改动面波及 6+ 页面与路由结构，与 AI 助手 PR 叠加会放大回归面；页签统一已部分立案（C2），应独立专项。方案 A 合入后若仍有痛感再启动。

## 5. AI 助手入口与布局设计

### 5.1 侧边栏 pinned 入口（v1 采纳）

- **位置**：Logo 区与第一个导航组之间，全宽 pinned 块——「✦ AI 助手」，用主题色渐变/描边与业务项做视觉区分（不占业务组坑位）。
- **行为**：点击 → `/assistant`（v1 独立页，路由 `/assistant` 按实施计划注册）。admin 额外在助手页头见齿轮入口 → `/settings/ai-assistant`。
- **状态标识**（预留）：运行中任务时显示呼吸点（后续从 action 状态派生，v1 可不做）。
- **collapsed 模式**：缩为图标 + title tooltip，与其他项一致。
- **移动端**：抽屉侧边栏内同位置出现。
- **理由**：助手是横切工具（任何工作流都可能唤起），置顶 = 高频 + 全局可见；不放「平台管理」（非 admin 也要用）、不埋业务组（语义不符）。
- **实现注意点（审核 Q3 补充，v1.1 采纳）**：① collapsed 分支与现有渲染路径保持一致（`Sidebar.tsx:142-145` 的 `opacity-0 w-0` 收缩式）；② `isMobile` 抽屉分支单独处理；③ pinned 块带明确 `aria-label`「AI 助手」，与业务组的视觉区分不得依赖纯颜色（可访问性）；④ admin 齿轮 → `/settings/ai-assistant` 与实施计划 §4 一致。

### 5.2 助手页内布局（承接实施计划 §4，此处固定形态)

左栏（280px，可收起）：会话列表（新建/搜索/删除）。右栏：消息流 + 底部输入框（Enter 发送 / Shift+Enter 换行）；操作卡内嵌消息流中；日志面板折叠展开。页头齿轮（admin）→ 设置页。未配置时顶部横幅引导（admin「前往设置」/ 用户「联系管理员」）。

### 5.3 v2 预留：全局抽屉

Header 右侧（NotificationBell 旁）加悬浮 ✦ 按钮唤起全局抽屉（Sheet 组件），与侧边栏入口并存；对话组件已按可复用拆分，届时仅新增壳层。**v1 不做**。
