# ADR-0041：独立站点交付与管理边界

- 状态：**Accepted**（独立站点、轻量导航、统一交付运维及只读总览获用户确认；功能未实施，SSO 当前不纳入）
- 版本：1.1
- 版本记录：v1.0 确认独立站点与账号基线；v1.1（2026-09-14）用户接受其余管理方案、暂不考虑 SSO，明确导航/只读总览的分期交付范围
- 日期：2026-09-14
- 决策者：本需求用户
- 标签：多站点, 部署, 运维, 账号, 故障隔离
- 需求：[`多城市独立站点交付与运维 PRD`](../prd/2026-multi-site-delivery.md)

## 背景

城市 A 已有内网平台，城市 B、C 将配置同类控制服务器、日志服务器、Host 和 Devices。
目标是降低首次安装和长期维护成本，而不是首先建立跨城市共享的运行控制面。

2026-09-14 用户确认独立站点架构，并表示可按各站点现有入口和账号管理体系开设，同时要求评估更便捷的多站点管理方式。
同日用户进一步确认“当前暂时不考虑 SSO，其他方案接受”。轻量站点导航、统一交付运维和只读运维总览因此纳入本需求，仍按 PRD 分阶段落地。
本次确认不扩张为共享业务控制面、统一账号或跨站点写操作；SSO 不作为当前开发项，也不作为交付前置条件。

## 决策

### D1. 以独立站点作为运行与故障隔离边界

- 各站点拥有自己的控制面、数据库、Redis、中心存储、Agent 和设备资源；现有站点内执行契约保持不变。
- 不跨城市共用业务数据库、队列、租约或文件挂载；本地核心执行不依赖跨城链路、统一门户或发布服务持续在线。
- 外部提单、通知等集成单独声明依赖及不可达行为，不能由“站点自治”推导出所有外部功能均可离线工作。
- 单站点多实例/HA 按 [ADR-0027](./ADR-0027-control-plane-horizontal-scaling.md)单独评估，不是增加城市的前置条件。

### D2. 统一交付与运维规则，不统一运行时事实库

- 共用代码、受支持的发布体系、安装/升级/备份恢复规程；新增城市主要增加站点输入，而不是长期维护城市分支。
- 发布物、站点配置、秘密与运行数据分离；不复制 A 的业务库、密钥或 Agent 状态作为 B 的初始化方式。
- 各站点独立选择维护窗口；统一运维工具仍须服从站点授权、升级门禁、活跃任务保护和版本兼容性要求。
- “同一套运维流程”不要求建设持有所有站点管理员凭据的中央远程执行服务；具体交付工具按 PRD 分期实施。

### D3. 入口与账号继续站点独立，SSO 当前不纳入

- 新站点沿用现有登录、管理员开设账号和站点内角色管理；当前不做 SSO 接入、身份提供方选型或统一用户数据库。
- 同名账号不自动视为同一身份，A 的管理员不自动获得 B 的权限；跨站点任职/离职需要逐站点授予或收回权限，不能假定删除一个站点账号会同步其他站点。
- 不通过同步密码、共享 JWT 签名密钥、传递浏览器 token 或扩大 Cookie Domain 来模拟统一登录；仍遵守 [ADR-0024](./ADR-0024-browser-session-security-hardening.md)。
- SSO 仅在用户未来重新提出需求时再评审，不预留当前排期，也不为此提前改动账号模型或会话协议。
- 新网段、运维信任边界或主机审计要求仍须核对 [ADR-0035](./ADR-0035-agent-host-identity.md)触发条件；本条不替代 Agent 身份安全评审。

### D4. 轻量导航与只读总览纳入交付，但不得形成运行依赖

- 区分统一导航、只读总览、统一认证、跨站点写操作四种能力；不因需要一个入口就一并引入其他能力。
- 轻量导航直接跳转站点，不代理登录、携带凭据或成为唯一入口；导航不可用时仍能使用站点原地址。优先复用已有内网页，不强制新建后台服务。
- 只读总览汇总获授权的版本、健康、备份时间与异常摘要，不替代站点业务事实；失联或超时必须显示未知/过期，不能继续展示为已确认健康。
- 集中升级执行器或跨站点业务写操作不在当前范围；未来若提出，须另做权限、审计、网络和失败处理设计，不能由“站点目录”自然扩权得到。
- **导航与只读总览是已确认的交付范围，而非仍待选择的建议**：导航随 P1 交付，只读总览在 P4 落地，不要求后者阻塞新站点安装。SSO 和跨站点执行器不在当前范围内。

## 备选方案与权衡

| 方案 | 优点 | 当前取舍 |
|------|------|----------|
| 独立站点，仅人工分别管理 | 最少新增依赖，断网隔离清晰 | 账号继续按此基线管理；入口和运维便利性由后续两项补齐 |
| 独立站点 + 轻量导航/标准化运维 | 降低找入口、识别站点和重复维护的成本，不改变认证 | 已接受；导航优先复用既有工具，运维复用统一发布及安全操作规程 |
| 独立站点 + 只读总览 | 集中值守时能看版本、健康和备份摘要 | 已接受，按 P4 交付；授权网络通道及访问控制待技术设计，不同步业务数据库 |
| 独立站点 + 企业 SSO | 减少重复登录和人员账号生命周期操作 | 用户明确当前不考虑；不纳入本次实施或前置条件 |
| 跨城共享数据库/控制面 | 全局操作表面上集中 | 不作为本需求方案；引入链路与故障耦合，不能直接解决可重复安装和恢复 |

## 影响

- 保留单站点现有执行能力和低运维复杂度，新城市不要求 A 先迁库、迁存储或改认证。
- 多个独立账号体系确有管理成本，需站点责任人、人员权限清单及离职核销；轻量导航只能解决入口问题，不能冒充统一身份治理。
- 管理员仍需具备到目标站点的授权网络路径。网页导航不能打通隔离网络，也不能替代 VPN/堡垒机或安全网络方案。
- 推荐各站点使用可区分的主机名及明确站点标识；同一主机名的不同端口不能作为 Cookie 安全隔离边界。
- 管理层的故障不应阻断本地站点；总览自身访问控制和各站点摘要授权需单独明确，不通过共享身份或鉴权失败时放行来实现。

## 落地与后续动作

1. PRD 将独立站点、现有入口/账号、轻量导航、统一运维和只读总览标为已确认范围；SSO 标为当前不纳入。已确认不等于已实现。
2. P0 继续确认网络、OS/存储支持矩阵、安全触发、维护窗口及恢复目标；本 ADR 不代表 P0 全部完成。
3. P1 完成 B 的可重复安装及轻量导航，P2 完成安全运维闭环，P4 完成只读总览；分期推进，不把总览设成站点运行前提。
4. 补充导航、只读总览和站点权限隔离的验收；总览的连通、采集、访问控制和数据时效设计仍需确认，不能把方向批准当成这些技术细节已定。
5. 本次仅落文档，不修改运行代码、账号数据、网络连通或线上部署；多站点验收仍为 pending。
