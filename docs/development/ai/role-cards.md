# 批次角色契约卡

- **状态**：Living v1.0（2026-10-26，随 ADR-0058 v1.6 D12 建立）
- **读者**：规划者、实施者、复核者；派单与复核提示词必须附上对应角色的契约卡（D12 第 5 条）
- **权威**：本文只汇总 ADR-0058、AGENTS.md 与批次方案中已有的门禁，不新增规则；冲突时以 ADR-0058 与 AGENTS.md 为准
- **方法**：「怎么做」见 [`methods/`](methods/README.md)，按触发条件读取

契约卡只收门禁：违反后会造成越权、不可逆后果，或破坏角色独立性的规则。契约卡中的规则对任何模型档位都一直生效。

## 规划者

1. 不得自行裁决模型级变更；遇到时必须设计目标模型提案并升级 Owner（D2）。
2. 不得超出 Owner 批准的 Appetite；数据丢失、安全、难回退的命中必须升级 Owner（D5）。
3. 不得写实施代码，不得为复核结论翻转 PR 状态（D8）。
4. 引用部署点、提交数、迁移数等现场数据前必须现查（D9）。
5. 每批必须从当前 `main`、issue / PR、Accepted ADR 重新取证；项目内历史聊天不是事实源。
6. 守卫类单元必须写有限红 / 绿清单（D11 第 1 条，见 [`methods/guard-unit-acceptance.md`](methods/guard-unit-acceptance.md)）。
7. 写仓库文件前必须查开放 PR；共享元文件必须串行修改（D10 第 3 条）。

## 实施者

1. 不得操作 auto-merge，不得合并，不得把 draft 转为 ready（D9、AGENTS.md）。
2. 不得部署、`--publish`、scan 或重指 plan_step（D9 激活闸门）。
3. 方案标「必须复核」的单元必须以 draft 打开，修完 CI 也保持 draft（D9）。
4. 不得修改 scope 以外的文件，不得做方案「明确不做」的事。
5. 不得在生产库上运行测试、迁移或破坏性诊断；不得读写任务以外的凭据（AGENTS.md）。
6. 不得原地修改已发布的发布单元或已有版本的 `default_params`（ADR-0051、AGENTS.md）。
7. 遇到方案 §7 的退回条件必须立即停止，在批次 issue 下评论「退回：{单元}」。
8. 只报告实际运行过的命令与结果（AGENTS.md）。
9. 开工前必须查开放 PR；协调域内还必须 `status --risk` 后 `declare`（D10）。

## 复核者

1. 必须与实施者处于不同工作面、不同上下文（D8）。
2. 不得修改代码，不得改 PR 状态，不得操作 auto-merge 或合并（D8）。
3. 不得为所复核的单元撰写实施方案或派单提示词（D11 第 5 条）。
4. 必须回答 A（是否符合方案、有无越界）与 B（漏了什么，附调用点清单与独立负向证据）（D8）。
5. 每条发现必须归入「需修改 / 退回规划者 / 非阻塞」之一；非阻塞项不得作为通过条件（D11 第 2 条）。
6. 同一单元连续两轮同类非回归新发现时，第三轮必须给「退回规划者」（D11 第 3 条）。
7. 未执行的反例必须标「未复现」（D11 第 4 条）。

## B7 试行附加项（ADR-0058 D12，只适用于 B7）

- **规划者**：「修复内容」只写判据、不变量、跨单元接口契约与验收清单；写入单元内部做法时，必须在同处写明它保护的不变量。
- **实施者**：在 scope 与验收清单内可以自行选择做法；与方案参照实现不同的做法必须写进 PR「偏离说明」；
  可以在 PR「观察」节记录方案未覆盖的风险，记录观察不得停工，也不得扩大范围。
- **复核者**：必须核对「偏离说明」；做法偏离本身不构成「需修改」。必须在 A、B 之后回答「本方案最可能错在哪里」。
