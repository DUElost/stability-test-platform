# 同族扫描：按来源追溯

- **状态**：Living v1.0（2026-10-26，自 `batch-planning.md` v1.3 §3 要点与 `batch-review.md` v1.2 §3-B 迁出）
- **触发**：规划者做形态压缩（方案 §1）；复核者回答 B 问题「这次修复漏了什么」

## 规划者

- **按来源追溯，不按关键字**：对每个受影响族列出该形态的全部调用点（如所有 prefs 读路径、
  所有设备 shell 插值），标注来源（常量 / 已校验 / 已转义 / 未处理）。B1 v1.0 按 `rm/dd/chmod` 等关键字扫描，
  漏掉了 `mkdir/cat/cd/tar/dumpsys/cmd wifi`。
- 扫描结果写进方案 §1 形态压缩表的「同族扫描结果」列，并给出参照实现。

## 复核者

- 列出该缺陷形态在受影响范围内的全部调用点，每一处标注来源（常量 / 已校验 / 已转义 / 未处理）或处置状态。
  清单写进复核评论；「未处理」一类必须为空，否则列为遗漏。
- 同时检查：
  - 异常路径：瞬态失败、超时、权限不足、非 UTF-8 输出、空参数；
  - 新增的异常 / 失败是否被上游宽泛的 `except` 吞掉，或被调用方的重试语义正确承接；
  - 新测试能否区分修复前后（在修复前的代码上应当失败）；
  - 白名单类修复是否误拒现有合理取值（对照模板与现有参数）。
