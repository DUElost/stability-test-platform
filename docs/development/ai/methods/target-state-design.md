# 模型级问题：目标状态优先

- **状态**：Living v1.0（2026-10-26，自 `batch-planning.md` v1.3 §2「模型级问题：目标状态优先」原样迁出）
- **触发**：修法需要改变模型（新表、新状态、新 env、权威冲突、生命周期变化、跨族共享运行时）
- **权威**：ADR-0058 D2「设计权 ≠ 裁决权」；规划者设计目标模型，不自行裁决

1. **先设计目标，再谈迁移**：先不以当前实现形状和既有方案边界约束目标状态设计，问「从系统长期规模与演进方向看，这件事应怎样解决」；
   再与代码、ADR、数据、部署事实对账；最后给迁移路径。不要先读 ADR、划掉「已裁过」的空间、再在剩余空间里设计。
2. **拆开被绑在一起的维度**：现成的 A/B/C 二分往往把两个独立问题捆成一个（B1 的 helper 副本：「权威源码放哪」与「运行时如何进入脚本」）。
   列选项前先问：这个选项集合本身是否被现状锚定？
3. **ADR 是证据，不是方案边界**：读它，用它当迁移约束（历史可重放、生产兼容、回滚）；目标模型若要求修订 / supersede，
   直接写出条款并论证——为何它在此处只是局部最优、新模型解决什么更根本的问题、哪些不变量仍保留。
   仍受真实系统事实约束：不得假装系统不是现在这样。
4. **交付物**：目标模型 + 相对既有选项的论证 + 保留 / 修订 / supersede 的 ADR 条款 + 迁移路径与本批过渡姿态 + 需 Owner 裁决的问题清单。
   不预设结论，不自行生效。
5. **不因目标而扩批**：目标模型回答「往哪收敛」，不自动推出全量改造；迁移优先机会式 + 防倒退棘轮。
   载体：另立独立架构 issue（不塞进批次 issue，避免污染关单判据），批次方案 §2 只链接它并写明本批的过渡姿态。
   参照：#3498（B1 §2 A/B/C 升格）。
