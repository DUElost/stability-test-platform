# 守卫类单元的有限验收

- **状态**：Living v1.0（2026-10-26，自 `batch-planning.md` v1.3 §3 要点迁出）
- **触发**：单元是 checker、门禁或静态分析工具这类判定其它代码的单元
- **权威**：ADR-0058 D11 第 1 条；复核时的分类规则见 [`batch-review.md`](../batch-review.md) §3

## 规划者

守卫类单元的方案必须写明以下四项：

- 威胁模型：防误改复发，还是防刻意绕过；
- 守卫支持的输入形态；
- 有限的红 / 绿验收清单；
- 哪些运行时语义由哪条行为测试与 required 门禁承担。

规划者不得把「证明被守卫代码在任意改写下满足某个语义」写成验收条件。
反例：B4 G2（#3601 v1.1 §4.3 只写了「支持本扫描发现的有限表达式」，没写清单与语义归属，复核 10 轮未闭合；v1.2 补齐）。

## 实施者

- 实施者不得为闭合复核发现而扩大守卫支持的输入形态。
- 对支持形态以外的输入，实施者必须让守卫判为需人工分类（fail-closed）。
